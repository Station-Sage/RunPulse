### 1. daily_fitness 폴백 여전히 활성 (Phase 5-F 미정)
- **파일:** `src/analysis/trends.py:167`
- **문제:** `SELECT {col} FROM daily_fitness` + fallback 주석 유지
- **설계:** DDL 삭제 후 metric_store만 사용
- **결정 필요:** Phase 5-F 정책 (삭제 vs 조건부 유지)

### 2. 서비스 레이어 완전 부재 (Phase 5-0 미구현)
- **설계 요구:** `src/services/` 4개 모듈
  - activity_service.py (목록/상세)
  - wellness_service.py (일별 웰니스)
  - metrics_service.py (배치 로드)
  - training_service.py (훈련 계획)
- **실제:** `unified_view.py` 만 부분 구현
- **결과:** 각 뷰가 독립적으로 SQL 작성 (DRY 위반, 유지보수 비용↑)

### 3. raw SQL 직접 쿼리 40+ 곳 (ADR-009 준용)
- **위반 파일:**
  - `views_dashboard_loaders.py`: 배치 로드 SQL
  - `views_report.py`: 통계 + 메트릭 SQL
  - `views_perf.py`: 5개 메트릭 직접 쿼리
  - `views_wellness_enhanced.py`: 웰니스 메트릭 SQL
  - `views_race_enhanced.py`: marathon_shape/di 쿼리
  - `views_ai_coach.py`: metric_store 직접 쿼리
- **근본:** 서비스 레이어 부재
