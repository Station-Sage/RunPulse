## 3. 남은 일의 묶음 (제안 순서)

의존 관계(원본 "순서 원칙")를 유지하되, 이미 끝난 앞단을 제거했다.

1. **A. 확인 작업(코드 변경 없음)** — 위 표의 `TODO: 확인 필요`를 `src/`·`frontend/` 실제 상태와 대조해 닫는다. 이 문서 갱신이 산출물이다. 규모 S.
2. **B. 1-1 후속 소건** — Today 1회성 변경 알림, formChart 음영 상수의 SSOT 흡수, RRI 등급 등재. 모두 표시·상수 수준이며 DB 값은 바꾸지 않는다. 규모 S~M.
3. **C. 2-5/2-1 잔여** — D1d 활동 scope, explain 드릴(`race_pred_marathon_sec`·`x.taper`). 규모 M.
4. **D. 트랙 C(Plan) 완결** — 3-13~3-15 완결 여부 확인 후 잔여 슬라이스. 3-16은 D4 지시 대기.
5. **E. 기본 전환 경로** — 2-3(`ui_default` 스키마) → G1~G4 점검 → 4-8. 계정 설정 스키마 변경과 기본 진입 전환은 사용자 결정(DECISIONS 참조).

한 릴리스에 L 2개 이내라는 원본 권고는 유지한다.

## 4. 안전 원칙 (이 로드맵의 모든 후속 구현에 적용)

- 실 DB 값을 바꾸는 작업(재계산·재매칭·마이그레이션)은 **DB 사본에서 검증만** 수행하고, 운영 적용은 백업 + 사용자 확인 후 별도 단계로 한다. 자동 구현 단위는 운영 DB 적용 금지.
- 3-16(R6·R7)과 외부 계정 쓰기(워치 푸시)는 사용자 지시 전 착수 금지. 진행 중인 11/22 계획 재생성 금지(D4).
- 각 항목 착수 전 BACKLOG 등록(workflow-rules), 착수 시 해당 탭 `design.md §9`로 plan 확정.
