# Library · 메트릭 브라우저·메트릭 상세·웰니스·Provider 비교 — UI(시각·인터페이스) 리뷰

**리뷰일**: 2026-09-27
**대상**: `/v2/library/metrics`, `/v2/library/metrics/:slug`, `/v2/library/wellness`, `/v2/library/providers` (계정 pansongit 실데이터, 데스크톱 1280 / 모바일 390)
**함께 읽을 문서**: 같은 폴더 `ux.md`(흐름·설명·분해 구조). 이 문서는 흐름 문제를 다시 쓰지 않고, 시각 문법·포맷·레이아웃·접근성만 다룬다. 공통 컴포넌트 문제는 `10-today/ui.md`, `20-library-activities/ui.md`의 해당 항목을 참조한다.

요약:
1. **차트가 값을 읽을 수 있게 그려지지 않는다.** `TrendChart`의 y 라벨은 데이터 값이 아니라 5% 패딩 경계값 2개(`92.0`/`35.2`, 마라톤 예측 `13660.8`/`12851.2`)뿐이다. 라벨은 선과 겹치고, 중간 격자선에는 라벨이 없으며, x축은 ISO 날짜 2개뿐이다. 시간 계열은 원시 초로 그리고 방향도 반대여서 기록이 좋아지면 선이 내려간다.
2. **브라우저 카드 스파크라인이 변화를 크게 과장한다.** 카드마다 자기 min-max로 정규화한다. 그래서 HR 프로필 177.5→177.6(0.1 bpm), eFTP 278→279초(1초)가 카드 전체 높이의 계단으로 그려진다. 예측 기록 스파크라인도 방향이 반대다(5K는 느려지는데 선이 올라간다).
3. **모바일 핵심 카드에서 Provider 배지가 카드 밖으로 넘친다.** `3:40:23` + `RunPulse` 배지가 151px 내부 폭을 넘는다. 게다가 38장 중 35장에 같은 회색 `RunPulse` 배지가 반복되어 정보 없는 잡음이 된다.
4. **메트릭 상세·웰니스·Provider 비교의 데스크톱 레이아웃이 비어 있거나 늘어나 있다.** 상세 차트는 1016×140(7.3:1) 띠에 가깝고 아래 약 270px가 비어 있다. 웰니스 30일 추세는 1016×32(32:1) 선 3개로, 축·값 없이 임의 3색(주황=주의 의미색과 충돌)으로 그린다. Provider 표는 1072px 전폭에 값 열이 약 250px씩 벌어져 있다.
5. **의미 밴드와 상태 색을 차트에 쓰지 않는다.** ACWR 0.8~1.3, TSB 구간, CIRS 구간은 `metricMeaning.ts`에 이미 있지만, 상세 차트에는 배경 띠·기준선·현재/피크 마커가 없다. 웰니스 UTRS 59 / CIRS 37은 무채색 숫자뿐이다.

### [중요] F-UI-05 메트릭 상세 레이아웃: 납작한 차트, 빈 하단, 요약 카드 타이포 불일치
- 현상:
  - 데스크톱 차트는 1016×140px(가로:세로 약 7.3:1)이다. 3개월 90점짜리 UTRS가 톱니처럼 빽빽하게 그려진다. 차트 아래 버튼 행 이후로 뷰포트의 약 270px(y 530→800)가 빈 공간이다.

## 잘된 점 (유지)
- 카드 전체가 `<a>`이고 `active:bg-surface-3` 누름 피드백이 있다. 메트릭 카드 → 상세 이동이 빠르다(148~195ms).
- 브라우저 값 표시는 `formatUnitValue`를 써서 목록에서는 `3:40:23`, `4:38/km`, `19.8 min/wk`가 올바르다. 이 포맷을 상세·차트·분해로 확장하기만 하면 된다.
- `TrendChart`는 `touch-action: pan-y`, 포인터 스크럽, `vector-effect="non-scaling-stroke"`, 다계열 공통 축을 이미 갖췄다. 축·마커·밴드만 더하면 공통 차트 기반이 된다.
- `Sparkline`이 null 구간을 끊어 그려 결측을 선으로 잇지 않는다(데이터 정직성).
- 상태 라벨이 `● 피로 누적`(색 + 텍스트)으로, 색만으로 의미를 전달하지 않는다.
- 장식(그라데이션·글래스·그림자)이 없고 다크 surface 3단 위계가 절제되어 있다(P5 방향).

- 비전 부합: **4** — 투명성 재료(분해·소스 비교)가 원시 라벨 목록과 무단위 표로만 드러난다.
- 정보 정확성: **3** — 상세 원시 초, 시간 축 방향 반전, 패딩값 y 라벨, 스파크라인 과장으로 오독을 유도한다.
- 시각 품질: **4** — 절제된 팔레트는 좋지만 모바일 배지 오버플로, 납작한 차트·빈 하단, 그리드 리듬 붕괴, 대비 미달이 있다.

## 최우선 개선 3개
1. **공통 차트 문법 적용(F-UI-01, F-UI-02, F-UI-06)**: `formatMetric` 단일 포맷터(h:mm:ss·페이스·h m), 방향 메타에 따른 y 반전과 `↑ 빠름` 캡션, 플롯 밖 nice-tick y축과 월 x축, 끝점·스크럽 마커, 의미 밴드·평균선을 적용한다. 스파크라인에는 메트릭별 최소 스케일 폭과 방향 반전을 넣는다. TrendChart·Sparkline·FormChart를 한 사양으로 정리한다.
2. **메트릭 상세 재배치(F-UI-04, F-UI-05, F-UI-11)**: 데스크톱은 8/4 2열(값+차트 / 이 지표는+선택일 분해 인라인 패널), 모바일은 180px 차트 바로 아래 분해 패널로 둔다. 요약 카드 타이포를 통일하고, 기여 막대 행과 정보/이동 행을 시각적으로 분리하며, 한국어 제목을 쓴다.
3. **목록·표 정리와 접근성 기준선(F-UI-03, F-UI-07, F-UI-08, F-UI-09, F-UI-10)**: Provider 배지는 예외 출처만 라벨 줄에 표시하고, 그리드는 2/4열로 통일한다. 웰니스는 날짜 헤더, 등급 색, 기준선 캡션, small-multiple 추세로 바꾼다. Provider 표는 단위·오른쪽 정렬·차이 칩을 쓴다. 칩 44px 히트 영역·`aria-pressed`, 키보드 차트 판독, fg-muted 대비 4.5:1 이상을 맞춘다.
