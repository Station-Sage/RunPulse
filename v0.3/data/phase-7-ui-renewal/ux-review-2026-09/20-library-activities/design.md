# Library 홈 · 활동 목록 · 활동 상세 — 통합 개선 설계

**작성일**: 2026-09-27 · **대상**: `/v2/library`(홈), `/v2/library/activities`(목록), `/v2/library/:id` 요약·스트림·랩·지표·소스 5 서브탭
**입력**: 같은 폴더 `data.md`(F-DATA-01~13), `ui.md`(F-UI-01~18), `ux.md`(F-UX-01~14), `00-vision-criteria.md`, `../03c-library.md`, `../03g-common-patterns.md`, 스크린샷·API 실측(읽기 전용 GET)
**공통 규격 참조**: 차트(C1)·근거 칩(C2)·드릴다운 시트(C3)·값 포맷(C4)·로딩(C5)·출처 배지(C6)·색(C7)·타이포·아이콘(C8)은 `10-today/design.md` §C를 따르고, 이 문서는 재정의하지 않는다. 이 문서에 남은 규격은 Library 고유 확장이며 **§Cn 확장**으로 표시한다. 두 문서가 다르면 §C를 따르고, 남은 충돌은 §11 정합 메모에 적는다.

## 1. 요약

**설계 목표**
1. **숫자부터 바로잡는다.** RE·스플릿·디커플링·GAP·대회 PB·소스 비교가 틀리거나 서로 어긋나면 다른 개선은 의미가 없다. 수치 교정(S1)을 UI 작업보다 먼저 하거나 같은 릴리스에 넣는다.
2. **읽히는 차트**: 페이스는 반전 축으로 그리고, 스플릿·랩은 평균을 기준으로 한 고정 스케일을 쓴다. 요약 탭은 거리축을 공유하는 `ActivityTimeline`으로 바꾸고 지도·스플릿과 연동한다. 모바일에서는 탭하면 값이 고정된다.
3. **활동은 어디서든 한 번에 연다**: `ActivityRow`를 하나로 만들고, 히트맵에 팝오버를 붙이고, `?from=` 복귀 규칙을 둔다. 필터·스크롤은 URL과 snapshot으로 보존한다.
4. **상세 = 판정 → 근거 → 행동**: L0에 판정 한 문장과 근거 칩 3개를 두고, RPE 입력과 "코치에게 묻기"로 끝맺는다. 아카이브에는 기간·유형 필터와 연-월 스크러버를 넣어 3.9년치를 찾을 수 있게 한다.

**범위**: 위 3개 화면과 서브탭 5개다. 공유 컴포넌트(`ActivityRow`, D2 시트 — §C3 공통 구현)는 Today·계획·Coach 화면에도 적용하지만, 그 화면들의 배치는 각 탭의 design.md가 정한다. 메트릭 브라우저(`/library/metrics`)와 CTL 상세 설명은 `21-library-metrics/design.md` 몫이다.

**세 평가가 충돌한 지점과 판단**

## 2. 정보 구조·배치

### 2-1. Library 공통 셸
Library 아래 모든 화면에 `library/+layout.svelte`를 적용한다. 섹션 탭은 `홈 | 활동 | 메트릭 | 웰니스 | 소스`로, 지금 "활동"이 홈을 가리키는 오명을 바로잡는다(F-UX-11). 활동 목록에서도 섹션 탭을 유지한다. 활동 상세(`/library/:id/*`)는 섹션 탭 대신 활동 헤더와 서브탭을 쓴다.

### 2-2. Library 홈 — 블록 순서
순서: ① 아카이브 히어로(근거 칩) → ② 찾기 줄 → ③ PB + 대회 기록 → ④ 캘린더/월별(탭 전환 카드 1개) → ⑤ 최근 활동(`ActivityRow` ×5) → ⑥ 내 데이터 출처.
근거: 소유감(히어로)을 먼저 주고, 곧바로 "무엇을 찾을 수 있나"(찾기)를 보여준다(P4). 관리성 정보(출처)는 맨 아래로 내린다. 메트릭 칩 9개는 삭제한다.

### 2-4. 활동 상세 — 공통 헤더 + 서브탭 (`library/[id]/+layout.svelte`)
```
← 8월 활동   러닝 · 9월 27일 (일) 06:10   ⋯
[이지] [Garmin ★ · Intervals]   (헤더 56px, sticky)
요약 | 스트림 | 랩 | 지표 | 소스   (탭 44px, sticky)
```
- ← 라벨과 목적지는 `from`에 따라 정한다(§3). 서브탭 페이지에는 별도 ←가 없다.
- `⋯` 메뉴: `Garmin에서 열기 ↗`(`core.source_url`), `GPX 내보내기`, `대표 소스 변경`(보류, §10).
- 데이터가 없는 탭은 `랩 —`처럼 비활성으로 표시한다(포커스는 가능, 탭하면 "기기 랩 없음" 토스트).

### 2-5. 요약 탭 — 블록 순서(L0 → L1 → L2)

### 2-6. 나머지 서브탭
- **스트림**: 트랙 토글 칩(페이스·심박·고도·케이던스·파워, 높이 36px) + x축 `시간 | 거리` 세그먼트 + 트랙별 y 눈금 + 크로스헤어 교차점 표시. 구현 설명 문구는 ⓘ 안으로 옮기고, 본문에는 `Garmin 1,675개 기록점`만 남긴다.
- **랩**: 고정 열 표. 데스크톱 열은 `# | 거리 | 시간 | 페이스 | 발산 막대(160px) | 평균/최대 HR | spm | W | 상승`이다. 모바일은 2줄 카드로 보인다. 인터벌로 분류되면 `워크/회복` 그룹 뷰가 기본이고, 헤더에 `워크 평균 4:35 · 회복 평균 7:10 · 계획 2-1 크루즈 ›`를 둔다.
- **지표**: 섹션 순서는 `얼마나 힘들었나(부하) → 얼마나 효율적이었나 → 체력 신호 → 기타`다. 섹션 머리에 결론 한 줄을 두고, 행은 2줄(이름·값·상태 점·소스 점 / 해석 한 줄)이다. `미매핑`은 개발자 모드에서만 보인다.
- **소스**: 표 위에 요약 한 줄(`측정 차이 1건 · 정의가 달라 비교하지 않는 항목 5개`)을 둔다. 섹션은 `기록 값` / `계산 지표` / `관련 지표(정의 다름, 비교 안 함)` 세 개로 나눈다. 숫자는 오른쪽 정렬하고, 대표 셀은 `★`와 fg-secondary 1px 테두리로 표시하며(teal은 good 의미색이라 쓰지 않는다, §C7), 차이 열을 둔다. 행을 누르면 인라인으로 펼쳐진다.

## 4. 지표 표기·설명 규격

### 4-1. 값 포맷 (§C4 따름 + Library 확장)
시간·페이스·심박·점수·변화량·음수 부호(U+2212)·`.num`·날짜·시각은 §C4를 그대로 쓴다. 아래는 §C4를 활동 화면에 적용한 결과와 §C4에 없는 확장 항목이다.

| 종류 | 형식 | 예 | 근거 |
|---|---|---|---|
| 거리 | §C4: ≥1km `n.n km`, <1km `n m` | `9.3 km`, `171.0 km`, `525 m` | §C4. 상세 히어로 소수 2자리는 §C4 확장 제안(§11 남은 충돌) |
| 시간 | §C4: `h:mm:ss` / `m:ss` | `55:18`, `3:42:12` | §C4 |

| 페이스 차이 | 부호 + <1분 `n초/km`, ≥1분 `m:ss/km`. 빠름 = `−`(U+2212) | `−8초/km`, `+1:05/km` | §C4 확장(§C4 "시간 차"의 페이스판) |

모든 수치 출력은 `lib/format.ts`의 `formatUnitValue(value, unit)` 한 곳을 거친다(§C4). D2 시트의 주값·`formula.terms`·`sources`도 같다(F-UI-02). 원시값은 D2 ② 하단 `정밀값 110.20` 토글에서만 보여준다.

### 4-2. 이름·약어·ⓘ 설명
- 한글 이름을 먼저 쓰고 약어는 괄호에 둔다: `유산소 분리(Decoupling)`, `부하(TRIMP)`, `경사 보정 페이스(GAP)`. 이름에 "RunPulse" 접두어를 붙이지 않는다(소스 점과 중복).
- ⓘ(또는 행 탭 → D2 ① 의미 블록, §C3.2)는 4줄로 고정한다(v2 `meaning{what, bands, baseline, so_what}`에 대응). **무엇**: 한 문장. **좋은 범위**: 러닝 관행 기준. **내 값**: 개인 기준 대비 해석. **그래서**: 행동 한 줄.
  - 예) 유산소 분리 — 무엇: 후반에 같은 속도를 내는 데 심박이 얼마나 더 들었나 / 좋은 범위: 정속 롱런 5% 미만 양호, 5~10% 주의 / 내 값: 4.4%, 최근 롱런 중앙값 6.1% / 그래서: 이 페이스로 롱런 거리를 늘려도 된다.
- 판정 색은 **정속 유산소 세션**(이지·롱런, 페이스 CV < 5%)에만 붙인다. 프로그레션·인터벌 세션에는 `참고(속도 변화 큼)`를 회색으로 표시한다(F-DATA-02).
- Training Effect 구간: `<1 효과 미미 · 1–1.9 회복 · 2–2.9 유지 · 3–3.9 향상 · 4–4.9 크게 향상 · 5.0 과도`. caution 색은 5.0에만 쓰고, 대회에서는 경고하지 않는다(F-DATA-10).
- 신뢰도: 메트릭 `confidence < 0.8`이거나 대체 경로로 계산된 값에는 `추정` 태그(회색 테두리)를 붙이고, 요약 L0·L2에서 뺀다(F-DATA-01).

### 4-3. 출처 배지 (§C6 따름 + 확장)
- 표기·색·블록 단위 표시·기준일 표기·탭 동작은 §C6을 그대로 쓴다(테두리+글자, 채움 금지, provider 토큰).
- **§C6 확장(병합 배지)**: 활동 헤더는 형제 활동 병합을 보여주는 `Garmin ★ · Intervals`(대표 = ★)를 쓴다. 모양은 §C6 배지 2개를 `·`로 이은 것이다.
- 지표 행은 좁은 곳이므로 §C6 글자 약어 배지(`G`·`I`·`S`·`R`, 테두리+글자, 스크린리더용 전체 이름)를 쓴다. 기존 안의 8px 색 점은 색만으로 구분하므로 쓰지 않는다.
- RunPulse 계산값은 §C6 `RunPulse 계산`(neutral)으로 표시한다. 기존 안의 teal 테두리는 good 의미색과 겹치므로 버린다(§C7). 공식 버전은 D2 ④ 푸터에 `formula_v1 · 12:37 계산`으로만 보인다.

### 4-4. 좋음·나쁨 색
- 등급·의미색·시리즈색은 §C7을 따른다. 등급은 서버 `status`·`status_label`로만 렌더하고 프론트에 경계값을 두지 않는다.
- **§C7 적용**: 스트림·타임라인 트랙은 서로 겹치지 않으므로 트랙마다 주 시리즈 = `--series-1`, 평균·기준선 = `--series-2`를 쓴다. 트랙 구분은 색이 아니라 트랙 라벨과 위치로 한다. 기존 안의 계열색 5종(`--series-pace/hr/elev/cadence/power`)은 두지 않는다.
- **§C7 확장 제안(차이 색)**: 스플릿·랩 발산 막대와 소스 차이에는 `--delta-better`·`--delta-worse` 2색만 쓴다. §C7에 이 토큰이 없고, 기존 안(파랑/amber)은 `--series-1`(sky)·caution(amber)과 겹친다 → §11 남은 충돌. 확정 전까지는 부호·라벨이 주 전달 수단이다(F-UI-17).
- 색만으로 뜻을 전달하지 않는다. 차이에는 부호, 판정에는 텍스트 라벨(`양호`·`주의`)을 함께 둔다.
- 막대 안에 텍스트를 넣지 않는다(amber 위 흰 글씨 대비 2.1:1 문제, F-UI-04).

## 5. 차트 규격

공통 문법은 §C1 ChartScrub을 따른다(상호작용·키보드·판독줄·툴팁·y 눈금·방향·참조선·범례·결측·최소 크기). 이 탭의 모든 대화형 차트(타임라인·스트림·스파크라인)는 `ChartScrub` 코어 위에 만든다.
- **방향(§C1)**: 페이스·시간은 `invert: true`로 **빠름 = 위**, 축 캡션 `빠름 ↑`(F-UI-01). 기존 안의 `polarity` prop은 쓰지 않는다.
- **눈금(§C1)**: nice ticks 3~5개, 페이스는 5/10/15/30초 단위, 라벨 11px sans·fg-secondary·오른쪽 정렬, 패딩 경계값 라벨 금지. 기존 안의 `font-mono`·2~3개는 버린다.
- **§C1 확장(x축 거리)**: §C1 x 눈금은 날짜축 규격이다. 활동 차트의 거리축은 10km 이하 1km, 초과 5km 간격, 라벨 `0 1 2 … km`로 한다.
- **§C1 확장(트랙 높이)**: `ActivityTimeline`은 3트랙을 하나의 ChartScrub(합계 ≥ 120px)으로 묶는다. 40~64px 트랙은 3~5개 눈금이 들어가지 않으므로 트랙별 nice tick 2개(상·하)를 예외로 허용한다.
- **§C1 확장(빈 데이터)**: §C1의 `데이터 수집 중 (n/필요 일수)`는 일별 시계열용이다. 활동 차트는 원인 한 줄로 바꾼다(`심박 데이터 없음 — 광학 센서 미착용`). 같은 높이를 예약하고 축만 있는 빈 차트는 그리지 않는다.
- **기준선(§C1 참조선)**: 평균은 수평 점선 + 라벨(`평균 5:57`), 색 `--series-2`.

**② 분해 — `GET /api/v1/library/metrics/:slug?scope_type=activity&scope_id=&explain=1`** (현재 `children:[]`, `inputs:[]` — API 확인). 응답은 10-today §7.3 **분해 v2 계약**(§C3 렌더 계약)을 그대로 쓰고, scope만 `activity`로 준다. 아래는 형식 예시다.
```json
{"slug":"trimp","name_ko":"부하","abbr":"TRIMP","scope":{"type":"activity","id":17414,"basis":"canonical"},
 "value":97.3,"display":"97","unit":"AU","status":"neutral","status_label":"평소보다 조금 높음","higher_is_better":null,"confidence":0.9,
 "meaning":{"what":"…","bands":["…"],"baseline":{"same_class_30d":{"median":72,"p25":61,"p75":88}},"so_what":"…"},
 "formula":{"text":"TRIMP = Σ Δt·HRr·0.64·e^(1.92·HRr)","version":"formula_v1","computed_at":"2026-09-27T12:37:53",
   "terms":[{"slug":"hr_zone_1","label":"Z1","contribution":61.2},"…",
            {"slug":"avg_hr","label":"평균 심박","raw":137,"drill":"m.avg_hr"},{"slug":"hr_rest","label":"안정 심박","raw":48},{"slug":"hr_max","label":"최대 심박","raw":186}]},
 "sources":[{"type":"activity","id":17414,"label":"이지 9.3km","value":97.3,"unit":"AU"}],
 "provider":{"kind":"runpulse","version":"formula_v1","computed_at":"2026-09-27T12:37:53"},
 "compare":[{"provider":"garmin","value":110,"note":"EPOC 기반"},{"provider":"intervals","value":61}]}
```
- 기존 안 필드 대응: `meaning{what,good_range,mine,action}` → v2 `meaning{what,bands,baseline,so_what}`, `children`·`inputs` → `formula.terms`, `other_scales` → `compare[]`, `provider:"runpulse:formula_v1"` → `provider{kind,version}`.
- **§C3 확장 필드**: `meaning.baseline.same_class_30d`(같은 유형 30일 분포, v2의 `avg_7d`·`delta_1d` 대신 활동 scope에서 사용), `confidence`(<0.8이면 `추정` 태그, §4-2).
- 공식이 비공개인 provider 메트릭은 `formula.text:null, formula.reason:"vendor"`로 주고 `sources`에 이 활동을 넣어 v2 계약(`terms`·`sources` 모두 빈 응답 금지)을 지킨다. 채우는 책임은 system-architect 쪽이며 CalcContext 규칙(ADR-009)을 따른다.

**③ 소스 비교 — `GET …/:id/providers`**: 행 스키마에 `quantity`, `unit`, `section: record|computed|related`, `diff: {abs, pct, significant, threshold}`, `reason`을 추가한다. `significant` 판정은 서버가 항목별 임계로 한다(고도 10m, 기온 2°C, 시간 1%, 거리 1%). 케이던스·FTP 정규화도 서버에서 한다.

**④ 활동 목록 — `GET /api/v1/library/activities`** 파라미터를 추가한다: `type`(race|interval|tempo|long|easy|recovery), `month=YYYY-MM`, `sort`(date|distance|pace|load), `q`(이름·날짜·장소·대회명), `sport_group=running`(running+indoor+trail). 행에 `workout_class`, `display_title`(기본 이름이면 `이지 9.3km · 네거티브 스플릿`), `load`, `is_race`를 추가한다. 현재 `workout_label`은 20행 전부 null이다(API 확인).

**⑤ 신규 `GET /api/v1/library/activities/facets`**
```json
{"sports":[{"key":"running_group","label":"러닝","n":488},{"key":"swimming","n":46},{"key":"strength","n":43}],
 "types":[{"key":"race","n":18},{"key":"interval","n":…}],
 "months":[{"month":"2026-09","n":17},{"month":"2023-10","n":…}]}
```
종목 칩·스크러버·빈 달 표시에 쓴다. 칩 하드코딩(`strength_training`)을 제거한다(F-UX-03).

**⑥ archive** — `totals`에 `breakdown:{outdoor:472, indoor:16}`, `time_basis:"timer"`, `active_days_365`를 추가하고(365일 창), `races:[{id,date,name,time_sec,official:bool}]`를 추가한다. PB 계산을 `official_time_sec` 우선, 환산 없음으로 바꾸고 링크는 캐노니컬 id로 한다.

**⑦ 신규 활동 피드백 — `PUT /api/v1/library/activities/:id/feedback`** `{rpe:1-10, pain:"none|mild|moderate|severe", pain_site?:str, note?:str}` → `{saved_at}`. 저장소는 **설계 결정 필요**: 현 `user_inputs`는 `UNIQUE(input_date, input_type)`라서 같은 날 활동 2건의 RPE를 저장할 수 없다. 두 안이 있다. 안 A는 신규 테이블 `activity_feedback(activity_id PK, rpe, pain, pain_site, note, updated_at)`(권장, 활동 단위 1:1)이고, 안 B는 `user_inputs` 재생성 + UNIQUE 변경이다. 사용자 승인 후 `decisions.md`에 ADR로 남긴다.

**⑧ 시스템 의존(이 탭 밖에서 결정)**: PMC 감쇠 `1−e^(−1/τ)` + 전체 이력 워밍업(F-DATA-04), RE 대체 경로 교정(F-DATA-01), GAP 경사·방향 교정(F-DATA-05), 활동 VDOT 조건(F-DATA-07), 날씨 category 백필, dedup 시간대 규칙(F-DATA-13). 모두 ADR 대상이며 `check_data_consistency`에 `_unmapped > 0` 경고를 추가한다.

**남은 충돌** (10-today 쪽 결정 또는 합의 필요)
1. **차이 색 토큰**: §C7에는 `--delta-better/worse`가 없다. 기존 안(파랑/amber)은 `--series-1`(sky)·caution(amber)과 겹친다. §C7에 차이 2색을 추가하고 dataviz 팔레트 검증으로 확정해야 한다.
2. **상세 히어로 거리 소수 2자리**(`9.30 km`): §C4는 `n.n km`다. 활동 히어로만 2자리를 허용할지 §C4 예외로 정해야 한다. 정해질 때까지 §C4(`9.3 km`)를 따른다. §2 와이어프레임의 `9.30 km`는 이 결정을 기다리는 자리 표시다.
3. **§C3.3 scope 문법**: `YYYY-MM-DD`·`YYYY-MM`만 정의되어 있다. 다른 화면(Today·Coach)에서 특정 활동의 메트릭을 직접 열려면 활동 scope 토큰(예: `m.trimp@a17414`)이 필요하다. §C3.3에 추가를 제안한다.
4. **PMC α**: 10-today는 원문 `1/τ` 기본(DECISIONS 확정 필요), 이 문서 §7-2 ⑧은 `1−e^(−1/τ)`를 적었다. 결정은 S1b ADR 하나로 모으고, 어느 쪽이든 활동 화면은 "이 세션 부하 기여"만 표시하므로 UI 규격은 바뀌지 않는다.
5. **와이어프레임 기호**: §2의 `⚠`·`✕`·`▾`·`★`는 §C8에 따라 `Icon.svelte` 아이콘의 자리 표시다. `★`(대표 소스)에 대응하는 아이콘이 §C8 목록에 없으므로 추가가 필요하다.
