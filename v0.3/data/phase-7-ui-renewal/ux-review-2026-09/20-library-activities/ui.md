# Library 홈 · 활동 목록 · 활동 상세 — UI(시각·인터페이스) 리뷰

요약:
1. **활동 상세의 차트는 대부분 값을 읽을 수 없다(U1).** 요약 탭의 페이스·심박 흐름, 고도 프로필, 경로, KM 스플릿, 랩 막대, Library 히트맵·월별 막대 모두 축 눈금이 없거나 값이 `title` 호버에만 있다. 모바일에서 탭해서 값을 확인할 수 있는 차트는 스트림 탭 하나뿐이다.
2. **페이스 선의 방향이 반대다(U2, 치명).** `Sparkline`은 큰 값을 위로 그린다. 그래서 페이스(초/km)는 느릴수록 위로 올라가고, 요약 탭과 스트림 탭의 페이스 스파이크는 모두 "느려진 순간"을 나타낸다. 같은 화면의 스플릿 바는 반대로 "빠를수록 길게" 그려서 한 화면 안에 방향 규칙이 두 개 있다.
3. **스케일이 차이를 과장하거나 거짓 신호를 만든다.** 고도(5m 범위가 차트 높이 전체를 채움), 스플릿 바(최소~최대를 25~100%로 정규화한다. 마지막 0.3~0.4km 부분 구간이 스케일을 흔들고 "최고 구간" 초록을 가져감), 랩 막대(행마다 트랙 길이가 달라 서로 비교할 수 없음)가 그렇다.
4. **계산 분해 시트에 원시 부동소수(`110.20204162597656`)가 그대로 나온다(U3).** 데스크톱에서도 1280px 폭 전체를 덮는 모바일 하단 시트를 쓴다.
5. Library 홈의 아카이브 히어로·히트맵·PB는 "내 데이터의 집"이라는 방향이 맞다. 다만 모바일에서는 히트맵 글자가 약 5px라 읽을 수 없다. 모바일 최근 활동 행은 거리·시간·페이스를 숨겨서 날짜와 이름만 남는다. 활동 목록(경로 썸네일, 주 단위 그룹)은 이 탭에서 가장 완성도가 높다.

### [치명] F-UI-01 페이스 선이 "느릴수록 위"로 그려진다 — 요약·스트림 탭 공통

- 근거: `frontend/src/lib/components/Sparkline.svelte:30-31` (`toY = height - ((v-minVal)/range)*height`로 큰 값이 위), 입력은 `library/[id]/+page.svelte:47` 과 `streams/+page.svelte:29`의 `1000/speed_ms`(초/km). 스크린샷 `activity-desktop.png` 하단, `activity-streams-desktop.png`, `activity-streams-mobile.png`. 같은 화면의 `SplitBars.svelte:33-36`은 "빠를수록 길게"라서 방향 규칙이 서로 충돌한다.
- 왜 문제인가: U2 정면 위반(실력 향상이 아래로 보임). Strava·Garmin Connect·Intervals.icu는 모두 페이스 축을 뒤집어 빠른 페이스를 위에 둔다. 러너는 "위=좋음"으로 읽는다.
- 개선안:
  - `Sparkline`에 `invert?: boolean` prop을 추가하고, 페이스 계열은 `invert=true`로 쓴다(`toY = ((v-min)/range)*height`).
  - 차트 문법을 전역 규칙으로 정한다: "낮을수록 좋은 값(페이스·시간·예측 기록)은 축을 뒤집어 좋은 방향이 위". `04-component-catalog.md`에 `ChartAxis.polarity: 'higher-better' | 'lower-better'`로 명시한다.
  - 페이스 차트의 y축 우측에 눈금 2~3개(예: `5:30 / 6:00 / 6:30`)를 두고 위가 빠름이라는 점을 표시한다. 평균 페이스 기준선(점선, `--fg-muted` 40%)과 라벨 `평균 5:57`도 넣는다.

### [중요] F-UI-03 요약 탭 차트 5종에 축·툴팁·탭 판독이 없다 (U1)
- 현상:
  - 고도 프로필: 양 끝 `0`·`9.3km`와 우상단 `6~11 m`만 있다.
  - 페이스·심박 흐름: 축·단위가 전혀 없다(라벨 "페이스"·"심박"뿐).
  - 경로: 범례가 `빠름 ━ 느림`뿐이고 수치가 없다.
  - 스플릿 바·경로·고도를 누르면 아무 반응이 없다(측정 `NO_VISIBLE_REACTION`: 경로 지도·스플릿 바).
- 근거: `ElevationProfile.svelte:57,75-78`, `library/[id]/+page.svelte:172-183`, `RouteMap.svelte:98-114`, `raw/interact-mobile.json` "Activity: 경로 지도 클릭"·"스플릿 바 클릭".
- 왜 문제인가: 사용자가 지적한 "차트 숫자 확인 불가"가 그대로 재현된다. P2(차트 포인트 한 번 탭에 근거) 위반이다.
- 개선안: 요약 탭의 선 차트 3개(고도·페이스·심박)를 **하나의 공유 x축(거리 km) 스택 차트 `ActivityTimeline`**으로 합친다.
  - x축: 1km 또는 5km 간격 눈금을 `font-mono 10px fg-muted`로(마라톤은 5km 간격).
  - 각 트랙 우측에 y 눈금 2개(최소·최대), 페이스는 반전 축(F-UI-01).
  - 포인터/터치 드래그 시 세로 크로스헤어를 세 트랙에 동시에 그리고, 상단 고정 판독 줄에 `7.2km · 5:48/km · 143bpm · 9m`를 표시한다(스트림 탭의 `onPointerMove` 로직 재사용).
  - 판독 위치를 경로 지도에 점(6px, 흰 테두리)으로 동기화한다(Strava·Garmin의 핵심 인터랙션).
  - 스플릿 행을 누르면 해당 km 구간이 타임라인·지도에서 강조된다(나머지 30% 불투명).
  - 트랙 높이: 페이스 64px, 심박 48px, 고도 40px(모바일 동일), 트랙 사이 8px.

### [중요] F-UI-04 KM 스플릿 바: 최소-최대 정규화 + 부분 구간 포함으로 차이 과장·거짓 "최고 구간"
- 현상:
  - 폭을 `25% + 75%×(1-(p-min)/(max-min))`로 계산한다. 9.3km 러닝은 12:12/km(0.3km 부분 구간)가 최대값이 되어 나머지 9개 바가 거의 같은 길이가 된다.
  - 경주 마라톤(910)에서는 0.4km 부분 구간 `4:23/km`가 초록 "최고 구간"을 가져간다. 같은 화면 이야기 카드의 "가장 빠른 구간 39km · 4:43"과 모순이다.
  - 활동마다 스케일이 달라서 5:47이 한 활동에서는 짧고 다른 활동에서는 길다.
  - 바 안의 흰 10px 텍스트를 amber `#f59e0b` 위에 쓰면 대비가 약 2.1:1이다(WCAG 4.5:1 미달).
- 근거: `SplitBars.svelte:42-46,48-53,76`, `lib/splits.ts:251-254`(200m 이상 잔여 구간 포함), `activity-910-desktop.png`(0.4 행 초록), `activity-desktop.png`(0.3 행 12:12). 같은 구간을 랩 탭은 `0.3km 5:35/km`로 표시해 수치도 불일치한다(`activity-laps-*.png`).
- 왜 문제인가: 오판 유도(U2/정확성). 스플릿은 러너가 가장 먼저 읽는 차트다.
- 개선안:
  - 스케일: **평균 페이스를 기준선으로 하는 발산형(diverging) 바**로 바꾼다. 중앙 세로선=평균, 빠르면 오른쪽 파랑, 느리면 왼쪽 amber, 길이는 `Δ초/km`(±30초 고정 도메인, 초과는 끝을 톱니 모양으로 표시). 활동 간 비교가 가능하고 부분 구간 영향이 없다.
  - 부분 구간은 최고·최저 판정과 스케일에서 제외한다. 행을 `opacity-60`·점선 테두리로 표시하고 라벨을 `0.3 (부분)`으로 한다.
  - 페이스 텍스트는 바 밖(좌측 고정 폭 열 `w-14 font-mono text-xs fg-primary`)으로 뺀다. 바는 순수 그래픽으로 둔다.
  - 행 높이 20px → 모바일 28px(탭 타깃 확보), 행 탭 시 F-UI-03 구간 강조.
  - 마라톤처럼 43행인 경우: 기본은 5km 묶음 9행으로 보여주고 `1km 전체 보기` 토글을 둔다(현재 marathon 스플릿만 약 1,000px 높이).

### [중요] F-UI-05 고도 프로필이 5m 기복을 산악처럼 그린다
- 현상: 9.3km 평지 러닝(누적 상승 5.3m)의 고도 범위 `6~11 m`가 80px 높이를 꽉 채워 언덕 코스처럼 보인다. 24km(`-1~11 m`)도 같다.
- 근거: `ElevationProfile.svelte:27-38`(min-max + 5% 패딩, `show` 임계 3m), `activity-desktop.png`, `activity-15302-desktop.png`.
- 왜 문제인가: 차트가 사실(평지)과 반대 인상을 준다. 데이터 잉크를 과시하는 방향이라 P5와도 맞지 않는다.
- 개선안: y 도메인 최소 폭을 **30m**로 고정한다(`span = max(maxAlt-minAlt, 30)`, 중앙 정렬). 범위가 10m 미만이면 차트 대신 한 줄 텍스트 `거의 평지 · 누적 상승 5m`만 보여준다. y 눈금은 우측에 최소·최대 2개(`6m`, `36m`), 단위를 표기한다. 경사 구간(>3%)은 면 색을 amber 20%로 덧칠한다.

### [중요] F-UI-06 경로 지도: 데스크톱에서 1,000px 폭 상자에 가는 선 하나, 방향·거리 정보 없음
- 현상:
  - 1280 데스크톱에서 경로 박스가 약 1,020×300px인데 선은 가운데 약 80px 폭에만 그려지고 나머지는 빈 surface다.
  - 왕복 코스는 복귀 선이 출발 선을 덮어서 페이스 색이 절반만 보인다. 시작(초록)·종료(흰) 점이 겹쳐 구분되지 않는다.
  - km 마커와 진행 방향 화살표가 없다.
  - 심박 모드에서는 5~95 백분위 정규화가 전 구간을 빨강으로 칠한다(`activity-hr-toggle-mobile.png`).
- 근거: `RouteMap.svelte:61-65`(`w-full` + `max-height:280px`), `:80-95`(r=5 원 두 개), `routeGeometry.ts:186-193`, 스크린샷 `activity-desktop.png`, `activity-15302-desktop.png`, `activity-hr-toggle-mobile.png`.
- 왜 문제인가: Strava/Garmin의 지도 대비 시각 품질이 가장 떨어지는 지점이다. 넓은 빈 상자가 데스크톱 위계를 망가뜨린다(지도가 이야기 카드보다 커 보이지만 정보는 적음).
- 개선안:
  - 레이아웃: 데스크톱(≥1024)에서 **지도(좌 5/12) + 스플릿(우 7/12) 2열**로 배치하고, 지도 높이 = 스플릿 목록 높이(최대 360px)로 맞춘다. 모바일은 현재처럼 1열에 높이 220px.
  - 왕복 분리: 복귀 구간을 진행 방향 오른쪽으로 2px 오프셋하거나(Strava 방식), 트랙 폭을 3→4px로 늘린다.
  - 1km마다 번호 원(12px, `surface-1` 채움, `font-mono 9px`)을 찍고, 5km마다 강조한다.
  - 시작은 `▶` 초록 삼각, 종료는 체크무늬 사각으로 모양을 다르게 해서 겹쳐도 구분되게 한다.
  - 색 범례에 실제 값을 넣는다: `5:20 ━━━ 6:40 /km`, 심박은 존 색(Z1~Z5 이산 5색, `ZONE_COLORS` 재사용).
  - (옵션) 로컬 퍼스트 원칙을 지키면서 사용자 설정으로 OSM 타일 on/off를 둔다.

### [중요] F-UI-07 랩 막대: 행마다 트랙 길이가 달라 비교가 불가하다
- 현상: 랩 탭의 막대 트랙이 `flex-1`이고, 오른쪽 메타(`HR 119/132 160spm 220W ↑2m`)의 폭이 행마다 달라 트랙 끝이 들쭉날쭉하다(데스크톱에서 약 1,043px vs 1,082px, 모바일은 더 심함). 막대 길이 = `fastest/p`라 차이가 수 %뿐이라 사실상 전부 같은 길이다. "가장 빠른 랩 5:35/km"는 0.3km 부분 랩이다. 1km 랩에서 `6:34`(시간)과 `6:34/km`(페이스)가 같은 숫자로 두 번 나온다.
- 근거: `laps/+page.svelte:22-26,65-74`, `activity-laps-desktop.png`, `activity-laps-mobile.png`.
- 왜 문제인가: 차트 문법상 같은 축을 공유하지 않는 막대는 비교 도구가 될 수 없다. 인터벌 세션에서 이 탭의 가치가 가장 큰데 지금은 읽기 어렵다.
- 개선안: 랩 탭을 **고정 열 표**로 바꾼다.
  - 데스크톱 열: `# | 거리 | 시간 | 페이스 | 페이스 막대(고정 160px, F-UI-04 발산형) | 평균/최대 HR | 케이던스 | 파워 | 상승`. 숫자는 `tabular-nums text-right`.
  - 모바일: 2줄 카드. 1줄 `#  거리  페이스(굵게)`, 2줄 `시간 · HR · spm · W`, 막대는 행 아래 전폭 고정 트랙.
  - 1km 자동 랩이면 시간 열을 숨긴다(페이스와 중복).
  - 인터벌 랩이면(거리·강도 상이) 워크/레스트를 색 띠(좌측 4px, 파랑/회색)로 구분하고, 헤더에 `워크 평균 4:35 · 레스트 평균 7:10`을 표시한다.
  - 부분 랩은 최고 판정에서 제외한다.

### [중요] F-UI-08 Library 홈 히트맵·월별 막대: 모바일 판독 불가, 값 확인 경로 없음

## 잘된 점 (유지)
- **활동 목록 행**: 경로 썸네일 44px + 이름/요일·페이스·HR + 우측 굵은 거리/시간의 2줄 구성, 주 단위 그룹 헤더(`4회 · 34.7km · 3:17:19`)는 Strava 피드보다 밀도가 좋고 훑어보기 쉽다. 트레드밀 `⚠ 경로 없음` 처리도 명확하다.
- **이 러닝의 이야기 카드**: 결론 헤드라인 + 근거 4칸 구조가 P1 Evidence-First의 좋은 본보기다. 헤드라인을 먼저 두고 숫자를 뒤에 두는 순서를 유지해야 한다.
- **아카이브 히어로 `3,801 km`**: 데이터 소유감을 주는 첫 장면으로 방향이 맞다. PB 카드에서 활동으로 가는 링크도 동작한다.
- 스트림 탭 스크럽, 월별 막대에서 월 필터 목록으로 가는 흐름, 서브탭 전환 90~200ms.
- 숫자 mono·tabular 위계, 타일 없는 로컬 퍼스트 경로 원칙.

## 채점 (0~10)
- 비전 부합 **6**: 아카이브·이야기 카드·소스 비교가 방향은 맞지만, signature 요소(소스 비교·분해)의 시각 완성도가 낮다.
- 정보 정확성 **4**: 페이스 축 반전, 원시 부동소수, 고도 과장, 부분 구간의 거짓 최고 구간, 스플릿·랩 부분 구간 불일치.
- 시각 품질 **5**: 목록·히어로는 양호하다. 지도의 빈 공간, 비교 불가한 랩 막대, 균일 카드, 10px 텍스트 남용.
- 상호작용 반응성 **5**: 링크 전환은 빠르지만 차트·지도·스플릿·히트맵 탭은 무반응이고, 모바일에서 값 판독 수단이 거의 없다.
- 흐름 **6**: 목록→상세→서브탭은 매끄럽지만 서브탭에서 활동 맥락이 사라지고, 긴 요약 탭에 sticky 탭이 없다.
- 혁신성 **5**: 이야기 카드와 4소스 비교는 경쟁 앱에 없는 요소다. 다만 차트 연동(지도↔타임라인↔스플릿)이 없어 Strava·Garmin 대비 활동 화면의 몰입감이 부족하다.

## 최우선 개선 3개
1. **차트 문법 일괄 교정**(F-UI-01·04·05·07): 페이스 반전 축, 스플릿·랩을 평균 기준 발산형 고정 스케일로, 부분 구간을 판정에서 제외, 고도 최소 30m 도메인.
