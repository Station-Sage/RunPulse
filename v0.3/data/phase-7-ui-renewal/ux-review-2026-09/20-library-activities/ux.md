# Library 홈 · 활동 목록 · 활동 상세 — UX(경험·흐름) 리뷰

요약:
1. **활동이 등장하는 곳의 절반에서 상세로 갈 수 없다.** Today 최근 활동(`<div>`), 히트맵 셀, 계획 화면의 매칭 활동, 경로 지도·스플릿 바는 눌러도 반응이 없다. 사용자가 "클릭해도 상세로 안 간다"고 느낀 원인은 이 네 지점이다(확인).
2. **메트릭 카드를 누르면 분해 시트가 열리지만 활동 범위 메트릭은 값 하나만 나온다.** `children`/`inputs`가 빈 배열이고 값은 `110.20204162597656`처럼 원시 부동소수로 찍힌다. P2·U6 정면 위반(확인).
3. **3.9년치 아카이브에서 특정 날·대회·인터벌 세션을 찾기 어렵다.** 한 번에 20건씩 불러오고, 날짜 이동·대회·세션 유형 필터가 없다. "근력" 칩은 코드 불일치로 **항상 0건**이 나온다(확인).
4. **필터·스크롤·진입 경로가 보존되지 않는다.** 상세의 ←는 어디서 왔든 항상 `/library/activities`(쿼리 없음)로 가서 월 필터와 불러온 페이지를 잃는다(확인).
5. 활동 상세에서 다음 행동으로 이어지는 출구가 없다. "Coach에게 묻기", RPE·통증·메모 입력이 모두 0건이고(grep 확인), 인터벌 세션도 지속주처럼 해석한다.

## 발견

### [치명] F-UX-01 활동이 보이는데 눌러도 상세로 안 가는 지점이 흩어져 있다 (U4, P2)
- 현상: 같은 "활동 한 건" 표현이 화면마다 다르게 동작한다.
  | 위치 | 동작 | 근거 |
  |---|---|---|
  | Library 최근 활동 행, 활동 목록 행, PB 카드, 가장 멀리 달린 날, 월 막대 | 이동 | interact "Library: 최근 활동 행 클릭" NAVIGATED 291ms, "PB 풀" 311ms |
  | **Today 최근 활동 행** | 반응 없음 | `frontend/src/routes/today/+page.svelte:193` `<div class="flex items-center …">`(링크 아님). 02-performance §4에서 "치명"으로 판정 |
  | **Library 히트맵 셀** | 반응 없음(데스크톱은 `<title>` 호버만, 모바일은 아무것도 없음) | `lib/components/ActivityHeatmap.svelte:32-41`, interact NO_VISIBLE_REACTION |
  | **계획 주간 표의 매칭 활동**(`matched_activity_id`) | 상태 문구만 있고 링크 없음 | `routes/coach/plan/[id]/+page.svelte:42`. coach/plan 아래 `.svelte` 파일 어디에도 `library/` 링크가 없다(grep) |
  | **경로 지도, KM 스플릿 바** | 반응 없음 | interact "경로 지도 클릭"·"스플릿 바 클릭" NO_VISIBLE_REACTION |
- 왜 문제인가: 목록형 UI에서 이름·거리·시간·provider 배지가 한 줄에 있으면 사용자는 누를 수 있다고 기대한다(U4). 게다가 가장 자주 보는 Today에서 이것이 막혀 있다. 계획→실제 활동으로 이어지지 않으면 "계획 대비 실행" 근거(P1)가 끊긴다.
- 개선안:
  1. **"활동 행" 공용 컴포넌트 `ActivityRow`**(`href={base}/library/{id}?from=<origin>`)로 통일하고 Today·Library·계획·Coach·마일스톤에서 모두 사용한다. 행 끝의 `›`와 hover/active 배경을 필수로 둔다.
  2. 히트맵 셀: 탭하면 셀 아래에 **인라인 팝오버**(`9월 20일(일) · 24.2km 장거리 달리기 ›`)를 띄운다. 활동이 1건이면 팝오버를 누를 때 상세로, 여러 건이면 `/library/activities?from=D&to=D`로 이동한다. 활동이 없는 날은 "쉰 날" 한 줄만 보인다. 키보드 포커스도 가능해야 한다.
  3. 계획 주간 표: `✓`나 `부분 82%` 배지가 있는 행은 `→ 실제 활동` 링크를 달고 `/library/{matched_activity_id}?from=plan`로 보낸다.
  4. 스플릿 바: 탭하면 해당 km 구간을 경로 지도에서 강조하고(나머지는 30% 투명), 바 아래에 `3km · 5:55/km · HR 135 · +1.2m · 케이던스 174`를 펼친다. 지도 구간을 탭해도 같은 상태가 된다(양방향 연동, Strava 세그먼트 하이라이트 방식).

### [치명] F-UX-02 메트릭 분해가 "값 하나"에서 끝난다 — 원시 부동소수, 설명·공식·원천 없음 (P2, U3, U5, U6)
- 현상: 요약 탭 "훈련 부하(소스별)" 카드를 누르면 하단 시트에 `110.20204162597656 score Garmin`만 나온다. 메트릭 탭 VDOT 행도 `32.7 RunPulse · formula_v1`뿐이다.
- 근거: 스크린샷 `activity-card-click-desktop.png`, `activity-metric-vdot-mobile.png`. API `GET /api/v1/library/metrics/{training_load|runpulse_vdot|trimp|relative_effort}?scope_type=activity&scope_id=17414`를 호출하면 네 메트릭 모두 `children:[]`, `inputs:[]`이다. 컴포넌트 `lib/components/MetricBreakdown.svelte:198`은 `{data.value}`를 포맷 없이 출력한다.
- 왜 문제인가: RunPulse가 내세우는 "계산 투명성"이 드릴다운의 첫 단계에서 무너진다. 카드는 누를 수 있게 생겼는데 결과가 카드보다 정보가 적다. 러너에게는 "이게 뭐고, 좋은 값인가, 무엇으로 계산했나"가 필요하다.
- 개선안: 시트 레이아웃을 다음 4블록으로 고정한다. 데이터가 없는 블록은 숨기지 말고 "이 메트릭은 Garmin 기기가 계산한 값이라 공식이 공개되지 않았어요"처럼 **이유를 적는다**.
  1. **의미 한 줄**(Level 0): `이번 러닝이 몸에 준 부하 — 이지런 평균(70~90)보다 높은 편` + 상태 색.
  2. **값과 비교**: 포맷된 값(`110`), 내 최근 30일 분포에서 위치(작은 스트립 차트에 점), 같은 유형 세션의 중앙값.
  3. **계산**(RunPulse 메트릭): `TRIMP = Σ(구간 시간 × HRr × 0.64e^(1.92·HRr))` 공식과 기여도 막대(존별 기여 %). 입력값(평균 HR 137, 안정 HR, 최대 HR)을 누르면 다음 단계로 간다.
  4. **원천·비교**: provider 배지, 계산 버전과 시각, "Garmin 110 · RunPulse 55.7 — 왜 다른가?" 링크(소스 비교 탭의 해당 행으로 앵커 이동), "이 메트릭 추세 보기 →" `/library/metrics/{slug}?focus=<date>`.
  - 드릴 스택 시트 상단에 `‹ 훈련 부하 / TRIMP` 브레드크럼을 두어 한 단계씩 뒤로 갈 수 있게 한다. 현재는 `onClose`가 스택 전체를 비운다(`[id]/+page.svelte:212`).

### [치명] F-UX-03 "근력" 칩을 누르면 항상 "활동이 없습니다"가 나온다 (U4, 정보 정확성)
- 현상: 활동 목록에서 종목 칩 "근력"을 누르면 빈 상태 "활동이 없습니다 / 필터를 조정하거나 데이터를 동기화해 주세요"가 나온다.
- 근거: `routes/library/activities/+page.svelte:33`에서 칩 값이 `strength_training`이다. DB의 `activity_type`은 `strength`(93건)다. API 결과는 `sport=strength_training` → total 0, `sport=strength` → 43건(확인).
- 왜 문제인가: 데이터가 있는데 "없다"고 말하고, 원인을 사용자의 동기화 탓으로 돌린다. 데이터 신뢰가 무너진다.
- 개선안: 칩 목록을 하드코딩하지 말고 **서버가 주는 실제 종목 분포**(`running 472 · swimming 46 · strength 43 · indoor_running 16 …`)로 생성한다. 칩에 건수를 함께 표시한다(`근력 43`). "러닝" 칩은 `running`+`indoor_running`+트레일을 묶은 러닝 계열로 정의한다. Library 홈의 488회와 일치하게 된다(F-UX-12).

### [중요] F-UX-04 3.9년 아카이브에서 "그날/그 대회/그 인터벌"을 찾는 경로가 없다 (P4, U8, REVIEW-05 "내 아카이브")
- 현상: 목록은 20건씩 불러오고 "더 불러오기"로 이어진다. 기본 목록에서는 버튼이 존재한다(`raw/library-activities.txt` 끝, API `has_more:true, total:626`). 측정의 NOT_FOUND는 "하프+" 필터(14건, `has_more:false`)를 켠 상태에서 찾았기 때문이다(`raw/interact.mjs:98-99`, 확인). 2023년 10월 활동까지 가려면 **약 31번** 눌러야 한다. 날짜 이동, 정렬, 대회 필터, 세션 유형 필터가 없고 기간 입력은 제거됐다(`+page.svelte:22` 주석). 검색은 이름만 대상이다. "대회"로 검색하면 0건이지만 `event_type='race'`는 18건 있다. 이름이 "러닝"인 활동이 대다수라서 이름 검색이 인터벌 세션을 찾는 수단이 되지 못한다("인터벌" 7건, "크루즈" 3건만 걸린다).
- 과업별 현재 동작 수(추정 포함):
  - 특정 날(예: 2025-04-12): Library → 월 막대(최근 12개월에 들어갈 때만 가능) → 스크롤. 12개월보다 오래된 날은 사실상 찾을 수 없다(31번 누르기).
  - 특정 대회: 이름을 기억하면 검색 1회. 기억하지 못하면 방법이 없다(PB 6개와 "가장 멀리 달린 날"만 우회로).
  - 지난 인터벌 세션: 이름에 "인터벌"이 들어간 경우에만 가능.
- 개선안:
  1. 목록 상단 필터를 **3줄 → 1줄 + 시트**로 정리한다. `[기간 ▾] [종목 ▾] [유형 ▾] [거리 ▾] [정렬 ▾] 🔍`. 유형은 `대회 · 인터벌/템포 · 롱런 · 이지 · 회복`이고 `event_type`과 RunPulse 워크아웃 분류(`runpulse_workout_class`)를 사용한다.
  2. 기간 시트: `이번 달 / 지난 달 / 최근 3개월 / 올해 / 2025 / 2024 / 2023 / 직접 선택`. 목록 오른쪽 가장자리에 **연-월 스크러버**(iOS 사진 앱 방식)를 두어 드래그 한 번으로 2023-10까지 점프한다.
  3. 무한 스크롤로 바꾸고(센티널 + "N / 626건 표시" 진행 표시) 끝에 닿기 전에 미리 불러온다.
  4. 검색 범위를 이름·날짜(`2025-10`, `10/18`)·장소·대회명으로 넓힌다. 결과가 0건이면 "이름에 '대회'가 들어간 활동은 없어요. **대회로 표시된 활동 18건 보기**"를 제안한다.
  5. 정렬: 최신순 / 거리순 / 페이스순 / 부하순. "하프+ · 페이스순"만으로 PB 후보를 볼 수 있다.

### [중요] F-UX-05 필터·페이지·스크롤·진입 경로가 보존되지 않는다 — ←가 늘 같은 곳으로 간다 (U8)
- 현상:
  - 종목·거리·검색 필터와 현재 페이지가 컴포넌트 로컬 state에만 있다(`activities/+page.svelte:23-26`). URL에는 기간(`from`/`to`)만 남는다.
  - 상세 헤더의 ←는 하드코딩된 `href="{base}/library/activities"`다(`[id]/+page.svelte:78`). 그래서 월 필터 목록에서 들어왔다가 ←를 누르면 필터가 풀린 전체 목록으로, PB나 Library 홈에서 들어왔다가 ←를 누르면 홈이 아닌 목록으로 간다.
  - 서브탭 페이지의 ←는 "요약"으로 간다(`laps/+page.svelte:121`). 같은 아이콘이 탭마다 다른 뜻이다.
  - 스크롤 복원·SvelteKit `snapshot` 사용은 0건이다(grep 결과 coach 한 곳뿐). "더 불러오기"로 60건을 본 뒤 상세에 들어갔다가 돌아오면 20건부터 다시 시작한다.
- 왜 문제인가: 목록 → 상세 → 목록을 반복하는 "훑어보기" 과업(지난달 세션 비교 등)이 매번 초기화된다. 사용자는 뒤로가기를 믿지 못하게 된다.
- 개선안:
  1. 필터 전체를 URL 쿼리로 옮긴다: `/library/activities?from=2026-08-01&to=2026-08-31&sport=running&type=interval&q=크루즈&sort=date`.
  2. 상세 링크에 `?from=<origin>`(today|library|list|plan|coach|pb)을 붙인다. ← 동작은 `history.length > 1`이고 같은 앱에서 왔으면 `history.back()`, 아니면 origin에 맞는 경로로 간다. 라벨도 바꾼다: `← 8월 활동`, `← Library`, `← 계획`.
  3. 목록에 SvelteKit `snapshot`으로 `{activities, page, scrollY}`를 저장해 복원한다.
  4. 서브탭 전환은 `replaceState`로 처리해 탭 이동이 브라우저 히스토리에 쌓이지 않게 한다. 서브탭 페이지에서는 ←를 없애고 헤더를 공통 레이아웃으로 유지한다(F-UX-11).

### [중요] F-UX-06 월 필터 목록: 지금 어느 달인지, 다음·이전 달로 어떻게 가는지 보이지 않는다
- 현상: 월 막대로 들어오면 헤더는 여전히 "활동 목록 18건"이고, 칩 `2026-08-01 ~ 2026-08-31`과 작은 "기간 해제 ✕"만 있다. 다른 달로 가려면 Library 홈으로 돌아가 다른 막대를 눌러야 한다. 월 경계에 걸친 주는 부분 합계가 "주 합계"처럼 보인다(예: `7/27 – 8/2 · 1회 · 8.1km`). 12개월보다 오래된 달은 진입할 수 없다.
- 근거: `library-month-filter-mobile.png`, `activities/+page.svelte:114`, `ArchiveHero.svelte:48`.
- 개선안: 헤더를 `‹ 2026년 8월 ›`으로 바꾸고(좌우 스와이프도 지원) 그 아래에 월 요약 한 줄을 둔다: `18회 · 171km · 이지 12 / 인터벌 4 / 롱런 2 · 전월 대비 +12%`. 필터가 걸린 경계 주는 `(8월분만)`으로 표시한다. 해제는 44px 이상 칩 `✕ 8월`로 만든다. 월 막대 차트에도 `‹ 이전 12개월` 페이지를 추가한다.

### [중요] F-UX-07 활동 상세에서 다음 행동으로 가는 출구가 없다 — Coach 묻기·RPE·통증·메모 (P6, P1, U8)
- 현상: 요약 탭은 "이 러닝의 의미"(CTL +2.8 · TSB −15 · D-56)로 끝나고, 행동 요소가 없다. `routes/library/[id]/` 아래와 `RunStory.svelte`에서 `coach|rpe|RPE|통증` grep 결과는 0건이다(확인). 원본 Garmin 링크(`core.source_url`)도 응답에는 있지만 UI에 쓰이지 않는다(grep 0건).
- 왜 문제인가: P6은 활동 상세에서 3탭 이내 RPE·통증·메모 입력을 요구한다. 러너가 활동 직후 가장 먼저 하는 질문("오늘 롱런 후반에 심박이 왜 이렇게 올랐지?")을 코치에게 이어갈 수 없다. 코칭 옆 근거라는 비전과 반대 방향으로 끊겨 있다.
- 개선안:
  1. 요약 탭 히어로 바로 아래에 **세션 피드백 바**를 둔다: `어땠나요? RPE [1…10 슬라이더] · 통증 [없음/부위 선택] · 메모 +`. 한 번 탭으로 펼치고 저장하면 `RPE 6 · 메모 1` 칩으로 접힌다. Strava의 Perceived Exertion 위치와 같다.
  2. 페이지 하단에 고정 CTA `이 러닝에 대해 코치에게 묻기`를 둔다. 누르면 `/coach/new?activity=17414`로 가고 대화 첫 메시지에 활동 카드(거리·페이스·디커플링·TSB)가 근거 칩으로 붙는다. 추천 질문 3개는 활동 유형에 맞춘다(롱런: "후반 심박 상승이 걱정할 수준인가요?" / 인터벌: "목표 페이스를 지켰나요?").
  3. 헤더 오른쪽 `⋯` 메뉴에 `Garmin에서 열기 ↗`, `GPX 내보내기`(P8 소유권)를 넣는다.

### [중요] F-UX-08 세션 유형을 모른 채 해석한다 — 인터벌에 "네거티브 스플릿", 랩 탭엔 work/rest 구분 없음 (U5, P1)

  - `buildRunStory`는 km 스플릿만으로 헤드라인을 만든다(`lib/runStory.ts:26-45`). 크루즈 인터벌(14597)이나 롱런도 "전반/후반 페이스" 틀로 요약된다.
  - "이 러닝의 의미"의 "비슷한 거리 이전 10회 중 3번째로 빠른 페이스"도 인터벌과 이지런을 같은 기준으로 비교한다(API `impact.similar`, 14597).
  - 롱런 15302는 초록 헤드라인 "후반이 전반보다 0:09/km 빨랐어요"인데, 같은 카드 안의 디커플링 11.2%(주황)와 심박 132→153은 부정 신호다. 헤드라인이 더 중요한 신호를 가린다(`activity-15302-mobile.png`).
  - 랩 탭은 1km 랩과 150초 회복 랩을 같은 막대로 나열한다. API에는 `wkt_step_index`, `compliance_score`가 있지만 프론트엔드에서 쓰이지 않는다(grep 0건).
- 개선안:
  1. 상세 헤더에 **세션 유형 칩**(`인터벌 · 크루즈 1k×4` / `롱런` / `이지` / `대회`)을 둔다. 출처는 RunPulse 워크아웃 분류이고, 탭하면 분류 근거가 보인다.
  2. 유형별로 이야기 템플릿을 나눈다.
     - 인터벌: `4개 반복 모두 목표 4:20±5초 안 — 마지막 반복 심박 177로 가장 높음`
     - 롱런: `후반 페이스는 유지했지만 심박이 21bpm 올라갔어요 — 유산소 분리 11%(주의)`. 경고 신호가 있으면 헤드라인에 우선 반영한다.
     - 대회: 목표 기록 대비와 스플릿 전략.
  3. 랩 탭은 인터벌일 때 **work/recovery 그룹 뷰**로 기본 전환한다. 반복별 페이스·심박을 나란히 놓고, 반복 간 편차와 계획 대비 이행률(`compliance_score`)을 보여준다. 매칭된 계획 세션이 있으면 `계획: 2-1 크루즈 (1k, 2분, 4회) ›` 링크로 잇는다(Intervals.icu의 interval 탭, TrainingPeaks의 planned vs completed 참고).
  4. "비슷한 세션" 비교 기준을 같은 유형으로 바꾼다: `지난 크루즈 3회 대비 반복 평균 −6초/km`.

### [중요] F-UX-09 메트릭 서브탭: 이름·값 나열뿐 — 설명·범위·해석 없음, 개발용 항목과 중복 개념이 노출된다 (U5, U6, P3)
- 현상: 20개 메트릭이 카테고리별 `<details>`에 들어 있다.
  - 이름이 잘린다(`TRIMP (Ban…`, `RunPulse 유산소 …`, `Field-Equival…`, `activity-metric-vdot-mobile.png`).
  - 해석과 상태 색이 없다. 같은 화면 요약 카드에서도 status가 붙은 것은 "유산소 훈련 효과 ● 큰 개선" 하나뿐이다.
  - 사용자 화면에 `미매핑 (개발용) (1) splits_metric —`가 보인다(`raw/activity-metrics.txt`).
  - 같은 개념이 둘씩 나온다. GAP는 Garmin 5:56과 RunPulse 6:02, VO2Max는 Garmin 53과 RunPulse VDOT 32.7, 디커플링은 요약 카드 4.5%와 메트릭 탭 4.4%다.
  - 탭끼리 값이 다르다. TRIMP는 메트릭 탭 97.3, 소스 비교 탭 101이고 Relative Effort는 메트릭 탭 302, 소스 비교 "상대적 노력도" 27.7이다(`raw/activity-providers.txt`). 차이를 설명하는 문구가 없다(정확성 판단은 데이터 전문가 영역, UX로는 "설명 없는 불일치").
  - 요약의 "전체 메트릭 보기 →"는 이 탭으로 이동할 뿐이라 서브탭 "메트릭"과 같은 목적지로 가는 경로가 두 개다.
- 개선안:
  1. 행을 2줄로 만든다. 1줄: `유산소 분리 4.4% ●안정`. 2줄(작게): `심박 대비 속도가 후반에 얼마나 떨어졌나 · 5% 미만이면 유산소 기반 양호`. 이름은 줄바꿈해 전체를 보인다.
  2. 카테고리 순서를 러너 질문 순서로 바꾼다: **"얼마나 힘들었나(부하)" → "얼마나 효율적이었나" → "체력 신호" → "기타"**. 카테고리 머리에 한 줄 결론을 둔다(`부하: 이지런 대비 높음 — TRIMP 97 / 30일 중앙값 72`).
  3. 같은 개념은 **한 행으로 묶고 provider를 병렬 표기**한다: `VO2max  Garmin 53 · RunPulse VDOT 32.7 ⚠ 차이 큼 — 왜?`. 탭하면 소스 비교 행으로 이동한다.
  4. `미매핑(개발용)`은 설정의 "개발자 모드"에서만 보인다.
  5. 요약의 "전체 메트릭 보기 →"는 이동 대신 **요약 내 확장**(핵심 5개 → 부하·효율 전체)으로 바꾸거나 링크를 없앤다.

### [중요] F-UX-10 서브탭 구조: 헤더가 바뀌고, 탭마다 650KB를 다시 받고, 스크롤 위치가 사라진다 (U8, U9)
- 현상:
  - 요약 헤더는 `← 러닝 [Garmin] 2026-09-27`인데 서브탭으로 가면 `← 랩`, `← 메트릭`이 되어 **어떤 활동인지 사라진다**(`raw/activity-laps.txt`).
  - 각 서브탭 `+page.ts`가 `getActivity(id)`를 다시 호출한다(`laps/+page.ts`). 02-performance 기준 650KB이고, 스트림 탭은 +630KB다.
  - 로컬에서는 전환 90~277ms지만 모바일 LTE에서는 탭마다 수백 ms~초 단위로 추정된다. 로딩 표시가 없어 그동안 이전 탭이 멈춘 것처럼 보인다.
- 개선안:
  1. `routes/library/[id]/+layout.svelte`로 헤더(이름·날짜·세션 유형·provider 병합 배지)와 탭 바를 공통화하고, `+layout.ts`에서 요약 데이터를 한 번만 받는다. 스트림 원본은 스트림 탭에서만 지연 로드한다.
  2. 모바일에서는 탭 바를 sticky로 두고, 탭을 전환할 때 탭 바 위치로 스크롤한다.
  3. 탭 전환 즉시 상단 2px 진행바(`$navigating`)와 탭 본문 스켈레톤을 보인다.

## 잘된 점
- 요약 탭 "이 러닝의 이야기"는 전후반·디커플링·가장 빠른 구간을 근거와 계산 설명("앞 4km 평균과 뒤 4km 평균")과 함께 보여준다. 활동을 "읽히는 이야기"로 만드는 방향이 맞다.
- 목록의 주 단위 그룹(주 합계 + 상대 막대), 경로 썸네일, 페이스·심박 상시 노출은 훑어보기에 좋다. 월 막대 → 월 필터, PB → 해당 활동 연결은 잘 동작한다(250~320ms).
- 경로 지도의 페이스/심박 색 토글, 스트림 기반 KM 스플릿 막대(최고 구간 강조), 이상치 클램프 고지는 투명성 원칙에 맞다.
- 소스 비교 탭(★ 대표값, ⚠ 5% 초과)은 경쟁 앱에 없는 자산이다. 노출 위치만 끌어올리면 된다.

## 채점 (0~10)
- 비전 부합 **5** — 아카이브 소유감과 활동 이야기는 방향이 맞지만, 투명성의 핵심인 분해가 비어 있고 행동(Coach·RPE)으로 이어지지 않는다.
- 정보 정확성 **4** — 근력 필터 0건, 원시 부동소수 110.2020…, 탭 간 값 불일치(TRIMP 97.3/101, RE 302/27.7), 설명 없는 건수 불일치.
- 시각 품질 **6** — 요약 탭 위계는 좋다. 메트릭 탭 이름 잘림과 개발용 항목 노출이 있다.
- 상호작용 반응성 **5** — 로컬 전환은 빠르지만 로딩 피드백 0, Library 홈 1.4~1.7s 빈 화면, 서브탭마다 650KB 재요청.
- 흐름 **3** — 상세로 못 가는 지점 4곳 이상, ← 고정 목적지, 필터·스크롤 소실, 막다른 상세.
