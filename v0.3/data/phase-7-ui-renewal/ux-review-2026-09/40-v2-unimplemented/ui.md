# v2 미구현 영역 — UI(시각·인터페이스) 평가·설계

**리뷰일**: 2026-09-27 · **대상**: v2(`/v2/*`)의 미구현·반구현 영역 — ☰ 메뉴와 Data(`/data`, `/data/sources`, `/data/sync`, `/data/export`, `/data/settings`), 계획 비교(`/v2/coach/plan/compare`), Story(`/library/story*`, 현재는 Today 월간 시트), 웰니스 일자별(`/library/wellness/:date`), 전역 셸(사이드바·하단 탭·as-of·동기화 상태)
**근거**: `screenshots/coach-plan-compare-*`, `library-wellness-*`, `today-month-story-*`, `v1-*`(계승 패턴 추출용), `raw/*.txt`, `raw/interact-*.json`, 읽기 전용 GET(`/api/v1/library/providers/status`, `/library/wellness?date=`, `/coach/plan/templates`), 코드 `frontend/src/**`
**v1 취급**: 평가하지 않는다. §3에 v2가 계승·참고할 **UI 패턴**만 표로 정리한다.

요약:
1. **v2에는 "내 데이터가 언제까지 들어왔나"를 보여 주는 화면이 없다.** ☰는 `disabled`인데 fg-muted 색이라 켜진 버튼처럼 보이고, 동기화 시각·소스 연결 상태·내보내기·설정으로 가는 경로가 v2 안에 하나도 없다. P8(마지막 동기화 시각 상시 표시)을 정면으로 어긴다.
2. **"마지막 동기화" 값이 출처마다 다르다(확인).** 같은 계정에서 v2 API는 Garmin `2026-09-27 11:56:47`, v1 대시보드는 `2026-09-27T10:46`, v1 동기화 화면은 `2026-05-11 09:39`로 나온다. 셸에 동기화 상태를 올리기 전에 기준 필드를 하나로 정해야 한다. 그렇지 않으면 표시가 오히려 신뢰를 깎는다.
3. **계획 비교는 URL로 바로 들어가면 가공되지 않은 오류 화면("400 / 거리 정보가 없습니다")을 여백 없이 띄운다.** 정상 경로로 들어가도 실데이터 API는 템플릿을 1개만 돌려줘서 "비교"가 성립하지 않는다. 위험도 "중간"에는 정의되지 않은 토큰(`text-semantic-yellow`)이 쓰였다.
4. **웰니스는 "오늘" 한 장뿐이다.** API는 `?date=`와 `metrics_by_category`를 지원하지만 UI에는 날짜 이동이 없고, 날짜는 ISO 원문으로 표시되며, 수치는 눌러도 반응이 없다. 30일 스파크라인에는 축·날짜·최솟값/최댓값이 없고 팔레트 밖 hex 색을 쓴다.
5. **Story는 URL 없는 하단 시트로만 존재한다.** 데스크톱에서도 1280px 전폭 하단 시트로 뜨고, 시트 배경이 페이지와 같은 surface-1이며, 월 이동 버튼은 약 24px로 작고, CTL 추세 칸은 비어 있다.

### [중요] F-UI-03 "마지막 동기화" 출처가 셋이고 값이 서로 다름 — 표시 설계 이전에 기준을 하나로
- 현상: 같은 시점(2026-09-27)에 세 화면이 다른 값을 보인다.

  | 표시 위치 | Garmin | Strava |
  |---|---|---|
  | v2 API `/library/providers/status` `last_synced_at` | 2026-09-27 11:56:47 | 2026-06-23 14:13:16 |
  | v1 대시보드 헤더 | 2026-09-27T10:46 (소스 구분 없음) | — |
  | v1 동기화 화면(소스 카드·요약 배너) | 2026-05-11 09:39 | 2026-05-08 11:09 |

  v1 동기화 화면의 자동 동기화 블록은 "마지막 실행: 2026-09-27T12:40:05"로, 같은 화면의 배너(05-11)와도 어긋난다. API 값에는 시간대가 없는데, `providerHint.ts`는 공백 형식을 `Z`(UTC)로 가정해 해석한다.

- 왜 문제인가: P8은 "마지막 동기화 시각 상시 표시"를 요구하는데, 값이 틀리면 상시 표시가 신뢰를 깎는다. 시간대를 잘못 해석하면 "9시간 전"처럼 틀린 상대 시각이 나올 수 있다(추정 — 서버 저장 시간대 미확인).

### 2.7 설정(`/data/settings`)
섹션 4개를 SectionHeader + SettingRow(라벨 좌 / 값·입력 우, 행 높이 48)로 구성한다.

## 4. 잘된 점 (유지)
- `SourceCoverage`의 소스별 12개월 월 셀 띠와 "동기화 안 함" 소스의 경고 생략 규칙은 소스 카드에 그대로 쓸 수 있는 좋은 기반이다.
- `providerHint.ts`는 상태를 "다음 행동 한 줄"로 번역한다("N일째 동기화가 없어요 …"). SyncStatusPill 문구 규칙으로 확장할 가치가 있다.
- `asOf.ts`는 "오늘 지금까지 반영"과 "M월 D일 기준"을 구분한다. 기준일 개념은 이미 올바르다. 문제는 노출 범위와 크기다.
- 웰니스 API의 `?date=`와 `metrics_by_category`, `providers/status`(182ms)는 이미 있어서 일자별 뷰와 셸 상태 표시는 프론트 작업 위주로 진행할 수 있다.
- 셸의 3탭 SVG 아이콘, 사이드바↔하단 탭 반응형 전환, `aria-current`는 일관되다.

## 5. 채점 (0~10, 현재 v2 상태 기준, 한 줄 근거)
- 비전 부합: 2 — P8의 핵심(동기화 시각 상시 표시, export, 소스 상태)이 v2에 전무하고, 관리 과업은 v1으로 이탈해야 한다.
- 정보 정확성: 4 — 동기화 시각이 출처마다 다르고 시간대가 불명확하다. 웰니스는 오늘만, 비교는 1건이라 "비교"라는 이름부터 틀린다.
- 시각 품질: 4 — 오류 화면은 가공되지 않았다. 팔레트 밖 hex, 미정의 토큰 2곳, provider 색 대비 미달, 전폭 시트가 있다.
- 상호작용 반응성: 3 — ☰ 무반응, 웰니스 카드 무반응, 월 이동 24px 버튼. 반응하는 요소는 빠르다(시트 수십 ms).
- 흐름: 2 — Story·웰니스 일자·Data에 URL이 없고, 비교 화면은 막다르다.
- 혁신성: 3 — 소스 커버리지 띠·기준일 개념은 차별화 씨앗이지만, "4소스 통합 상태판"이라는 signature 화면이 아직 없다.

1. **SyncState 단일 계약 + 전역 SyncStatusPill(F-UI-01/03/04)**: 소스별 `last_success_at`(오프셋 포함)·오류·enabled와 `latest_data_date`를 한 API로 제공하고, 셸 헤더와 사이드바에 상시 표시한다. ☰는 좌측 MenuDrawer로 활성화한다.
