# v2 미구현 영역 — UX(사용자 경험·흐름) 평가·설계

**리뷰일**: 2026-09-27 · **대상**: v2 기본 진입 전환(현재 `/` → v1 `/dashboard`), ☰ Data 흐름(동기화 실행·진행·실패, 소스 연결/재연동/해제, 내보내기, 설정), 계획 비교 진입 경로, Story, 웰니스 일자별, 첫 사용자 온보딩·빈 상태, 오류 상태(API/소스)
**근거**: `raw/v2-root.txt`, `raw/v1-*.txt`, `screenshots/coach-plan-compare-*`, `today-month-story-*`, `library-wellness-*`, `raw/interact-*.json`, 코드 `frontend/src/**`, `src/web/app.py`, 읽기 전용 GET(`/api/v1/library/providers/status`, `/bg-sync/status`)
**관계 문서**: 같은 폴더 `data.md`(동기화 원장·오류 분류·API 재사용 판단 §B)와 `ui.md`(MenuDrawer·SourceCard·SyncStatusPill·화면 와이어프레임 §2)가 이미 다룬 내용은 반복하지 않고 참조만 한다. 이 문서는 **흐름·동작 수·상태 전이·전환 절차**를 다룬다.
**v1 취급**: 평가하지 않는다. §C에 v2가 계승·참고할 **흐름**만 표로 정리한다.

요약:
- **v2는 혼자서 "데이터를 넣고 → 확인하고 → 고치는" 루프를 닫지 못한다.** ☰가 비활성이고(`+layout.svelte:29-36`), v1↔v2 상호 링크가 0개다. v2에서 동기화를 하려면 주소창에 `/sync`를 직접 쳐야 한다. 동기화를 권하는 v2 문구 3곳이 모두 막다른 곳이다(data F-DATA-03).
- **v2 기본 진입 전환의 전제가 문서와 코드에서 어긋난다.** 07 로드맵의 롤백 수단인 `use_v2` 쿠키 베타 토글은 코드에 없다(grep 0건). `/`는 무조건 `/dashboard`로 302한다(`app.py:305-307`). 지금 전환하면 되돌릴 스위치가 없다.
- **오류와 빈 상태가 구분되지 않는다.** Today는 `/today` 호출이 어떤 이유로 실패해도 "아직 데이터가 없습니다 — 소스를 연결하면…"을 보여 준다. 전역 `+error.svelte`가 없어 계획 비교 직접 진입은 "400 / 거리 정보가 없습니다" 원문에서 멈춘다. 소스 실패(403·토큰 만료·레이트리밋)는 v2 어디에도 보이지 않는다.
- **계획 비교는 활성 계획이 있으면 진입 경로가 0개다.** Coach 홈은 활성 계획이 있으면 "새 프로그램 만들기"를 숨기고, `/coach/plan`은 활성 계획으로 302한다. 계획 상세에는 목표 수정·재생성·비교·내보내기가 없다. 없는 계획으로 가는 경로도 "단계 1/3 → 3/3"으로 2단계가 빠져 있다.
- **Story·웰니스 일자는 "다시 찾아갈 수 없는" 화면이다.** 월간 이야기는 URL 없는 시트라서 뒤로가기를 누르면 Today를 떠난다. 웰니스는 오늘 한 장뿐이다. API(`?date=`, `?year&month`)가 이미 있어 프론트 라우트만 없으면 되는 상태다.

## 잘된 점 (유지)
- 백엔드 동기화는 이미 흐름 설계에 필요한 이벤트를 준다. 소스별 SSE(`source_start`/`source_done`), 중복 실행 방지(`running`), 재시도 대기(`retry_after`), 정책 가드 한국어 메시지가 있다. v2는 이를 상태 기계로 표시만 하면 된다.
- 계획이 없을 때 레이스 허브·계획 게이트웨이가 목표를 프리필해 `/coach/plan/new`로 이어 준다(`planPrefill.ts`, `plan/+page.svelte:28`). 맥락을 전달하는 올바른 패턴이며 "목표 수정" 흐름에도 그대로 쓸 수 있다.
- `providerHint.ts`가 상태를 "다음 행동 한 줄"로 번역하는 방식과 `SourceCoverage`의 "동기화 안 함 = 경고 아님" 규칙은 소스 상태 문구의 기준으로 적합하다.
- 새 프로그램 화면은 입력 전 제출을 막고, 실패 시 "다시 시도해주세요" 인라인 오류를 준다. 오류 처리의 최소 형태는 이미 있다.
- 월간 이야기·마일스톤 시트는 반응이 79~166ms로 빠르다. 라우트로 옮겨도 체감 속도는 유지될 가능성이 높다(API 520ms 제외).
