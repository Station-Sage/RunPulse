## 1. 북극성 (평가의 최상위 질문)

> RunPulse는 러너의 흩어진 데이터를 하나로 모아, 스스로 이해할 수 있는 언어로 번역하고,
> 더 나은 결정을 내릴 수 있게 돕는 **개인 러닝 인텔리전스 플랫폼**이다.

- **페르소나**: Garmin/Strava/Intervals/Runalyze를 오가며 상태를 스스로 조립하던 러너. 데이터를 좋아하지만
  데이터 과학자는 아님. *"왜 쉬어야 하는지, 어떤 수치가 그 판단의 근거인지"를 함께 보고 싶은 사람.*
- **비전 3원칙**: ① 데이터 통합·소유권 ② 투명한 분석 ③ 맥락 있는 안내(그래서 무엇을 할까 + 근거)
- **되지 않을 것**: 소셜(Kudos/리더보드), 라이브 GPS 트래커, 경직된 PDF 플랜, 클라우드 잠금
- **REVIEW-05 방향 3문장**: 목표 중심(다음 레이스를 안다) · 보이는 증거(활동=읽히는 이야기, 코칭 옆 근거) ·
  내 아카이브(수년치가 "내 것"으로 보임)

## 2. 설계 원칙 P1~P8 체크 (우선순위 순)

| # | 원칙 | 화면에서 확인할 것 (합격 기준) |
|---|------|------------------------------|
| P1 | Evidence-First | 결론·권장·점수·경고 옆에 **클릭 가능한 근거 칩** 2~3개. "왜?"를 누르지 않아도 근거가 보임. 근거 없는 결론 = 위반 |
| P2 | Drillable Everything | 모든 메트릭 값·차트 포인트가 **한 번의 탭**으로 계산 분해 → 원천(활동/날짜)까지(최대 3단). 클릭해도 반응 없는 숫자/차트 = 위반 |
| P3 | Provider Transparency | 숫자마다 출처 배지 또는 1탭 내 확인. RunPulse 합성 메트릭은 공식 버전·계산 시각. 타 provider 값 비교 |
| P4 | Intent-Centered IA | 탭=의도(Today/Library/Coach + ☰Data). 진입 3초 안에 "여기서 무엇을 할 수 있나" 전달. 영역 이동 시 컨텍스트 유지 |
| P5 | Quiet Data | 데이터 잉크 우위, 장식 그라데이션·글래스·네온 없음, 숫자는 모노스페이스 위계, 의미색(등급 5단/provider 4종)만 |
| P6 | One Finger Reach | RPE·통증·메모 입력이 Today/활동 상세/Coach에서 **3탭 이내** |
| P7 | State-Bound Plan | 계획·세션 카드에 현재 ACWR/HRV/TSB와 상태 기반 조정 제안([수락]/[원래대로]) |
| P8 | Data Ownership | 외부 LLM 전송 범위 고지, export/원본 접근이 기본 흐름에 노출, 마지막 동기화 시각 상시 표시 |

## 3. 사용자 지정 필수 점검 항목 (원문 요구 → 검사 방법)

| ID | 요구 | 검사 방법 |
|----|------|----------|
| U1 | 차트 숫자 확인 가능성 | 모든 차트에 축 눈금·값 라벨·호버/탭 툴팁 존재 여부. 모바일에서 탭으로 값 확인 가능한지 |
| U2 | 차트 방향 = 의미 방향 | 시간·페이스·예측기록 등 "낮을수록 좋은" 값의 축이 뒤집혀 **실력 향상이 위로** 보이는지(예: 마라톤 예측 시간 차트) |
| U3 | 단위·포맷 | 시간은 `h:mm:ss`, 페이스는 `m:ss/km`. 원시 초(예: `1800`)·소수 과다·단위 누락 = 위반 |
| U4 | 클릭 기대 = 반응 | 활동 행/카드/차트 포인트/메트릭 칩 등 **누를 것 같은 모든 요소**가 실제로 이동·확장되는지 |
| U5 | 지표 설명·의미 | 지표마다 "무엇인가 / 좋은 범위 / 지금 내 값의 해석 / 그래서 무엇을" 제공 여부 |
| U6 | 지표 분해의 질 | 분해가 단순 나열인지, **기여도·가중치·공식·원천**으로 구성되어 결론을 설명하는지 |
| U7 | 혁신성 | Strava/Garmin/Intervals/Runalyze에 없는 signature moment(4소스 통합·계산 투명성·근거 코칭·목표 레이스 허브)가 눈에 보이는지 |
| U8 | 화면·탭 간 흐름 | 진입→판단→근거→행동 경로가 끊기지 않는지, 뒤로가기·탭 상태 유지, 막다른 화면 |
| U9 | 속도 | 초기 로딩, 탭 전환, 주요 클릭 반응, API 응답 시간(아래 기준) |
| U10 | 최고 수준 여부 | 세계 최고 러닝 앱(Strava·Garmin Connect·Runna·TrainingPeaks·Intervals.icu·WHOOP) 대비 수준 |

## 4. 성능 기준 (U9)

| 항목 | 좋음 | 허용 | 나쁨 |
|------|------|------|------|
| 초기 로딩(첫 의미 있는 콘텐츠, LCP 근사) | ≤ 1.5s | ≤ 2.5s | > 2.5s |
| 탭/화면 전환(클릭→콘텐츠 렌더) | ≤ 300ms | ≤ 1s | > 1s |
| 클릭 반응(시각 피드백 시작) | ≤ 100ms | ≤ 200ms | > 200ms (INP 기준) |
| API 응답 | ≤ 200ms | ≤ 800ms | > 800ms |
| 로딩 중 상태 | 스켈레톤/진행 표시 | 스피너 | 빈 화면·레이아웃 점프 |

## 5. 전문가별 관점

| 역할 | 핵심 질문 | 주 근거 |
|------|----------|---------|
| 러닝 데이터 전문가 | 지표가 정확·일관·의미 있게 선택·해석되었나? 러너의 결정(훈련/회복/레이스)에 실제로 쓸모 있나? 단위·방향·범위가 러닝 관행에 맞나? | 화면 수치 vs API 응답, 계산 근거, 코칭 원칙 |
| UI 전문가 | 시각 위계·타이포·색·밀도·차트 문법·반응형·일관성·접근성(대비·터치 타깃 44px) | 스크린샷(데스크톱 1280 / 모바일 390), 컴포넌트 코드 |
| UX 전문가 | 의도→행동 경로, 어포던스와 실제 반응 일치, 피드백·로딩·빈 상태·오류, 탭 간 흐름, 인지 부하 | 클릭 측정, 사이트맵, 라우트 코드 |

## 6. 심각도 정의

| 등급 | 정의 |
|------|------|
| **치명** | 잘못된 정보로 오판을 유도(방향 반전·단위 오류·틀린 수치), 핵심 과업 불가(클릭 무반응·막다른 화면), 비전 핵심 원칙(P1/P2) 정면 위반 |
| **중요** | 과업은 되지만 이해·신뢰·효율을 크게 떨어뜨림(설명 부족, 느린 반응, 위계 붕괴, 모바일 깨짐) |
| **개선** | 품질·완성도·일관성 향상, 최고 수준 도달을 위한 다듬기 |

## 7. 평가 척도 (화면별 점수)

각 탭 결과물 말미에 아래 6축을 0~10으로 채점한다: **비전 부합 / 정보 정확성 / 시각 품질 / 상호작용 반응성 / 흐름 / 혁신성**.
