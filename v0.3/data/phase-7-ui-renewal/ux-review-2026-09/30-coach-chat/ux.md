# Coach 대화 — UX(사용자 경험·흐름) 리뷰

**리뷰일**: 2026-09-27 · **대상**: `/v2/coach`(Coach 홈), `/v2/coach/:threadId`(대화), Coach 홈의 컨디션 입력, Today·활동 상세에서 Coach로 들어오는 경로
**범위 메모**: 메시지는 전송하지 않았다. 응답 흐름은 코드(`routes/coach/**`, `src/services/coach_service.py`, `src/ai/chat_engine*.py`)와 저장된 스레드 4개(메시지 11건)의 API 응답으로 추론했고, 추론한 부분에는 "(추정)"을 붙였다. 계획(`/v2/coach/plan/**`)은 `31-coach-plan/`에서 다룬다.

요약:
- **지금 Coach는 AI 코치가 아니라 키워드 템플릿이다. 사용자는 그 사실을 알 수 없다.** 저장된 어시스턴트 답변 6건이 모두 `ai_model: "rule"`이다. 컨테이너 로그에는 Gemini·Groq 호출이 `404 Not Found`로 실패한 기록이 있고, 실패는 조용히 규칙 응답으로 넘어간다. 화면에 보이는 신호는 말풍선 안 11px "규칙 기반 답변" 한 줄뿐이다. 규칙 응답은 회복 등급이 `excellent`일 때도 "피로 회복이 필요합니다"라고 말한다(등급 코드 불일치). 존재하지 않는 "훈련 탭", "설정 > AI"로도 안내한다.
- **근거 칩은 이 답변의 근거가 아니다.** 질문과 상관없이 답변 시점의 Today 브리핑 근거를 붙인다(`build_evidence`). 그래서 "피로 회복이 필요"라는 답 옆에 `UTRS 75 (양호)`가 붙는다. `TSB -11` 칩을 누르면 같은 날짜(9/25)의 TSB가 **-3.3**으로 뜬다. 칩 4개 중 2개는 누를 수 없고, 시트는 값 한 줄만 보여주는 막다른 곳이다.
- **맥락을 가지고 Coach에 올 수 없다.** Today의 "Coach에게 더 묻기 →"는 빈 Coach 홈으로 이동하고, 활동 상세에는 Coach로 가는 경로가 없다. Coach는 `?q=`나 활동 id 같은 맥락 파라미터를 받지 않는다.
- **기다리는 동안과 실패했을 때의 피드백이 약하다.** 스트리밍이 없다. 새 대화는 버튼 문구가 "전송 중…"으로 바뀌는 것 말고는 사용자 메시지조차 보여주지 않는다. provider 타임아웃이 60s·30s로 이어져 최악의 경우 1~2분을 기다릴 수 있다(추정). 전송에 실패해도 보낸 말풍선은 성공한 것처럼 남고, 재시도 버튼이 없다.
- **스레드는 쌓이기만 하고 관리할 수 없다.** 삭제·이름 변경·검색이 없다. 제목은 첫 메시지를 그대로 자른 것이고, 미리보기는 템플릿 문장이라 4개 중 3개가 "오늘의 훈련 추천 피로 회복이 필요합니다…"로 똑같다. 대화 화면에는 날짜가 없어서 "오늘 계획: recovery 6.9km"가 언제의 '오늘'인지 알 수 없다.

## 발견

### [치명] F-UX-01 AI 응답 체인이 깨져 모든 답변이 키워드 템플릿인데, 사용자에게는 그 사실과 품질 저하가 알려지지 않는다
- 현상: 저장된 어시스턴트 메시지 6건이 전부 `ai_model: "rule"`이다(`GET /api/v1/coach/threads/1~4`로 확인). 같은 질문 유형에는 문장이 거의 같다. "훈련 분석"과 "훈련분석"에는 `"훈련 분석"에 대한 분석 — TSB(신선도) -16.5, 회복 등급: moderate … 💡 더 정확한 답변을 원하시면: 설정 > AI에서 Claude 또는 ChatGPT API 키를 입력하세요`가 나온다. v2에는 설정이 없다. "마라톤 거리별 예상시간은?"에는 "설정된 목표 레이스가 없습니다. 훈련 탭에서 목표를 추가하세요"가 나온다. v2에는 훈련 탭이 없다. 오늘 훈련 추천은 회복 등급이 `A/B/C`일 때만 분기하는데, 실제 값은 `moderate`/`excellent`다. 그래서 **등급과 관계없이 항상 "피로 회복이 필요합니다. 가벼운 조깅이나 휴식을 권장합니다"**가 나온다. 스레드 2에서는 `회복 등급: excellent`, `TSB +2.6 — 적정 훈련 상태`, `UTRS 81 (매우 좋음)` 근거와 "피로 회복이 필요" 결론이 같은 화면에 함께 보인다.
- 근거: 컨테이너 로그 `Gemini API 오류: Client error '404 Not Found' … /v1beta/openai/chat/completions`, `Groq API 오류: … 404 Not Found`. `src/ai/chat_engine.py:43-99`(provider 체인이 실패하면 경고 로그만 남기고 `rule_based_response`로 넘어감). `src/ai/chat_engine_rules.py:70-84`(`grade in ("A","B")`), `:115`("훈련 탭"), `:260-262`("설정 > AI"). `lib/markdownLite.ts` `localizeSource`: `rule` → "규칙 기반 답변". `coach-thread-mobile.png`.
- 추가(추정, 키워드 분기 순서로 추론): 홈 주제 칩 "목표 기록 가능할까?"는 "할까"가 먼저 걸려서 **오늘 훈련 추천** 템플릿으로 답한다. 후속 칩 "남은 기간 주차별로 어떻게 준비할까?"도 같은 템플릿으로, "왜 테이퍼하면 폼이 올라가?"는 `"…"에 대한 분석` 일반 템플릿으로 답한다. 앱이 직접 제안한 질문이 엉뚱한 답을 받는다.
- 왜 문제인가: 비전 ③ "맥락 있는 안내"의 핵심 화면이 오판을 유도한다. TSB +2.6·UTRS 81인 날에 쉬라고 한다. 이것은 오판을 유도하는 잘못된 정보다(심각도 정의상 치명). 품질이 떨어졌다는 신호가 없으니 사용자는 "RunPulse 코치는 원래 이 수준"이라고 학습하고 이탈한다. P1(근거와 결론이 모순)과 P8(어떤 엔진이 답했는지 투명성)을 위반한다. U10.
- 개선안:
  1. **엔진 상태를 1급 UI로 드러낸다.** Coach 홈 상단과 대화 입력창 위에 상태 배지를 둔다. `AI 코치 연결됨 (Gemini)` / `AI 연결 실패 — 기본 규칙 답변으로 대체 중 · 원인 보기 ›`. 원인 시트에는 provider별 마지막 오류(404/429/키 없음)와 시각, ☰ Data → 설정 → AI 링크를 둔다. 폴백이 일어난 답변에는 말풍선 상단에 amber 띠 "AI 연결 실패로 기본 규칙 답변입니다"를 붙인다(11px 회색 라벨 대신).
  2. **규칙 응답의 역할을 좁힌다.** 규칙 엔진은 질문 이해를 흉내 내지 않는다. Today 브리핑과 **같은 판정 함수**(권고 문장·근거)를 재사용해 "오늘 상태 요약"만 돌려준다. 이해하지 못한 질문에는 "지금은 AI가 연결되지 않아 이 질문에 답할 수 없어요. 오늘 상태 요약은 아래와 같아요"라고 정직하게 말한다. 등급 코드 매핑(`excellent/good/moderate/poor`)은 데이터 전문가 검토 항목으로 넘긴다.
  3. v2에 없는 목적지("훈련 탭", "설정 > AI")를 가리키는 문구를 모두 v2 경로 링크로 바꾼다(목표 등록 → `/v2/coach/plan/new`).
  4. 운영 쪽: 폴백 발생률을 헬스 체크에 넣고, 연속 실패 N회면 동기화 상태 시트에 경고를 띄운다.

### [치명] F-UX-02 근거 칩이 답변의 근거가 아니고, 칩 값과 드릴 값이 다르며, 드릴은 막다른 곳이다
- 현상: 9/25 "오늘 훈련 조언" 답변에는 `42km 목표 D-58`, `레이스 아침 TSB +25 (테이퍼 시)`, `TSB -11 (피로 누적)`, `UTRS 75 (양호)` 칩이 붙어 있다. 본문은 "TSB -10.7 — 피로 축적"과 "피로 회복이 필요"를 말하는데, `UTRS 75 (양호)` 칩은 그 결론과 반대 신호다. 레이스 칩 2개는 질문과 관계가 없다. `TSB -11` 칩을 누르면 "Training Stress Balance **-3.3** RunPulse · formula_v1"만 있는 시트가 뜬다. 그날 이후 활동이 반영되며 값이 재계산된 것으로 보이지만(추정), 화면에는 "당시 값/현재 값" 구분이 없다. D-58 칩과 레이스 아침 칩은 `drill: null`이라 누를 수 없는데, 모양은 누를 수 있는 칩과 같다.
- 근거: `src/services/coach_service.py:27-33`(`build_evidence` = `get_today_briefing(conn)["evidence"][:5]`, 질문·답변 내용과 무관), `:104-107`. `GET /api/v1/library/metrics/tsb?scope_type=daily&scope_id=2026-09-25` → `value: -3.3, children: [], inputs: []`(확인). 스레드 4 메시지 14의 evidence(확인). `coach-thread-evidence-desktop.png`. `interact-*.json` "Coach thread: 근거 칩 TSB" → IN_PAGE_CHANGE 38~39ms(반응은 빠름).
- 왜 문제인가: P1 Evidence-First는 "결론 옆에 그 결론의 근거"를 요구한다. 지금 칩은 "그 시각 Today에 있던 숫자"일 뿐이다. 러너가 칩을 눌러 검증하려는 순간 숫자가 달라지면(−11 → −3.3) 코치 전체의 신뢰가 무너진다. P2(원천까지 3단)도 1단에서 끝난다. U4, U6.

  1. **근거는 답변이 실제로 쓴 입력에서 만든다.** AI 경로에서는 tool call 결과(`call_with_tools`가 조회한 메트릭·활동)를 evidence로 저장한다. 규칙 경로에서는 분기에 쓴 값(`tsb`, `grade`, `plan_today`)만 저장한다. 본문에 나온 숫자는 반드시 칩으로도 존재해야 하고, 칩에 있는 숫자는 반드시 본문 판단에 쓰였어야 한다.

  4. 목적지가 없는 칩은 칩 모양을 쓰지 않는다(Today F-UX-03과 같은 규칙).

### [치명] F-UX-03 Today·활동에서 맥락을 가지고 Coach에 올 수 없다
- 현상: Today 권고 카드의 "Coach에게 더 묻기 →"는 `/v2/coach` 홈으로만 간다. 권고 문장, 근거 칩, 오늘 날짜 중 어느 것도 넘어가지 않아 사용자가 질문을 처음부터 다시 써야 한다. 활동 상세(`/v2/library/:id`)에는 Coach 진입점이 없다. "이 인터벌 어땠어?"라는 가장 자연스러운 질문을 하려면 Coach 탭으로 가서 날짜·이름을 직접 타이핑해야 하고, 규칙 엔진은 그 활동을 식별하지도 못한다(추정).
- 근거: `routes/today/+page.svelte:116`(`href: ${base}/coach`), `grep -rn coach routes/library` 0건, `routes/coach/+page.ts`(URL 파라미터를 읽지 않음), `lib/api/coach.ts` `createThread(initialMessage)`(맥락 필드 없음). `interact-*.json` "tab Coach→Today" 744/734ms.
- 왜 문제인가: P4(영역 이동 시 컨텍스트 유지)를 위반하고 U8 흐름이 끊긴다. 질문이 가장 강하게 생기는 순간(권고를 읽은 직후, 활동을 본 직후)에 재입력 비용을 물린다. WHOOP Coach는 Recovery·Strain 화면에서 "Ask Coach"로 해당 지표 맥락을 들고 대화를 연다. TrainingPeaks는 워크아웃마다 코멘트 스레드가 붙어 있다. RunPulse의 차별점인 "근거 달린 코칭"이 정확히 이 연결에서 나와야 한다.
- 개선안:
  1. **맥락 첨부 API**: `POST /coach/threads { initial_message, context: { kind: 'today'|'activity'|'metric'|'session', ref: '2026-09-27'|17414|'tsb'|'plan/1/2026-09-28' } }`. 서버가 맥락을 프롬프트와 evidence에 넣고, 스레드에 `context_kind/ref`를 저장한다.
  2. **진입점**: Today 권고 → `/v2/coach/new?ctx=today:2026-09-27`. 활동 상세 헤더 → `Coach에게 이 러닝 묻기`(`ctx=activity:17414`). 분해 시트 푸터 → `이 지표 Coach에게 묻기`(`ctx=metric:tsb:2026-09-27`). 세션 상세 → `이 세션 조정 상의`.
  3. **새 대화 화면**: 상단에 맥락 카드(예: `9/27 러닝 9.3km · 55:18 · 계획 대비 92%`, 탭하면 원래 화면으로)를 두고, 맥락별 추천 질문 3개(활동: "페이스 배분 괜찮았어?", "심박이 왜 높았지?", "다음 세션에 반영할 점")를 보여준다. 칩을 탭하면 **즉시 전송**한다.

- 현상: 후속 칩은 `evidence[].metric`만 보고 고정 문장을 고른다. evidence가 항상 Today 근거이므로 거의 모든 답변 아래에 "왜 테이퍼하면 폼이 올라가?", "이 폼이면 이번 주엔 뭘 하면 돼?", "남은 기간 주차별로 어떻게 준비할까?"가 똑같이 뜬다. 칩을 누르면 편집 없이 바로 전송된다(1탭 전송 자체는 좋음). 그런데 F-UX-01처럼 규칙 엔진은 이 질문들을 제대로 분기하지 못한다(추정).
- 근거: `lib/coachSuggestions.ts` `followUps()`, `routes/coach/[threadId]/+page.svelte:156-169`.
- 개선안: 후속 질문을 답변과 함께 서버가 생성해 저장한다(`suggested_followups`). 규칙 경로에서는 규칙 엔진이 **실제로 답할 수 있는 질문만** 제안한다. 이미 물어본 질문은 제외한다.

### [개선] F-UX-12 외부 LLM 전송 범위 고지 없음 (P8)

### [개선] F-UX-13 경쟁 앱 대비 — Coach가 "묻는 곳"에 그치고 행동으로 이어지지 않는다
- 비교(공개 제품 기준 일반 지식):

- 대화 화면 전환이 빠르다(스레드 열기 152/170ms, 근거 칩 38~39ms, 페이지 FCP 0.45~0.5s — `02-performance.md`).
- 대화 화면 입력창이 탭바 바로 위에 고정되어 있고(`sticky bottom-14`), Enter 전송·Shift+Enter 줄바꿈 규칙이 명확하다. 전송 중에는 중복 전송이 막힌다.
- 대화 화면의 낙관적 사용자 말풍선과 "답변 생성 중…" 자리 표시는 올바른 출발점이다(실패 롤백만 보강하면 됨).
- 같은 제목의 스레드에 날짜를 붙이는 `threadTitles`, 7일 지난 대화에 "당시 기준"을 붙이는 `staleLabel`처럼 시간 맥락을 의식한 장치가 이미 있다(기준만 조정하면 됨).

- 어시스턴트 마크다운을 `{@html}` 없이 토큰 렌더링한다(`ChatBody.svelte`). 안전하다.

## 채점 (0~10)
- **비전 부합 3**: "근거 옆 코칭"의 틀(칩·드릴)은 있지만, 칩이 답변 근거가 아니고 결론과 모순된다. 맥락 전달·행동 연결이 없다.
- **정보 정확성 2**: 회복 등급 매핑 오류로 권고 방향이 항상 휴식 쪽이다. 칩 -11 vs 시트 -3.3, 원시 소수, 없는 탭 안내가 있다.
- **시각 품질 5**: 말풍선·칩 구조는 깔끔하다. 이모지가 □로 깨지고, 규칙 폴백 라벨이 묻히며, 드릴 시트가 대화를 가린다.
- **상호작용 반응성 5**: 탐색 반응은 좋다(≤170ms). 전송 대기는 스트리밍·취소·타임아웃이 없고, 새 대화는 사용자 말풍선도 없다(추정).
- **흐름 3**: Today·활동 → Coach 맥락 전달이 없다. 근거 드릴이 막다른 곳이다. 스레드를 구분·관리할 수 없다. 주제 칩이 2단계다.
- **혁신성 2**: 현재 사용자 경험은 키워드 템플릿 챗봇이다. 경쟁 앱(WHOOP Coach·Runna) 대비 대화 품질·계획 연결 모두 뒤처진다.

## 최우선 개선 3개
1. **엔진 복구 + 폴백 투명화 + 규칙 응답 정직화(F-UX-01)**: provider 404를 해결하고, 폴백 상태 배지·원인 시트를 둔다. 규칙 경로는 Today와 같은 판정 함수만 재사용한다(회복 등급 매핑 수정 포함). 이것 없이는 나머지 개선이 의미 없다.
2. **답변에 묶인 근거(F-UX-02)**: 답변이 실제로 사용한 입력만 evidence로 저장하고, 당시 값/현재 값을 병기한다. 시트는 4블록 골격(의미 → 공식 → 원천 활동 → Library)으로 막다른 곳을 없앤다.
3. **맥락 첨부 진입 + 즉시 피드백 대화(F-UX-03·04·07)**: `context` 필드가 있는 스레드 생성, Today·활동·분해 시트·세션의 "Coach에게 묻기", 칩 1탭 즉시 전송, 먼저 이동하고 스트리밍으로 응답 받기, 실패 말풍선 재시도.
