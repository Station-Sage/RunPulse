# Today — UX(사용자 경험·흐름) 리뷰

**리뷰일**: 2026-09-27 · **대상**: `/v2/today` + Today에서 나가는 경로 + v2 기본 진입 전환 조건
**범위 메모**: v1은 폐기 대상으로 확정되었으므로 진입 경험은 "v2를 기본 진입으로 바꿀 때 무엇이 빠져 있나" 관점으로만 다룬다.

요약:
- **"왜 이 숫자인가" 경로가 2탭 만에 막다른 곳에 닿는다.** 근거 칩 `TSB -14`와 UTRS 분해 안의 "Training Stress Balance ›"를 누르면 값 하나(`-14.4 RunPulse · formula_v1`)만 있는 빈 시트가 뜬다(API children/inputs 모두 빈 배열 — 확인). 분해 시트에서는 원천(활동·날짜·Library 메트릭 상세)으로 이어지는 링크가 하나도 없다. 그런데도 페이지 하단에는 "거기서 다시 원본 데이터로 이어집니다"라고 적혀 있다.
- **누를 것처럼 보이는 요소 절반이 반응하지 않는다.** 최근 활동 3행(설계 목업에는 `→`가 있었음), 예측 기록 3:40:23, 마일스톤 행, 근거 칩 7개 중 4개, 준수율 점, 예측 추이 차트가 그렇다. 버튼 칩과 비대화형 칩은 모양이 똑같다.
- **모바일에서는 "오늘 뭘 할까"가 네 번째 화면에 있다.** 첫 화면은 레이스 예측 비교표가 차지하고, 다음 세션은 차트·마일스톤 아래(`order-4`)로 밀려 있다. 오늘 세션을 이미 끝낸 상태(9.3km, completed=1)인데도 권고는 "오늘은 가볍게 가세요"라고 말한다. 하루 루프가 닫히지 않는다.
- **로딩 중에는 피드백이 없고, 드릴다운은 URL과 뒤로가기에 묶여 있지 않다.** 처음 들어오면 1.25초간 빈 화면이고, 다른 탭에서 돌아오면 0.75초간 이전 화면에 멈춰 있다. 시트를 연 상태에서 브라우저 뒤로가기를 누르면 Today 자체를 떠난다. 드릴 스택에 "←"가 없다.
- **v2를 기본 진입으로 바꾸기에는 ☰가 비어 있다.** 동기화 시각, 소스 연결, 설정이 없어서 데이터가 없는 상태의 안내("소스를 연결하면…")도 누를 곳이 없는 막다른 곳이다.

## 발견

### [치명] F-UX-01 "왜?" 드릴다운이 2탭 만에 빈 시트로 끝나고, D3(원본)로 가는 경로가 전혀 없다
- 현상: 권고 카드의 근거 칩 `TSB -14 (피로 누적)`를 누르면 하단 시트에 `-14.4 RunPulse · formula_v1`만 있고 그 밖에는 아무것도 없다. UTRS 링 → 입력 메트릭 "Training Stress Balance -14.4 ›"(화살표가 있어 더 들어갈 수 있다고 약속함)를 눌러도 같은 빈 시트다. UTRS·CIRS 시트에도 활동·날짜·Library로 가는 링크가 없다. 페이지 하단 문구는 "위 지표는 탭 한 번으로 계산 분해에 닿고, 거기서 다시 원본 데이터로 이어집니다"이다.
- 근거: `today-evidence-chip-desktop.png`(빈 TSB 시트), `today-utrs-click-desktop.png`. API `GET /api/v1/library/metrics/tsb?scope_type=daily&scope_id=2026-09-27` → `children: [], inputs: []`, `ctl` → children `CTL 증가율` 1개, inputs 0개(확인). `MetricBreakdown.svelte:191-229`는 children/inputs만 렌더하고 링크 요소가 없다. `+page.svelte:302-304`의 약속 문구.
- 왜 문제인가: P2(최대 3단으로 원천까지)와 P1을 정면으로 위반한다. 러너가 가장 먼저 묻는 "왜 피로 누적이라는 거지?"에 대해 TSB가 CTL−ATL이라는 설명도, 최근 부하를 만든 활동도 보여주지 못한다. 약속 문구 때문에 신뢰도 추가로 깎인다. U6, U8.
- 개선안(설계):
  - **분해 시트 공통 골격**을 4블록으로 고정한다. ① 의미 한 줄("최근 1주 피로가 6주 체력보다 15 높아요 — 강훈련 직후엔 정상 범위") ② 공식·기여도(TSB = CTL 73.8 − ATL 88.2, 각 항은 탭 가능한 행) ③ 원천(ATL을 가장 많이 올린 최근 7일 활동 Top 3 — 날짜·이름·TRIMP, 행 탭 → `/v2/library/:id`) ④ 푸터 링크 `추이·전체 설명 보기 → /v2/library/metrics/tsb?period=3m`.
  - 빈 분해(children·inputs 0)는 UI에서 절대 빈 채로 두지 않는다. 최소한 ①+④를 보여주고, 서버가 입력을 주지 않는 합성 메트릭(TSB/ATL/CTL)에는 공식 기반 입력을 채운다.
  - 약속 문구는 실제 동작이 맞춰질 때까지 "Library에서 전체 탐색 →" 한 줄로 줄인다.

### [치명] F-UX-02 최근 활동 행이 링크가 아니다 — 가장 흔한 "어제 뛴 거 보기" 과업이 막혀 있다
- 현상: 오늘/어제/2일 전 3행이 카드 안의 목록 행처럼 보이고(경로 썸네일, 거리, 시간, 배지) hover 배경도 없다. 클릭해도 무반응이다. 설계 목업(`03a-today.md:61-66`)에는 각 행 끝에 `→`가 있었다.
- 근거: `+page.svelte:192-206` — `<div class="flex …">`이고 `<a>`나 onclick이 없다. API `recent_activities[].id` = 17414 등으로 id가 이미 들어 있다(확인). `interact-desktop.json`/`interact-mobile.json` "Today: 최근 활동 행(러닝) 클릭" → `NO_VISIBLE_REACTION`.
- 왜 문제인가: U4, P2, U8. 러너가 Today를 여는 가장 흔한 두 번째 이유는 "방금 뛴 러닝이 어땠나"다. 지금은 Library 탭 → (1.3초 멈춤) → 최근 활동 행으로 3동작 + 1.3초가 필요하다.
- 개선안: 행 전체를 `<a href="{base}/library/{act.id}">`로 감싸고 우측에 `›`를 붙인다. 터치 타깃은 최소 44px로 하고 hover/active 배경을 준다. 행 아래 "활동 전체 →"(`/v2/library/activities`)를 둔다. 오늘 활동 행에는 계획 매칭 결과 라벨(`계획 대비 92% · 초과`)을 같이 보여 ①번 과업의 루프를 닫는다(F-UX-04).

### [치명] F-UX-03 근거 칩 7개 중 4개가 가짜 칩 — 버튼과 비대화형 span의 모양이 똑같다

### [치명] F-UX-04 "오늘 뭘 할까"가 오늘 이미 달린 사실을 모르고, 모바일에서는 네 번째 화면에 있다
- 현상: 오늘 9.3km(55:18)를 이미 완료했고 계획 매칭은 `completed=1, outcome_label=overperformed, compliance 92.3%`이다. 그런데 권고는 "오늘은 가볍게 가세요"이고, 다음 세션 카드는 내일(4.6km 이지런)만 보여준다. 오늘 세션이 끝났다는 확인이 Today 어디에도 없다. 모바일에서는 레이스 허브(약 630px)가 첫 화면을 차지하고, "다음 세션"은 `order-4`라서 차트·마일스톤·월간 이야기 아래에 있다(`today-mobile.png` 기준 전체 높이의 약 82% 지점).
- 근거: `/api/v1/coach/plan/active` workouts id 153(2026-09-27, completed 1, 92.3%) 확인. `/api/v1/today` `briefing.headline` 확인. `+page.svelte:138`(`order-4`), `today-mobile.png`.
- 왜 문제인가: L0의 목적(03a "30초 안에 오늘 무엇을")과 맥락 적응 원칙에 어긋난다. 이미 달린 러너에게 "가볍게 가라"는 말은 코치가 나를 보고 있지 않다는 신호다. Runna/Garmin은 완료 즉시 "오늘 완료 ✓ + 내일 예고"로 전환한다. U8.
- 개선안(**Today 히어로 상태 기계**):
  - `pre`(오늘 세션 미완료): "오늘: 쉬운 달리기 4.6km · 6:21~6:45/km · Z2" + [세션 상세] + 상태 조정 배지.
  - `done`(오늘 활동이 계획에 매칭됨): "오늘 완료 ✓ 9.3km · 계획 대비 초과(92%)" + 활동 링크 + 한 줄 해석("쉬운 날치고 길었어요 — 내일은 짧게") + 내일 예고.
  - `rest`(휴식일): 회복 행동 1개(수면 목표 등).
  - 모바일 배치 순서는 **권고/오늘 세션 → 컨디션 입력 → 점수 링 → 레이스 허브(요약 1줄: `D-56 · 예측 3:40 · 목표 대비 −21분 ›`) → 최근 활동 → 흐름**으로 바꾼다. 레이스 허브 전체 비교표는 요약 1줄을 탭하면 열리게 한다. 데스크톱은 현재 2열을 유지하되 좌열 최상단을 오늘 세션 히어로로 한다.

### [중요] F-UX-05 예측 기록·예측 추이 차트는 누를 수도 읽을 수도 없고, 방향이 반대다
- 현상: 가장 큰 숫자인 `3:40:23`은 클릭해도 무반응이다. "예측 추이 · 근거 · 레이스 아침 폼 보기 ▾"를 펼치면 예측 근거(존 표) → **대회 기록 확인 13행** → 예측 추이 차트 순서로 나온다. 차트는 `interactive={false}`라 값을 확인할 수 없고, 시간이 3:47→3:40으로 줄면 선이 내려가 실력이 떨어지는 것처럼 보인다.
- 근거: `RaceHub.svelte:127-130`(span), `RaceHub.svelte:158-171`(details 내부 순서, `interactive={false}`), `today-prediction-expanded-desktop.png`(y축 3:47:24 위 / 3:40:03 아래), `interact-*.json` "예측 기록 3:40:23 클릭" → `NO_VISIBLE_REACTION`.
- 왜 문제인가: 사용자가 직접 지적한 U2·U1·U4. ②번 과업의 "나아지고 있나?"를 차트가 오히려 반대로 전달한다. 모바일 상단의 레이스 허브가 페이지 전체를 지배하면서도 정작 탭할 수 없다.
- 개선안: ① `3:40:23`(과 목표 격차 문구)을 탭하면 **예측 상세 시트(D2)**를 연다. 시트 구성: 90일 추이 차트(y축 반전, "빨라짐 ↑" 축 라벨, 탭하면 날짜·값 툴팁) → 근거 비중 막대(대회/품질세트/심박-속도 각 %) → 기여 대회 목록(각 행 → 활동) → 푸터 `메트릭 상세 → /v2/library/metrics/<marathon_prediction slug>`. ② 대회 기록 확인(쓰기 동작)은 추이 안에서 빼서 별도 항목으로 옮긴다(F-UX-09). ③ 인라인 미니 추이(72px)는 허브에 항상 보이게 두고 `-7분(90일)` 같은 변화 요약 라벨을 붙인다.

### [중요] F-UX-06 드릴다운 패턴이 설계(D2 = 데스크톱 우측 패널/모바일 풀스크린)와 다르고, 스택·뒤로가기·URL이 없다

### [개선] F-UX-15 지표 설명·의미가 필요한 순간에 없다

### [개선] F-UX-16 "매일 열고 싶은" 이유가 약하다 — 경쟁 앱 대비 signature moment 제안
- 현상: 날마다 바뀌는 요소가 권고 한 문장과 링 3개 숫자뿐이다. 어제 대비 변화(링 델타), 아침 브리핑 순서, 하루 루프(입력 → 권고 갱신 → 달리기 → 결과 해석)가 없다.
- 근거: `today-desktop.png`, `ScoreRing.svelte`(델타 표시 없음).
- 비교: WHOOP 홈은 Recovery 링 + 전일 대비 + 기여 요인 3개(HRV·RHR·수면을 개인 기준선 대비로)를 보여준다. Oura Readiness는 요인별 "Optimal/Pay attention" 막대를 준다. Garmin Morning Report는 기상 직후 수면→HRV→준비도→오늘 추천 워크아웃을 한 흐름으로 보여준다. Runna는 오늘 세션 구조를 히어로로 두고 완료를 표시한다.
- 개선안(RunPulse만의 순간): ① **"근거가 달린 아침 브리핑"**: 첫 방문 시 권고 1문장 + 개인 기준선 대비 변화 3개(`HRV 평소보다 −8%`, `수면 66 (−9)`, `TSB −14`)를 각각 분해 시트로 탭할 수 있게 하고, 4소스 중 어느 기기 값인지 배지를 붙인다. ② **"레이스까지 남은 거리" 진행 막대**: 예측이 목표에 다가온 정도(21분 → 목표)를 주 단위로 쌓아 보여주고, 이번 주 무엇이 예측을 바꿨는지(대회 1건, 품질세트 +2) 설명한다. ③ **링 델타**(`59 ↓4 vs 어제`) + 어제 권고를 지켰는지 한 줄 회고.
