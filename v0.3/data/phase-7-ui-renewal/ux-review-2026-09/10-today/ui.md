# Today — UI(시각·인터페이스) 리뷰

요약:
1. **"차트 숫자를 확인할 수 없다"는 모바일에서 재현(확인)된다.** 폼 차트는 손가락을 떼는 순간 판독값이 오늘 값으로 되돌아가고, 커서 근처 툴팁·점 마커가 없다. y축은 "148"(패딩된 최댓값)과 "0" 두 개뿐이고, 예측 추이 차트와 테이퍼 차트는 아예 `interactive={false}`다.
2. **예측 추이 차트의 방향이 반대다(확인).** 시간 값을 그대로 그려서 3:47→3:40으로 **좋아지는 구간이 선이 떨어지는 모습**으로 보인다. 축 라벨도 데이터 값이 아니라 패딩된 경계값(3:47:24 / 3:40:03)이다.
3. **시각 위계가 "오늘 무엇을 할까"가 아니라 "레이스 예측 표"를 향한다.** 모바일 첫 화면(390×844)은 레이스 허브 하나로 가득 차고, 오늘 권고 문장은 탭바에 걸려 잘린다. 점수 링·다음 세션은 첫 화면에 없다. 모바일에서 "내일 세션"은 페이지 거의 맨 끝(약 4,500px 위치)에 있다.
4. **디자인 시스템이 코드상으로만 있다.** Inter는 선언되지 않았고 JetBrains Mono는 로드되지 않는다(document.fonts 0개). 텍스트 요소의 82%가 12px 이하이고, 보조 글자색(#64748b)은 카드 배경에서 대비 3.07:1로 AA에 미달한다. 근거 칩은 button과 span이 똑같이 보이고, 이모지를 아이콘으로 쓰고 있으며, 미정의 토큰(`--color-accent`) 때문에 월간 CTL 스파크라인이 보이지 않는다.
5. 계산 분해 시트는 원시 DB 라벨("UTRS 구성요소 - TSB 정규화값 (parent: utrs)")을 1280px 폭 전체에 평평하게 나열할 뿐이다. 가중치·기여도 시각화가 없고, TSB 시트는 숫자 하나만 보여 준다.

## 발견

### [치명] F-UI-01 모바일에서 차트 값을 읽을 수 없음 — 손을 떼면 판독값이 사라지고, 툴팁·마커·y 눈금이 없음
- 현상: 모바일에서 폼 차트를 탭하면 헤더 판독값은 손가락을 누르고 있는 동안만 바뀐다(`2026-08-12 · CTL 47.5 …`). 손을 떼면 즉시 `2026-09-27 … TSB -14.4`로 되돌아간다. 판독값은 차트 위 헤더에만 있고 커서 위치에는 점도 값 라벨도 없다. 모바일에서는 헤더 판독값이 2줄로 줄바꿈된다. y축은 위 패널 "148"(max×1.08, 실제 값이 아님), 아래 패널 "0"뿐이라 TSB가 -30인지 -15인지 눈으로 읽을 수 없다.
- 근거: Playwright 터치 실측(스크래치 `ui_probe.mjs`): tap 후 "after tap (finger up): 2026-09-27 … -14.4", 누르는 동안 "2026-08-12 …", 뗀 뒤 "2026-09-27 …"로 되돌아감. 스크린샷 `screenshots/today-extra-chart-press-mobile.png`. 코드 `FormChart.svelte:112-115`(`onpointerleave`/`pointercancel`에서 `frac=null`; 터치는 pointerup 직후 pointerleave가 발생함), `FormChart.svelte:125,144`(y 라벨 2개), `formChart.ts:220`(topMax=max×1.08). 기존 측정 `interact-mobile.json` "폼 차트 클릭: ERROR".
- 왜 문제인가: 사용자가 원문으로 지적한 U1을 그대로 재현한다. P2(Drillable) 위반이다. 러너가 "지난주 TSB 최저가 얼마였지?"를 확인할 방법이 없다.
- 개선안(차트 공통 사양 `ChartScrub`으로 FormChart와 TrendChart 통일):
  - **탭 = 고정(sticky) 선택**: pointerup 뒤에도 frac을 유지한다. 차트 밖을 탭하거나 선택 칩의 ×를 누르면 해제한다. 데스크톱은 hover로 미리보기, click으로 고정.
  - **커서 툴팁**: 커서 x 위치의 각 시리즈에 반지름 4px 점과 surface-3 배경의 툴팁 박스(날짜 `9/12(금)`, `체력 70.9 · 피로 70.1 · 폼 +0.8`)를 띄운다. 가장자리에 닿으면 좌우를 뒤집고, 손가락에 가리지 않게 차트 상단 12px 안쪽에 둔다. 헤더 판독값은 유지하되 줄바꿈 없이 고정 높이 1줄로 두고, 모바일에서는 약어 `CTL 70.9 · ATL 70.1 · TSB +0.8`로 줄인다.
  - **y 눈금**: 위 패널은 0/25/50/75/100(nice ticks 3~5개)을 오른쪽에 붙인 라벨(10px mono는 제외하고 11px sans, fg-secondary)로 표시한다. 아래 패널은 -30/-15/0/+15/+30이다. 패딩 경계값은 눈금으로 쓰지 않는다.
  - **x 눈금**: 월 경계마다 `7월 8월 9월 10월 11월`처럼 짧은 라벨을 쓴다(ISO 전체 날짜는 쓰지 않음).
  - 키보드: 차트에 `tabindex=0`을 주고 ←/→로 하루씩 이동한다(접근성).
  - 참고: Garmin Connect 차트는 길게 눌러 스크럽하고 손을 떼도 값이 유지된다. WHOOP은 탭한 지점을 고정한다.

### [치명] F-UI-02 예측 기록 추이 차트의 방향이 반대 + 축 값이 패딩 경계 + 상호작용 없음
- 현상: "예측 기록 추이 · 최근 90일" 차트에서 최근 구간이 3:47→3:40으로 **좋아졌는데도 선이 아래로 떨어진다**. 축 라벨은 `3:47:24`(위)와 `3:40:03`(아래)인데 둘 다 실제 데이터 값이 아닌 ±5% 패딩값이다. 높이 72px에 스크럽도 없다.
- 근거: `today-prediction-expanded-desktop.png`(좌측 약 y=1220~1280 구간), 코드 `RaceHub.svelte:106-111`(`interactive={false}`, 시간 초를 그대로 전달), `TrendChart.svelte:290`(y는 항상 큰 값이 위), `trendChart.ts:427-429`(패딩).
- 왜 문제인가: U2 치명. 러너는 "선이 내려가면 나빠짐"으로 읽는다. 정보 반전으로 인한 오판이다.
- 개선안: `TrendChart`에 `invert?: boolean`(낮을수록 좋음)을 추가해 `py = ((v-min)/(max-min))*h`로 뒤집는다. 축 라벨에는 "빠름 ↑" 캡션(10px 대신 11px, fg-secondary)을 붙인다. 목표 3:19:00은 수평 점선으로 표시하고(`목표 3:19` 라벨) 목표선과의 거리가 한눈에 보이게 한다. 추이선 오른쪽 끝에 현재값 `3:40:23` 인라인 라벨과 기간 변화 `90일 −7:01` 배지(teal)를 붙인다. y 눈금은 5분 단위 nice tick(3:35/3:40/3:45/3:50)으로 한다. 높이는 120px 이상으로 하고 `interactive`를 켠다. 80% 범위는 옅은 밴드(fill-opacity .12)로 겹쳐 불확실성도 시각화한다. 같은 규칙을 페이스 차트 전역에 적용한다(Runna·Strava의 페이스 축은 위가 빠름).

### [치명] F-UI-03 계산 분해 시트가 원시 라벨을 평평하게 나열하고, 값 포맷도 없음
- 현상: UTRS 링을 누르면 영어 제목 "Unified Training Readiness Score", 값 `59.4`, 행 5개("UTRS 구성요소 - TSB 정규화값 (parent: utrs)" … 26/76/84/52/75)가 나온다. 가중치·기여도·방향(높을수록 좋음?)·색이 없다. TSB 칩·링을 누르면 `-14.4 RunPulse · formula_v1`만 있고 본문은 비어 있다. 데스크톱에서는 시트가 1280px 폭 전체(사이드바 포함)를 덮어 라벨과 값 사이가 1,200px 이상 떨어진다.
- 근거: `today-utrs-click-desktop.png`, `today-utrs-click-mobile.png`, `today-evidence-chip-desktop.png`. 코드 `MetricBreakdown.svelte:74,90-93,106`(value를 그대로 출력하고 `formatUnitValue` 미사용), `:52`(`inset-x-0` 전체 폭).
- 왜 문제인가: U6("단순 나열") 원문 지적의 재현이자 U5 위반이다. 값 포맷이 없으므로 `sec` 단위 메트릭(예: `race_pred_marathon_sec`=13307)이 이 시트로 열리면 원시 초가 그대로 나온다(코드 확인, Today에서의 실제 노출은 추정). 이는 U3 원문 지적("1800초")의 구조적 원인이다.
- 개선안: **Contribution Waterfall** 컴포넌트로 교체한다.
  - 헤더: 한국어 이름 + 한 줄 의미("오늘 훈련을 받아들일 준비도 · 높을수록 좋음"), 큰 값 `59` + 등급 칩(보통) + 0~100 등급 5색 스케일 바에 현재 위치 마커.
  - 구성요소 행: `수면 52 ×가중치 0.25 = 13.0` 형태로 **가로 막대**(길이=기여 점수, 색=구성요소의 등급색)를 가중치 내림차순으로 정렬한다. 가장 끌어내린 요소에 "가장 큰 감점 요인" 태그를 단다. 라벨은 "(parent: utrs)" 같은 내부 표기를 제거한 사람용 라벨로 쓴다.
  - 공식 줄: `UTRS = 0.3·TSB + 0.25·수면 + …`(mono 12px, fg-secondary)와 버전·계산 시각.
  - 모든 값을 `formatUnitValue`에 통과시킨다(sec→h:mm:ss, sec/km→m:ss/km).
  - 레이아웃: 데스크톱은 **우측 사이드 패널**(폭 420px, 높이 100%)로 본문 옆에 열어 비교를 유지한다. 모바일은 현재 하단 시트를 유지하되 드래그 핸들과 스냅 50%/90%를 둔다.
  - TSB처럼 children이 없는 메트릭은 "CTL 73.8 − ATL 88.2 = −14.4" 산식과 14일 미니 추이, 좋은 범위 밴드를 보여 준다.

### [중요] F-UI-04 첫 화면 위계: 오늘의 행동이 첫 뷰포트에 없음(모바일), 레이스 표가 권고를 밀어냄
- 현상: 모바일 첫 화면 844px는 D-56 헤더, 예측 3종 표, 각주 2줄, `<details>` 3개로 채워진다. 권고 문장 "레이스까지 56일 — …가볍게 가세요"는 y≈660부터 시작해 탭바에 가려 잘린다. 링 3개, 최근 활동, 다음 세션은 첫 화면 밖이다. 데스크톱은 좌측 열 첫 화면의 약 70%가 레이스 허브이고, 권고 카드는 y≈610 아래에 있다. 권고는 본문 16px로 히어로 수치(36px/24px)보다 위계가 낮다.
- 근거: `today-extra-firstview-mobile.png`(첫 뷰포트만 캡처), `today-desktop.png`, 코드 `today/+page.svelte:196-209`(RaceHub → RecommendationCard 순), `RaceHub.svelte:54,68`.
- 왜 문제인가: 03a L0 원칙(핵심 메시지 1~2개, 의미 먼저)과 P4(3초 안에 무엇을 할지)를 위반한다. 3초 안에 보이는 것은 "예측 기록 비교 표"이지 "오늘 무엇을 할까"가 아니다.
- 개선안: L0를 **Today Hero** 한 블록으로 재구성한다.
  - 1행: 권고 헤드라인 20px/semibold("오늘은 가볍게 — 쉬운 4.6km"), 그 아래 근거 칩 2~3개.
  - 2행: 링 3개를 가로 한 줄 소형(48px)으로 두고, 오른쪽에 "내일: 쉬운 달리기 4.6km" 세션 칩.
  - 3행: 레이스 요약 1줄 `D-56 · 예측 3:40:23 → 목표 3:19 (−21:23)`에 진행 게이지를 붙이고, 탭하면 레이스 허브 전체를 펼친다.
  - 예측 3종 비교 표, 각주, 근거 `<details>`는 "레이스" 확장 영역(L1)으로 내린다.
  - 모바일 첫 뷰포트(탭바 64px 제외 약 700px)에 Hero 전체가 들어가게 한다.
  - 참고: WHOOP·Oura는 첫 화면에 점수 1~3개 + 한 문장 코칭만 둔다. Runna는 "오늘의 세션" 카드를 최상단에 둔다.

### [중요] F-UI-05 작은 글씨 남용 + 보조 글자색 대비 미달(WCAG AA 실패)
- 현상: 본문 텍스트 요소 234개 중 12px 97+73… 정확히는 11px 97개, 12px 73개, 10px 21개, 9px 1개로 **192개(82%)가 12px 이하**다. `text-fg-muted`(#64748b)를 surface-2(#1e293b) 카드 위에 쓸 때 대비는 **3.07:1**이다(AA 소형 텍스트 기준 4.5). 예측 근거, 80% 범위, 각주, 차트 축, 링 상태 라벨이 모두 이 조합이다.
- 근거: 실측(스크래치 `ui_probe.mjs` fontHist), 대비 계산(muted/s2 3.07, muted/s1 3.75, secondary/s2 5.71). 코드 `PredictionBasis.svelte:252-279`(전부 `text-[11px] text-fg-muted`), `PredictionCompare.svelte:175,200`, `FormChart.svelte:143`(9px).
- 왜 문제인가: 근거·불확실성은 P1 Evidence-First의 핵심인데 가장 읽기 어렵게 표시된다. 모바일 야외(밝은 햇빛)에서는 읽을 수 없다.
- 개선안: 타이포 스케일을 토큰으로 고정한다. `--text-caption:12px/16`(최소), `--text-body-sm:13px/18`, `--text-body:15px/22`, `--text-title:18px/24`, `--text-hero:32px/36`(mono tabular). 9~11px는 금지한다(예외는 축 눈금 11px뿐). `fg-muted`를 #7c8aa0(s2 대비 약 4.6)로 올리거나, 카드 위 보조 텍스트는 `fg-secondary`로 통일한다. 각주성 문단(예측 각주 2줄, 근거 7줄)은 "요약 1줄 + 펼치기"로 줄여 작은 글씨의 양 자체를 줄인다.

### [중요] F-UI-06 폰트 체계 미구현 — Inter 미선언, JetBrains Mono 미로드, 한글이 mono로 렌더됨
- 현상: body는 Tailwind 기본 시스템 스택(-apple-system…Noto Sans)이고 Inter는 어디에도 없다. `--font-mono:'JetBrains Mono'`는 선언만 있고 @font-face나 import가 없다(`document.fonts` 0개). 따라서 OS마다 ui-monospace가 달라진다. 근거 칩은 `font-mono`인데 한글 라벨("레이스 아침 TSB +24 (테이퍼 시)")이 모노 폴백으로 렌더되어 **자간이 벌어진 이질적 글꼴**이 된다.
- 근거: 실측 bodyFont/fontsLoaded=[]. `layout.css:25`, grep 결과 font-face 0건. `EvidenceQuote.svelte:34,40`. 스크린샷 `today-desktop.png` 칩 영역("4 2 k m 목 표"처럼 벌어짐).
- 왜 문제인가: P5(숫자는 모노스페이스 위계) 미준수이고 플랫폼 간 시각 일관성이 없다. 숫자 폭이 바뀌어 스크럽 판독값이 흔들린다(tabular-nums 미보장).
- 개선안: Inter Variable + JetBrains Mono(woff2, self-host, `font-display:swap`)를 로드하고 `--font-sans`를 정의한다. 숫자는 `font-variant-numeric: tabular-nums`를 전역 유틸 `.num`으로 둔다. **칩은 sans로 쓰고 숫자 부분만 `.num`**(예: `<span>레이스 아침 TSB</span> <b class="num">+24</b>`). 한글에는 mono를 쓰지 않는다.

## 잘된 점
- 레이스 허브의 3경로 예측 비교(Garmin / RunPulse 기기 심박 / 자체 추정 + 차이 %)는 경쟁 앱에 없는 **투명성 signature 요소**다. 표현만 정리하면 핵심 자산이다.

- 혁신성: 5 — 3경로 예측 비교와 레이스 투영 폼 차트는 차별점이지만 시각적 완성도가 WHOOP·Runna급 signature에 못 미친다.
