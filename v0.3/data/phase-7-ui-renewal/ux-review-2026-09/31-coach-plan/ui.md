# Coach · 계획 — UI(시각·인터페이스) 리뷰

**리뷰일**: 2026-09-27
**대상**: v2 `/v2/coach/plan/:id`(계획 상세, 실측 id=1 "42km 목표"), `/v2/coach/plan/:id/session/:date`(세션 상세 — 9/26 완료일, 9/28 다음 세션), `/v2/coach/plan/new`(새 계획 폼), `/v2/coach/plan/compare`(계획 비교 — 파라미터 없이 진입한 빈 화면)
**근거**: `screenshots/coach-plan-*.png`(desktop 1280 / mobile 390), `raw/coach-plan*.txt`, `raw/interact-{desktop,mobile}.json`, 코드 `frontend/src/routes/coach/plan/**`, API `GET /api/v1/coach/plan/1`, `/coach/plan/1/session/2026-09-2{5,6}`, `/coach/plan/templates`(읽기 전용)

요약:
1. **"계획 vs 실제"가 오른쪽 끝 한 단어 라벨로만 표현되고, 색이 결과와 반대인 경우도 있다.** API는 `actual_dist_km`, `compliance_pct`, `outcome_label`을 주지만 화면에는 실제 거리·페이스가 없다. 9/26 세션(46%, `underperformed`)은 **초록 `✓ 46%`**, 계획보다 20% 더 달린 9/25 세션은 amber `✓ 페이스 상이`로 나온다.
2. **세션 상세는 "원래 계획"만 보여 주는 막다른 화면이다.** 실제 수행, 매칭 활동 링크, 처방 근거(`rationale`), 목표 HR존이 모두 빠져 있다. 같은 날짜의 계획 행 2개(대체된 계획과 실제 수행)가 **같은 URL**로 연결되고, 대체된 계획에 "조정 없음 — 계획대로 진행"이 표시된다.
3. **주기(단계) 시각화가 없다.** 9주 계획에서 보이는 것은 "1주차 / 9주" 텍스트와 "이번 주" 목록뿐이다. 빌드/피크/테이퍼 구조, 주간 볼륨 추이, 다른 주로 이동할 수단이 없다. "현재 CTL" 막대는 근거 없는 0~100 스케일이다. v1에는 단계 타임라인이 있었다.
4. **계획 비교를 파라미터 없이 열면 SvelteKit 기본 오류 화면이 나온다.** "400 / 거리 정보가 없습니다."가 여백 0, 스타일 없음, 복귀 수단 없이 표시된다(`+error.svelte` 부재).
5. 폼·목록 컨트롤이 모바일 기준에 못 미친다. 터치 타깃은 거리 칩·시간 입력 약 34px, ACWR 행 약 20px, 저장 버튼 약 32px다. 날짜 입력은 `mm/dd/yyyy`(html lang="en")다. 단계 표기는 1/3에서 곧바로 3/3으로 건너뛴다. 보조 텍스트 대비는 3.75:1이고, 대체된 행은 1.87:1이다.

## 발견

### [치명] F-UI-01 주간 목록에서 계획 vs 실제가 보이지 않고, 상태 색이 결과와 반대로 표시됨
- 현상: 각 행은 `계획 유형 · 계획 거리 · 목표 페이스` + (오른쪽 끝) 상태 라벨 1개로 구성된다. 실제로 달린 거리·페이스·시간은 어느 행에도 없다.
  - 9/25 회복 6.9km 계획을 8.3km 달렸다(`dist_ratio 1.20`, `outcome_label: modified`, `compliance_pct 60`). 화면에는 amber `✓ 페이스 상이`만 나온다. 20% 초과 거리는 표시되지 않고, 60% 점수도 없다.
  - 9/26 Garmin 장거리는 `compliance_pct 46.4`, `outcome_label: underperformed`인데 화면에는 **초록 `✓ 46%`**로 나온다. 초록=성공 문법으로 미달을 표시한다.
  - 9/27 `overperformed`(92.3%)는 초록 `✓`만 나온다. 과수행과 정상 수행이 같은 모양이다.
  - Garmin/Intervals 출처 행(9/26 "장거리 / 장거리 달리기", 9/27 "쉬운 달리기 / 기초체력 양성")은 거리·페이스가 비어 있어 한 줄이 짧고, 계획 행과 형태가 다르다.
- 근거: `coach-plan-detail-desktop.png`, `coach-plan-detail-mobile.png`, `raw/coach-plan-detail.txt`. 코드 `[id]/+page.svelte:35-48`(`statusOf`는 `outcome_label === 'modified'`만 분기하고 나머지 완료는 모두 green, pct<85이면 숫자만 붙임). `:133-144`는 계획 값만 출력한다. API `GET /coach/plan/1`의 workouts[4..8] 응답에서 `actual_dist_km`/`outcome_label`/`source` 값을 확인했다.
- 왜 문제인가: 계획 화면의 핵심 질문은 "계획대로 했나, 얼마나 벗어났나"다. 미달을 초록 체크로 그리면 오판을 유도한다(심각도 정의 "틀린 표현"). P1(근거가 보이지 않음)과 U3(수치 부재) 위반이다. Runna·TrainingPeaks는 계획/실제를 한 행에 나란히 두고 준수도를 색으로 표시한다.
- 개선안: **PlanActualRow** 컴포넌트.
  - 1줄: `유형 칩`(색=강도 계열, 아래 F-UI-05) + 계획 `11.5km · 6:05–6:45/km`(fg-secondary 13px).
  - 2줄: 실제 `8.3km · 7:12/km · 58:40`(fg-primary 13px mono `.num`)과 **계획 대비 거리 막대**를 둔다. 막대는 폭 100%=계획 거리, 실제 채움이고, 100%를 넘는 부분은 다른 톤으로 이어 그린다. 막대 끝에 `120%` 라벨을 붙인다.
  - 상태 배지는 `outcome_label`을 그대로 매핑한다: `completed`=teal `완료`, `overperformed`=teal 테두리 `초과 +20%`, `modified`=amber `변경(페이스)`, `underperformed`=amber `미달 46%`, 미이행=red 테두리 `놓침`, `superseded`=취소선 + `대체 →`, 예정=점선 테두리 `예정`. 배지에는 색과 함께 **아이콘/텍스트를 병기**한다(색각 이상 대응).
  - 외부 출처(Garmin/Intervals) 수행 행은 별도 행이 아니라 **대체된 계획 행 아래 들여쓴 하위 행**(`↳ 실제: 장거리 7.1km · Garmin`)으로 합친다. provider 배지(Garmin 파랑)를 붙인다.

### [치명] F-UI-02 세션 상세가 "원래 계획"만 표시 — 실제 수행·근거·매칭 활동이 없고, 같은 날 두 세션이 한 URL
- 현상: 9/26(완료일) 세션 상세는 `원래 계획 / 쉬운 달리기 11.5km 6:05–6:45/km / 토요일 11.5km 이지런` → `조정 없음 — 계획대로 진행` → 메모 입력으로 끝난다. 이 계획은 실제로는 **대체됨(superseded)** 상태이고, 그날 실제 수행(Garmin 장거리 7.1km, 46%)은 화면 어디에도 없다. "계획대로 진행"은 사실과 반대다. 9/25 세션도 API에는 `actual_dist_km 8.31`, `matched_activity_id 17035`가 있지만 표시되지 않는다(코드 확인). 화면 아래 약 60%(데스크톱 y≈470~800, 모바일 y≈470~790)는 비어 있다.
- 근거: `coach-plan-session-done-desktop.png`, `coach-plan-session-done-mobile.png`, `coach-plan-session-next-mobile.png`. 코드 `session/[date]/+page.svelte:62-79`(workout 계획 필드만 사용), `:97-98`(adjustment 없으면 무조건 "조정 없음 — 계획대로 진행"). 목록 `[id]/+page.svelte:126`의 href가 `session/{w.date}`라 9/26 두 행이 같은 URL이다. API `/coach/plan/1/session/2026-09-26`은 `superseded: true`인 계획 행 1건만 반환한다. `rationale`("저강도 유산소 (HR Zone 2). Seiler 2010…"), `target_hr_zone`은 응답에 있으나 미사용이다.
- 왜 문제인가: U8(막다른 화면)이고 P2(드릴 불가: 세션 → 활동 이동이 없음) 위반이다. 사실과 다른 상태 문구가 표시된다. 설계 5-G의 "원래 계획 | 조정" 2열과 조정 근거 EvidenceQuote도 구현되지 않았다.
- 개선안: 세션 상세를 **3블록 비교 레이아웃**으로 바꾼다.
  - 헤더: `토 9/26 · 1주차` 20px + 상태 배지(F-UI-01과 동일 체계) + 목표 레이스 breadcrumb.
  - **계획 | 실제 2열 카드**(데스크톱 2열, 모바일 세로 2카드). 행은 거리 / 페이스 / 시간 / 평균 HR(존) / 부하(TSS)이고, 각 행 오른쪽에 차이 `+1.4km`, `+0:27/km 느림`(느림은 amber, 빠름은 teal)을 둔다. 실제 카드 하단에 `활동 보기 ›`(→ `/v2/library/17035`, 높이 44px 행 링크)와 provider 배지를 둔다.
  - **처방 근거** 블록: `rationale`을 한 문장 + 근거 칩(`HR Zone 2`, `Seiler 2010`)으로 표시한다.
  - 조정 블록은 adjustment가 있을 때만 보여 주고, 없으면 블록을 생략한다(현재 문구 삭제). superseded면 `이 계획은 9/26 장거리(Garmin)로 대체됨 ›`을 표시한다.
  - URL은 `session/:date/:workoutId`(또는 `?w=`)로 행 단위를 구분하고, 같은 날짜 세션이 여럿이면 상단에 세그먼트 탭(`계획 쉬운 달리기 | 실제 장거리`)을 둔다.
  - 메모는 하단 고정이 아니라 실제 카드 아래에 두고, RPE 1~10 세그먼트(높이 44px)를 함께 둔다(P6).

### [치명] F-UI-03 계획 비교(빈 진입)가 SvelteKit 기본 오류 화면 — 무스타일·무여백·복귀 수단 없음
- 현상: `/v2/coach/plan/compare`를 파라미터 없이 열면 본문에 `400`(16px)과 `거리 정보가 없습니다.`만 나온다. **좌측 여백 0px**(모바일 x=0에 붙음)이고 제목, 설명, 뒤로 링크, 행동 버튼이 없다. 한국어 사용자에게 HTTP 코드 `400`이 노출된다.
- 근거: `coach-plan-compare-mobile.png`, `coach-plan-compare-desktop.png`, `raw/coach-plan-compare.txt`. 코드 `compare/+page.ts:15-17`(`throw error(400, …)`). `find frontend/src -name +error.svelte` 결과 0건이다. 01-sitemap: 진입 링크 0개.
- 왜 문제인가: 막다른 화면(U8)이고, 셸 안에서 유일하게 디자인 시스템이 적용되지 않은 화면이다. 뒤로가기 외에는 복구 경로가 없다.
- 개선안:
  - 공용 `routes/+error.svelte`를 만든다. 셸 여백(px-4, py-10)을 쓰고, 아이콘 + 사람 말 제목("비교할 조건이 없습니다") + 한 줄 설명 + 주 버튼(`새 계획 만들기 →` /v2/coach/plan/new) + 보조 링크(`코치로`)로 구성한다. 상태 코드는 12px fg-muted 각주로만 둔다.
  - compare는 파라미터가 없을 때 오류 대신 `redirect(307, /coach/plan/new)`로 보내거나, 인라인 빈 상태(위와 같은 구성)를 렌더한다.
  - 파라미터가 있을 때의 비교 화면 개선은 F-UI-10을 참고한다.

### [중요] F-UI-04 주기(단계) 시각화 부재 — 9주 구조·현재 위치·볼륨 추이가 없고 CTL 막대는 임의 스케일
- 현상: 헤더에는 `1주차 / 9주 · 레이스 2026-11-22 · 목표 3:19:00` 텍스트, `현재 CTL 74` 막대, `지금까지 이행률 16.7%`가 있다. 막대는 `ctl/100` 비율(74%)이라 목표 CTL·필요 증가량과 무관한 **의미 없는 채움**이다. 단계(기초/강화/정점/테이퍼), 주별 계획 볼륨, 지난 주·다음 주 이동 수단이 없다. 목록은 "이번 주"로 고정된다. 이행률 16.7%는 12px 보조 문구로 위계가 가장 낮다.
- 근거: `coach-plan-detail-desktop.png`(y≈150~195), 코드 `[id]/+page.svelte:79-92`(`width: ctl_current/100*100%`), `:117`("이번 주" 고정). API `GET /coach/plan/1` 키는 `compliance_pct, ctl_current, goal, next_session, week_index, workouts`로 단계·주별 합계가 없다. v1 `src/web/views_training_plan_ui.py:127-190`(`render_plan_overview`: 단계별 비례 막대 + 현재 단계 강조 + 단계 설명). 설계 5-F는 `CTL 진행 68/80 (+12 필요)`다.
- 왜 문제인가: 계획은 시간 구조가 본질이다. "지금 어느 단계에 있고, 앞으로 볼륨이 어떻게 오르내리나"를 보여 주지 않으면 목록형 할 일 앱과 다르지 않다(U7·U10). 스케일 없는 진행 막대는 P5(데이터 잉크) 위반이다.
- 개선안: 헤더 아래에 **PlanTimeline** 블록을 둔다(높이 모바일 96px, 데스크톱 120px).
  - 가로축은 주(1~9, 레이스 주 마지막)다. 각 주는 **세로 막대 = 계획 주간 거리**(outline)와 실제 거리(채움)를 겹쳐 그린다. 막대 아래에 단계 띠(기초/강화/정점/테이퍼, 4색 저채도, 라벨 11px)를 둔다. 현재 주는 흰 테두리 + `오늘` 마커, 레이스 주는 깃발 아이콘이다.
  - 막대를 탭하면 아래 주간 목록이 그 주로 바뀐다(선택 주 `aria-pressed`). 모바일은 좌우 스와이프, 데스크톱은 `‹ 1주차 ›` 페이저를 둔다.
  - CTL 막대를 **목표 기반 게이지**로 바꾼다: `CTL 73 → 레이스 목표 80 (+7)`, 레이스일 예상 CTL 마커 포함. 목표가 없으면 막대를 제거하고 숫자 + 4주 스파크라인만 둔다.
  - 이행률은 헤더 우측에 원형 게이지 32px + `이행 1/6 세션 · 17%`로 승격한다(분모 명시).
  - API 확장이 필요하다: `phases[{name,start_week,end_week}]`, `weeks[{index, planned_km, actual_km}]`(UX/데이터 담당과 조율).

### [중요] F-UI-05 주간 목록의 시각 문법 — 날짜·오늘 부재, 설명이 제목 반복, 강도 구분 없음, 데스크톱 1,040px 단일 열
- 현상:
  - 요일 열은 `월 화 …` 12px muted뿐이고 날짜(9/21)가 없으며 **오늘(9/27 일) 강조가 없다**.
  - 2줄째 설명 `월요일 11.5km 이지런`은 1줄째(`쉬운 달리기 11.5km`)를 반복한다. 9행 × 2줄 중 9줄이 중복 정보다. 반면 API의 `rationale`, `target_hr_zone`, `interval_prescription`은 쓰지 않는다.
  - 유형(쉬운/인터벌/회복/장거리)은 모두 같은 흰 14px 텍스트라 주간 강도 분포(하드/이지 배치)가 한눈에 보이지 않는다.
  - 주 합계(계획 57.6km / 실제 24.7km 등)가 없다.
  - 데스크톱에서 목록이 1,040px 폭 한 열이다. 제목(x≈260)과 상태 라벨(x≈1,240) 사이 약 1,000px를 눈이 건너야 한다. 모바일은 행 높이 약 59px(9행 약 530px)로 밀도는 적당하다.

- 모든 세션 행이 `<a>` 전체 영역 링크라 목록 → 세션 이동이 확실하고 빠르다(데스크톱 158ms, 모바일 79ms). Today의 "최근 활동" 행 문제와 달리 어포던스와 반응이 일치한다.

- ACWR → 계산 분해(ATL·CTL 입력) 드릴이 연결되어 있어 P2의 뼈대가 있다.
- 장식 없는 다크 톤과 구분선 기반 목록으로 Quiet Data 방향을 지킨다.
