# Coach · 계획 — UX(사용자 경험·흐름) 리뷰

**리뷰일**: 2026-09-27 · **대상**: `/v2/coach/plan`(게이트웨이) · `/v2/coach/plan/:id`(계획 상세) · `/v2/coach/plan/:id/session/:date`(세션 상세) · `/v2/coach/plan/new`(새 프로그램) · `/v2/coach/plan/compare`(프로그램 비교) + Today·Coach 대화와의 연결
**데이터 상태**: 활성 계획 1개(`42km 목표`, 9주, 레이스 2026-11-22, 목표 3:19:00). 오늘(9/27, 일) 9.3km 달리기는 Intervals 계획 이벤트(id 153)에 매칭(`completed=1, overperformed, 92.3%`). 원래 계획인 22.4km 장거리(id 189)는 `superseded=true`.
**범위 메모**: 쓰기 동작(메모 저장·계획 생성)은 실행하지 않았다. 화면 텍스트(`raw/coach-plan*.txt`), 클릭 실측(`raw/interact-*.json`), 투어(`raw/tour.json`), 읽기 전용 API 응답, 라우트 코드로 판단했다.

요약:
- **세션 상세가 엉뚱한 세션을 보여준다.** 계획 목록에서 완료된 행(`토 장거리 ✓ 46%`, `일 쉬운 달리기 ✓`)을 누르면, 같은 날의 **대체된 원래 계획**(11.5km 이지런, 22.4km 장거리런)이 뜬다. 그 아래에는 "조정 없음 — 계획대로 진행"이 표시된다. 실제로 달린 거리·이행률·활동 링크는 세션 화면 어디에도 없다. "오늘 세션 수행 후 결과 확인"은 불가능하다.
- **"계획 수정"과 "상태 기반 조정"을 할 수 있는 곳이 v2에 없다.** 세션 이동·건너뛰기·거리 변경, 조정 [수락]/[원래대로], 레이스 날짜·요일 변경 버튼이 0개다. 그런데 Today는 "계획 수립·수정은 Coach에서 →"라고 안내하고, 누르면 읽기 전용 목록에 닿는다. P7(State-Bound Plan)의 핵심 상호작용이 빠져 있다.
- **활성 계획이 있으면 새 대회 계획으로 가는 경로가 없다.** `/v2/coach/plan`은 활성 계획으로 302 리다이렉트된다. Coach 홈의 "새 프로그램 만들기"는 계획이 없을 때만 보인다. 새 계획은 URL을 직접 입력해야 만들 수 있다. 계획을 만드는 흐름도 "단계 1/3 → 단계 3/3"으로 건너뛰고, 비교 화면은 직접 열면 헤더도 뒤로가기도 없는 `400 거리 정보가 없습니다` 원시 오류 화면이다.
- **"이번 주 계획 확인"은 0탭이지만 읽기 비용이 크다.** 요일마다 행이 2개(대체된 원래 계획 + 실제 이벤트)이고, `✓ 46%`(초록), `✓ 페이스 상이`(실제로는 거리 120%), 계획 생성 전 날짜의 `미이행` 4건 같은 라벨이 오해를 부른다. 이번 주 밖(다음 주, 전체 9주 흐름)은 볼 수 없다.
- **메모는 저장해도 아무 데도 쓰이지 않는다.** 세션 메모는 날짜 키 하나로 `user_inputs`에 저장되고, Coach 대화 맥락·계획 목록·활동 상세 어디에서도 다시 읽히지 않는다(`grep session_note` → `plan_service`만 사용). 입력의 보상이 없다(P6 취지 위반).

### [치명] F-UX-01 세션 상세가 같은 날의 "대체된 원래 계획"을 보여주고, 실제 수행 결과는 어디에도 없다
- 현상: 계획 목록에서 같은 날짜의 두 행이 같은 URL(`/session/2026-09-26`, `/session/2026-09-27`)로 연결된다. 세션 화면은 그중 첫 행, 즉 `superseded=true`인 원래 계획(토 11.5km 이지런 / 일 22.4km 장거리런)을 보여준다. 완료된 행(`장거리 ✓ 46%`, `쉬운 달리기 ✓`)을 눌러도 결과는 같다. 화면에는 "원래 계획 → 조정 없음 — 계획대로 진행 → 세션 메모"만 있다. 실제 거리(`actual_dist_km 7.09 / 9.30`), 이행률(46.4% / 92.3%), 결과 라벨(underperformed / overperformed), 매칭 활동(`matched_activity_id 17323 / 17414`)은 API 응답에 있는 필드조차 렌더되지 않는다.
- 근거: `tour.json` coach-plan 링크 목록(토·일 각 2행이 동일 href). `GET /api/v1/coach/plan/1/session/2026-09-27` → `workout.id 189, superseded true, completed 0`(확인). `plan_service.py:158-160`(`next(w for w in workouts if date == session_date)` — 첫 행 선택). `session/[date]/+page.svelte:62-100`(원래 계획·조정만 렌더, actual/compliance/matched 필드 미사용). `coach-plan-session-done-mobile.png`.
- 왜 문제인가: 핵심 과업 ②가 막힌다. 오늘 9.3km를 달린 러너가 오늘 행을 누르면 "22.4km 장거리런 · 조정 없음 — 계획대로 진행"을 보게 된다. 러너는 잘못된 정보로 "아직 장거리를 안 했다"고 오판할 수 있다(심각도 정의의 "틀린 정보"). U4(누른 것과 다른 것이 열림), U8, P2(세션 → 활동 원천 경로 없음).
- 개선안:
  - URL을 날짜가 아니라 **워크아웃 id 기준**으로 바꾼다(`/coach/plan/:id/session/:workoutId`, 날짜 URL은 해당 날짜의 비대체·완료 우선 행으로 리다이렉트). 서버의 날짜 조회도 `superseded=0` 우선, 완료 우선으로 정렬한다.
  - 세션 화면을 **"계획 | 실제 | 해석" 3블록**으로 재구성한다. ① 계획: 종류·거리·페이스·HR존·구조·근거 한 줄(`rationale`). ② 실제(완료 시): 거리·시간·평균 페이스·평균 HR·존 분포 막대, `계획 대비 92% · 초과` 배지, `활동 보기 ›`(→ `/v2/library/17414`). ③ 해석: "쉬운 날치고 길었어요 — 내일 4.6km는 그대로 짧게" 1~2문장 + 근거 칩.
  - 대체된 원래 계획은 실제 세션 화면 안에 "원래 계획: 22.4km 장거리 → Intervals 이벤트로 대체됨" 한 줄로 접는다.

- 현상: 세션 상세는 `코치 / 42km 목표 / 1주차 토` 브레드크럼만 있다(계획 상세·새 프로그램은 `← 코치`). 이전/다음 세션으로 넘기는 방법이 없어 목록으로 돌아갔다 다시 들어가야 한다. 브레드크럼 글자는 12px 링크라 모바일 터치 타깃이 작다. 계획 화면의 `TODAY`는 `new Date().toISOString()`(UTC)라서 KST 00:00~09:00에는 어제 세션을 "미이행"으로 판정하지 않는다. `/coach/plan` 방문은 active와 `/:id`를 연달아 호출한다(각 10ms 내외라 체감 영향은 없음).
- 근거: `session/[date]/+page.svelte:49-56`, `[id]/+page.svelte:32`, `tour.json` coach-plan apis.
- 왜 문제인가: U8 일관성. 세션 연속 확인(주간 리뷰)에 불필요한 왕복이 생긴다. 날짜 판정 오류는 이른 아침 러너에게 라벨이 불일치하는 원인이 된다.
- 개선안: 상단에 `← 42km 목표` 1개 + 부제 브레드크럼으로 통일한다. 세션 상세 하단에 `‹ 금 회복` / `일 장거리 ›` 스와이프/버튼을 둔다. 날짜는 공용 `localToday()`(KST) 유틸을 쓴다.

### [개선] F-UX-11 경쟁 앱 대비 — 계획 영역은 기본 동등성에 못 미친다
- 비교:
  - **Runna**: 세션마다 구조 시각화(워밍업·반복·회복 블록 막대)와 목표 페이스를 보여준다. 세션 이동·건너뛰기·계획 설정(요일·장거리 요일·레이스 날짜) 변경, 워치 전송, 완료 후 "어땠나요" 피드백을 지원한다.
  - **TrainingPeaks**: 캘린더에서 계획 vs 완료를 색으로 구분한다(초록 완료 / 노랑 부분 / 주황 초과 / 빨강 미수행). 워크아웃 드래그 이동, 워크아웃별 코멘트 스레드(선수↔코치), 시즌 계획(ATP)으로 주별 TSS 목표를 제공한다.
  - **Garmin Coach**: 설정 시 가능 요일·장거리 요일·현재 주간 거리를 묻고, 러닝 후 "어떻게 느꼈나" 평가를 다음 세션 적응에 반영한다. 예상 완주 가능성 지표를 보여주고, 워치에 세션이 자동으로 들어간다.
  - RunPulse v2는 세 앱 공통 기능(주 이동, 세션 이동/건너뛰기, 요일 설정, 완료 후 피드백, 계획 vs 실제 색 체계, 워치 전송) 중 **하나도 없다**. 백엔드에는 `training/garmin_push.py`·`caldav_push.py`가 있으나 v2에 노출되지 않는다.
- RunPulse만의 기회(signature moment): ① **"근거가 달린 조정"**: 조정 카드마다 HRV·ACWR·체크인·수면 중 무엇이 얼마나 기여했는지 칩으로 보여주고, 탭하면 분해로 이어진다. 경쟁 앱의 조정은 블랙박스다. ② **4소스 계획 통합**: Intervals·Garmin 이벤트와 RunPulse 계획을 한 주에 겹쳐 "누가 무엇을 처방했나"를 출처 배지로 보여준다(현재 대체 로직을 투명하게 드러내는 방향). ③ **예측과 계획의 연결**: 계획을 수행했을 때 예상 예측 기록 궤적(3:40 → 3:2x)을 계획 헤더에 보여주고, 세션을 건너뛰면 궤적이 어떻게 바뀌는지 미리 보여준다.

## 잘된 점 (유지)
- 화면 전환과 API가 빠르다. 계획 관련 API는 7~37ms, 계획 상세 FCP 456~568ms, 목록→세션 전환 79~158ms, Coach→계획 167~180ms다. Today보다 체감 반응이 좋다.
- 계획 목록 행 전체가 `<a>`이고 hover 배경이 있다. U4 기준에서 Today 최근 활동 행보다 낫다.
- 계획이 없을 때 게이트웨이(`/coach/plan`)가 목표 레이스를 프리필해 `N주 로드맵 만들기`로 이어준다. Today의 다음 세션 카드도 같은 프리필 경로를 쓴다(`planPrefill.ts`).
- 대회일을 기준으로 역산해 계획 주차를 정하는 방식(대회 주 = 마지막 주)은 러너의 실제 사고와 맞다.
- 매칭 결과 필드(`compliance_pct`, `outcome_label`, `matched_activity_id`, `superseded`)가 이미 API에 있다. 화면 개선의 대부분은 새 데이터 없이 렌더링·라우팅만 바꾸면 된다.
- 세션 메모의 저장 중/저장됨 ✓/실패 문구와 입력 전 비활성 처리는 피드백 패턴으로 적절하다.

## 채점 (0~10)
- **비전 부합 3**: P7(상태 기반 조정 + 수락/거부)이 없다. 근거(`rationale`)가 API에만 있고 화면에 없다. Coach 대화와 계획이 연결되지 않는다.
- **정보 정확성 3**: 세션 상세가 대체된 계획을 보여주고 "계획대로 진행"이라고 말한다. `✓ 46%` 초록, "페이스 상이"(실제는 거리 초과), 계획 전 날짜의 미이행 집계가 있다.
- **시각 품질 5**: 목록은 정돈되어 있으나 요일당 2행, 흐린 대체 행, 기준 없는 CTL 막대, 원시 400 화면이 있다(UX 관점 한도).
- **상호작용 반응성 7**: 전환·API가 모두 빠르다(≤ 180ms). 무반응 요소는 적다(HRV 행). 쓰기 상호작용 자체가 거의 없어 평가 범위가 작다.
- **흐름 2**: 핵심 과업 5개 중 ③·⑤는 불가, ④는 활성 계획 시 진입 불가, ②는 잘못된 세션에 도착한다. 대화↔계획↔활동 연결이 0이다.
- **혁신성 3**: 대회 역산, 외부 계획 이벤트 매칭은 기반으로 좋다. 사용자에게 드러나는 차별 요소는 없고, 경쟁 앱 기본 기능에도 못 미친다.

## 최우선 개선 3개
1. **세션 = 계획·실제·해석 한 화면(F-UX-01·05·07)**: 워크아웃 id 라우팅으로 대체 행 오표시를 없앤다. 실제 결과(거리·이행률·활동 링크)와 결과 라벨 5종을 요일당 1행으로 보여준다. 완료 직후 RPE 원탭 회고를 워크아웃 단위로 저장하고, 다음 세션·Coach 맥락에 반영한다.
2. **P7 조정·편집 최소 세트(F-UX-02·09)**: 상태 한 줄 + 세션 인라인 조정 카드(근거 칩 + `[조정 수락] [원래대로]`)를 만든다. 행 액션(옮기기·건너뛰기·줄이기·휴식)에는 부하 변화 미리보기와 되돌리기를 붙인다. 계획 설정(요일·레이스 날짜·목표)을 바꾸면 이후 주를 재생성한다. 그 전까지 Today의 "수정은 Coach에서" 문구는 고친다.
3. **계획 생애주기 흐름(F-UX-03·04·06·08)**: 활성 계획 중에도 `새 대회 계획` 진입점을 둔다. 3단계(목표+프로필 근거 → 내 일정 → 성향별 비교·미리보기)를 실제로 구현하고 기존 계획 처리를 묻는다. 주 이동 + 9주 주기 스트립을 두고, 세션·답변에서 `Coach에게 묻기`/`계획에 적용`으로 대화와 계획을 양방향 연결한다.
