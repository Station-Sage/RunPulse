## 0. 결론 요약

### 무엇이 바뀌었나 (r1 → r2)

1. **채택안 변경.** r1은 "최근 대회 VDOT(시간 감쇠)와 90일 세션 하한 중 큰 값"(M5')이었다. 이 방식은 최근 훈련이 나빠져도 예측이 내려가지 않았다(PB 의존). r2는 세 신호를 섞는다.
   - (A) 대회 앵커
   - (W) 최근 42일 고강도 작업구간(GAP 기준)
   - (H) 기온 보정 심박-속도 곡선에서 LTHR(177)의 속도

   식은 `VDOT = 0.8 × [W ≥ A이면 W, 아니면 A + 0.25·(W − A)] + 0.2 × H`이다. 훈련이 좋아지면 W가 앵커를 대체하고, 나빠지면 그 차이의 25%만큼 내려간다. HR 곡선은 항상 20% 반영된다. 화면에는 "대회 기록 의존 X% / 최근 훈련 반영 Y%"를 표시한다(현재 60% / 40%).
2. **HR 외삽 재평가.** r1은 "HR-페이스 외삽이 레이스를 +4~18% 느리게 본다"고 했다. 이것은 (a) 여름 기온 효과와 (b) 기준 강도를 %HRmax로 잡은 탓이 컸다. 기온을 보정하고(기기 온도 15℃ 초과분 1℃당 −0.59% 속도) **LTHR 속도를 60분 레이스 페이스로 보면** 레이스 9건 MAE가 7.9%에서 4.2%로(편향 +1.5%) 줄어든다. 다만 레이스 날의 초과 속도는 평균 +5.5%, SD 5.7%로 **불안정해서 단독 보정계수로 쓸 수는 없다.** 그래서 가중 20%로만 넣는다.
3. **마라톤 손계수(0.06) 폐기.** 이 값은 경주 마라톤(서브맥스) 1건에 맞춰 손으로 정한 것이었다(사실상 n=1). 대체안은 두 모델을 쓴다.
   - (i) Daniels 환산: 충분한 마라톤 훈련을 가정한 **낙관 경계**
   - (ii) **Tanda(2011) 문헌식**: 8주 평균 주간 거리·훈련 페이스에서 마라톤 페이스를 추정한 **볼륨 반영 경계**

   두 값의 기하평균을 중앙값으로, 두 값을 넘는 구간을 범위로 쓴다. 두 모델이 벌어질수록 신뢰도가 떨어진다. 경주 마라톤 확인: Daniels 3:38:07, Tanda 3:44:49, 중앙값 3:41:26. 실제(서브맥스)는 3:42:13이었다.
4. **날씨 데이터 실측.** 세 소스 모두 **기기(손목) 온도만** 있다(canonical 러닝 2025-H2 이후 90%). 습도·풍속·체감온도는 저장된 payload 어디에도 없다. intervals는 `has_weather=False`가 100%이고, Garmin 활동 weather 엔드포인트는 수집하지 않고 있다. → 외기 날씨 인제스트 유닛을 새로 둔다(§4-8).
5. **메트릭 감사**(REVIEW-08)에서 예측에 영향이 가는 결함 7건을 찾았다. 예: GAP가 실제로는 경사 보정을 안 한다, 중복 활동 이중 합산, rec 100 고정, di 87%가 100. → 구현 순서를 **"메트릭 수정 → 예측"**으로 재편했다.

### 롤링 백테스트 핵심 수치

- **대리 타깃**: 2025-05 이후, 각 활동의 "8분 이상 연속 + 평균 HR ≥163" 고강도 구간 GAP-VDOT와 레이스. 모두 해당 시점 이전 데이터만 썼다. 2025년을 학습 구간, 2026년을 검증 구간(n=25)으로 시간순 분할했다. 거의 전력인 구간(HR ≥172)은 검증 n=12다.

- **결론**: 훈련 반응 항 중에서 **작업구간(W)만 일관되게 개선**한다. 앵커 대비 CI가 0을 넘지 않는 유일한 항이다.
  - **볼륨(TV)과 HR 추세(THR)는 개선하지 않았다.** 그래서 중앙값이 아니라 범위·신뢰도·설명에만 쓴다.
  - 하향 반영(k=0.25)과 H 20% 혼합은 **개선 폭이 CI 안이라 통계적으로 확정되지 않는다.** 그래도 레이스 확인에서 나빠지지 않았고(D-0 2.4%, 최대 오차 6.2%에서 5.2%로 감소), "최근 훈련이 예측을 움직여야 한다"는 요구에 맞기 때문에 채택했다. [판단]
  - 표본은 여전히 작다. 5K와 마라톤은 직접 검증하지 못했다.

- HRR 체계는 HRmax가 필요하다. 이 러너의 HRmax는 2026년 레이스에서만 관측됐고 2025년에는 184였다. RHR은 매일 측정되어 안정적이다. HRR Z4(163~178)는 LTHR을 가로질러 "역치 하"와 "역치"를 한 존에 섞는다.
- LTHR 체계는 성과(레이스·템포)에 직접 묶여 있고 Garmin 추정과 일치한다. 대신 LTHR 갱신에는 역치 이상 노력이 필요하다(최근 42일 템포·레이스에서 재추정 가능).
- **제안** [판단]
  - **LTHR 체계를 1차로 쓴다**: 예측(H 신호), 템포/인터벌 강도 판정, 작업구간 선정.
  - HRR 체계는 이지·회복 상한과 일상 존 표시에 쓴다(플랜의 "이지 HR ≤145"는 HRR 68%).
  - LTHR은 일별 메트릭 `hr_profile`에서 (a) 최근 180일 전력 레이스와 템포 블록의 추정치, (b) Garmin 값 중 **최근 것 우선**으로 정하고, 둘이 4bpm 이상 다르면 신뢰도를 낮춘다.
- 센서·GPS 제외 규칙: 워밍업 2랩, 900m 미만 부분 랩, HR 스파이크 활동, 트레일·실내.

### 2-7. 심박-속도 관계와 기온 효과 (r2 재평가)

- **기온 모델**: 정상상태 1km 랩 1,244개(기기 온도 있음, 2025-04 이후)에 `속도(GAP) = a + b·HR + c·max(0, T − T0)`를 적합했다.

| T0 | c (1℃당 속도 변화) | R² |
|---|---|---|
| 10℃ | −0.45% | 0.41 |
| **15℃** | **−0.59%** | **0.43** |
| 20℃ | −0.97% | 0.45 |

  기온 없는 모델의 R²는 0.31이다. **채택은 T0=15℃, −0.59%/℃**다.
  - 문헌 대조 [가정: 원문 수치 확인 필요]: Ely 등(2007) 마라톤 기록 분석에서 WBGT가 약 5℃에서 25℃로 오르면 중상위권 러너 기록이 수 % 느려진다. 이 러너의 계수(10℃ 차에 약 6%)는 **기기 온도(손목, 외기보다 높게 나옴)** 기준이라 직접 비교할 수는 없다.
- **월별 잔차**: 보정 전 여름 −4~−8%, 가을 +4~+8%. 보정 후 여름 −0.4~−5.8%로 줄었지만 **1~3월에 −5~−7%가 새로 드러났다**. 겨울에는 손목 온도가 소매 안에서 외기보다 높게 읽히는 문제와, 12~2월 훈련 감소가 섞인 것으로 보인다. 외기 날씨가 없어 분리할 수 없다 [가정].
- **레이스 당일 편향(기온 보정 후)**: 직전 90일 모델에 레이스 평균 HR과 레이스 기온을 넣었을 때, 실제 속도가 모델보다 **평균 +5.5%, SD 5.7%**(n=8, 범위 −2.8~+16.7%) 빨랐다. 보정 전(+7.8%)보다 줄었지만 SD가 커서 **고정 보정계수로 쓰면 개별 예측 오차가 ±7% 수준**이 된다 → 단독 신호로는 부적합하다.
- **LTHR 앵커링**: 같은 곡선에서 LTHR 177의 속도를 "60분 레이스 속도"로 보고 Daniels VDOT를 계산한 H 신호는 레이스 9건에서 D-0 MAE 4.2%(편향 +1.5%), D-28 MAE 4.7%다. 앵커가 없을 때의 **폴백으로는 쓸 만한** 수준이다.

**해석** [판단]
- "최근 훈련 성과를 반영하라"는 요구는 데이터로 절반만 지지된다. **역치 이상 작업구간의 실제 속도**는 앵커를 개선한다. **볼륨과 HR-속도 추세는 이 러너 데이터에서 예측을 개선하지 않았다.** 이유는 (1) 여름·겨울 기기 온도 오염, (2) 볼륨과 레이스 능력 사이의 시차(수개월), (3) 작은 표본이다.
- 그래서 볼륨·롱런·HR 추세는 중앙값이 아니라 **범위(비대칭 확대)·신뢰도·"왜" 설명**에 넣는다. 외기 날씨가 들어오면 HR 추세를 재평가한다(U-B2 수용 조건).

## 4. 설계 명세 — Race Prediction v2 (r2)

### 4-1. 원칙

1. 예측은 **보여준 성과**(대회, 작업구간, LTHR에서의 속도)에서 출발하고, 각 신호의 기여 비율을 공개한다.
2. 목표 기록은 입력이 아니다.
3. 손으로 정한 보정계수를 쓰지 않는다. 계수는 (a) 이 러너 데이터에서 추정하고 백테스트한 것, (b) 출처를 밝힌 문헌식, (c) 둘 다 안 되면 **범위 확대·신뢰도 하향**으로 표현한다.
4. 입력 메트릭은 정합성 수정이 끝난 뒤에만 쓴다(REVIEW-08).
5. Calculator 내부 raw SQL 금지 → CalcContext API 추가(§4-10).

### 4-2. 메트릭 그래프

```
[sync] Garmin 랩/스트림 확장 필드 · 외기 날씨 ──┐
[activity] run_quality (이상치·HR 트윈 병합·전력 판정) │
[activity] activity_weather (정규화 날씨)          ├→ [activity] session_profile (GAP·존·디커플링·작업구간@HR·회복HR)
[activity] runpulse_vdot v2 (가드)                 │        └→ [activity] run_effort (고강도 구간 GAP-VDOT)
[activity] workout_type_classified v2             ─┘
[daily] hr_profile (HRmax·RHR·LTHR·두 존 체계)
[daily] hr_pace_model (기온 보정 곡선, speed@LTHR → H)       ← session 랩, activity_weather
[daily] training_response (42일 작업구간 W, 볼륨 8·16주, 롱런, MP 노출, 작업구간 페이스@HR 추이) — 설명·범위용
[daily] perf_vdot (A·W·H 혼합 + 기여 분해)
[daily] marathon_shape v2 · marathon_model (Daniels·Tanda)

```

### 4-3. 입력·이상치 규칙

r1 §4-3과 같고 두 가지가 추가된다.
1. 속도는 **GAP 우선**이다(Garmin 랩 `avgGradeAdjustedSpeed`, 없으면 원속도). GAP이 있으면 `hilly` 활동도 성과 신호에서 제외하지 않는다.
2. 기온은 `activity_weather.temp_c`(외기) 우선, 없으면 기기 온도에 잠정 계수를 쓴다.

### 4-4. 신호와 결합식

| 신호 | 정의 | 창 | 비고 |
|---|---|---|---|
| **A** 대회 앵커 | max_i [ VDOT_i − 0.08 × max(0, 경과주 − 6) ], 전력 대회(사용자 확인 입력 Q3이 있으면 그 판정 우선) | 365일 | 감쇠 0.08/주는 문헌 기반 **가정**(디트레이닝, 분기당 VDOT 1~2). 백테스트로 튜닝하지 않음 |
| **W** 작업구간 | `run_effort` 중 구간 평균 HR ≥ 0.92×LTHR 또는 대회인 구간의 GAP-VDOT 최대 | 42일 | 기온 보정: 구간 속도 ÷ (1 − 0.0059×max(0, T−15)) |
| **H** HR@LTHR | 60일 정상상태 랩의 기온 보정 속도~HR 회귀에서 v(LTHR) → VDOT(거리 = v×3600, 시간 3600초) | 60일 | 랩 25개 미만이면 없음 |

결합(값은 VDOT):
```
core = W            (W ≥ A)
     = A + 0.25·(W − A)   (W < A)        # 하향은 25%만
     = A            (W 없음)
VDOT = 0.8·core + 0.2·H   (H 있음) / core (H 없음)
A 없음: VDOT = 0.6·W + 0.4·H, 신뢰도 상한 0.45 / W도 없음: VDOT = H, 상한 0.3 / 모두 없음: 미산출
```
- 0.25와 0.2는 **미리 정한 반올림 값**이다. 롤링 백테스트에서 0, 0.25, 0.5 / 0, 10%, 25%를 비교했을 때 차이가 CI 안이라 보수 쪽 값을 택했다. 튜닝 결과가 아니다.
- **기여 분해**(UI 표시): 실제로 적용된 가중치로 계산한다.
  - W ≥ A: 대회 0% / 작업구간 80% / HR 20%
  - W < A: 대회 60% / 작업구간 20% / HR 20% ← **현재 상태**
  - "대회 기록 의존 % = 대회 가중", "최근 훈련 반영 % = 작업구간 + HR 가중"
  - 근거 목록에는 각 신호의 원천 활동 id와 메트릭(`run_effort`, `hr_pace_model`)을 달아 MetricBreakdown으로 계보를 따라갈 수 있게 한다.

### 4-5. 시간 환산·범위·신뢰도 (5K·10K·하프)

- 중앙값: Daniels 역산 `time_for_vdot(VDOT, d)`
- 범위: `T × (1 ± 1.28·σ·(1 + 0.5·(1 − conf)))`. σ=3.5%는 레이스 9건 잔차 SD 3.3~3.6%에서 왔다. 5K는 검증이 없어 σ=4.0%로 **가정**한다.
- 범위를 **느린 쪽으로만** 넓히는 요인(각 +1%p): 최근 28일 러닝 < 6회, 8주 볼륨이 16주 평균의 80% 미만, 7일 평균 TSB < −20.
- 신뢰도 `conf = 0.9 × f_rec × f_agree × f_dist × f_data`
  - `f_rec`: 앵커 8주 이하 1.0 → 52주에서 0.5
  - `f_agree`: A·W·H 폭 / 중앙값이 3% 이하 1.0 → 10% 이상 0.6
  - `f_dist`: 앵커와 목표 거리 비율 1배 1.0, 2배 0.9, 4배 이상 0.75
  - `f_data`: HR·GAP 커버리지
- 현재: 10K conf = 0.9 × 0.86 × 0.93 × 1.0 ≈ **0.72**

### 4-6. 마라톤 (손계수 폐기)

- **D** = Daniels 환산 `time_for_vdot(VDOT, 42195)`. 10K·하프 능력이 마라톤 지구력으로 온전히 옮겨진다고 가정하므로 낙관 경계다.
- **T** = Tanda(2011) `Pm[s/km] = 17.1 + 140·exp(−0.0053·K) + 0.55·P`
  - K = 8주 평균 주간 거리(km), P = 8주 평균 훈련 페이스(s/km, 실내·트레일 제외)
  - [문헌: Tanda G., *J Hum Sport Exerc* 2011. 계수는 원문 값이며, 원문 오차(수 분)는 구현 시 재확인 필요]
  - 이 러너 데이터에서 추정한 계수가 아니라 문헌식이다.
  - P에 기온 보정을 할지는 원문에 없는 확장이라 **하지 않는다.** 여름 훈련 페이스 때문에 T가 느린 쪽으로 치우칠 수 있다는 점은 이유 문장에 적는다.
- 중앙값 = √(D·T). 범위 = [min(D, T)×0.98, max(D, T)×1.03]. 추가로 12주 안에 ≥28km 롱런이 0회이면 high에 +2%를 더한다. 이것은 **범위 확대이지 중앙값 보정이 아니다**(근거가 약해서).
- 신뢰도: 위 식에 `f_agree_M`(|D − T| / 중앙값이 3%이면 1.0 → 12%이면 0.5)과 `f_dist = 0.75`를 곱한다.
- 확인(유일한 표본): 경주 2025-10-18에서 D 3:38:07, T 3:44:49 → 중앙값 3:41:26, 실제(서브맥스) 3:42:13. **검증이 아니라 모순 없음 확인**이다.
- 현재: D 3:30:44 / T 3:48:22 → **3:39:22 (3:26:31~3:55:13)**, conf ≈ 0.35
- **r1의 `p = 0.06×(1 − shape)`의 출처** [정직한 기록]: 문헌값이 아니다. 경주 마라톤 1건에서 서브맥스 기록보다 느린 예측이 나오지 않도록 손으로 고른 값이다(0.08은 모순이 났고 0.06은 모순이 없었다). n=1에 맞춘 것이라 근거가 없어 폐기한다.
- 개인 Riegel 지수: 쓰지 않는다(§7 Q4).
- 춘천 이후 마라톤 결과가 생기면 D·T 중 어느 쪽이 맞는지 기록하고, 2건 이상 쌓이면 가중을 데이터로 정한다.

### 4-7. 날씨 보정 모델

- **학습 데이터에서**: 정상상태 랩 `속도 = a + b·HR + c·max(0, T − 15)`, c = −0.59%/℃(기기 온도, 잠정). 외기 온도가 인제스트되면 재추정하고 습도·이슬점 항을 추가 검토한다. 문헌 WBGT 기반 모델과 비교한다.
- **예측 시**: 신호 W·H는 15℃ 기준으로 정규화한다. 레이스 당일 페널티는 **what-if 입력으로만** 둔다(`race_temp_c` 입력 → 중앙값 × (1 + 0.0059·max(0, T − 15)), 범위 +1%p). 예보 자동 연동은 범위 밖이다.
- 11월 하순 레이스는 보정 영향이 작을 것으로 본다 [가정].

## 5. UI 방향 (r1 + r2)

1. RaceHub: 중앙값, 범위 막대, 목표 눈금(3:19)을 표시한다. 목표가 범위 밖이면 "현재 근거로는 어려움"이라고 쓴다. 신뢰도 점 표시.
2. **기여 분해 막대**: "대회 기록 60% · 최근 작업구간 20% · 심박 곡선 20%". 탭하면 각 신호의 원천 활동과 메트릭(MetricBreakdown)으로 이동한다.
3. **"왜 이 숫자인가"**: 신호 3개, 범위를 넓힌 요인(롱런 부족, 볼륨 감소, 모델 간 차이), 마라톤 Daniels 대 Tanda 두 값을 보여준다.
4. **훈련 반응 카드**: 작업구간 페이스@HR 월별 추이(기온 보정 전후 토글), 주간 볼륨, 롱런, MP 노출을 보여준다. 예측을 직접 바꾸지 않는 신호는 "범위에 반영" 배지를 단다.
5. **대회 후 확인 입력(Q3 확정)**: 대회로 인식된 활동에 "전력이었나요 / 페이스 조절 / 펀런 + 공식 기록" 한 번 입력.
6. 존 표시: LTHR 기준 5존을 기본으로, HRR 존은 토글로 둔다.
7. what-if: "레이스 당일 기온", "10K를 X분에 뛰면" → 서버의 순수 함수 재사용.
8. 메트릭 브라우저 '레이스 준비도': perf_vdot, hr_profile, training_response, marathon_shape. REVIEW-08 감사 결과 "데이터 부족·포화" 상태를 표기한다.
9. REVIEW06-UNITS-3의 PB 대조 유닛은 이 설계로 대체한다(Q7).
