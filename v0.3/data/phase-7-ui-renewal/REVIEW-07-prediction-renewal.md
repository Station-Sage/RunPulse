### 0-2. 채택안 (r3)

```
A  = max over 전력 대회(365일) [ VDOT(15℃ 등가) − 0.08·max(0, 경과주 − 6) ]
W  = 최근 42일 연속 랩 블록(≥2km·≥8분, GAP) 최고 VDOT, 자격: 대회 | 블록 HR ≥ 0.92·LTHR | (LTHR 없으면) 블록 속도 ≥ 0.90·v_t
H  = 최근 60일 정상 주행 랩의 HR–속도(15℃ 정규화) 직선에서 LTHR 속도 → 60분 레이스 VDOT
core = W (W ≥ A) | A + 0.25(W − A) (W < A) | A (W 없음);  VDOT15 = 0.8·core + 0.2·H (H 없으면 core)
T(d) = Daniels(VDOT15, d) × (d / d_앵커)^(k − 1.06)   ← k: 개인 내구성(수축)
마라톤 = √(Daniels × Tanda), 범위 [min×0.98, max×1.03×(1.02 if 12주 28km+ 롱런 0)]
출력은 15℃ 기준 + 기온별 표(5~30℃, 개인 heat_model), 80% 범위, 근거 기반 신뢰도·이유, 기여도
```

### 2-5. 심박 강도 체계 — HRR 대 LTHR (r2 신규)

> **r3**: LTHR·HRmax는 고정값을 쓰지 않는다. `hr_profile`이 매일 **자체 추정**(현재 HRmax 192, LTHR 177.4 — 전력 10K·하프 3건, RHR 44)과 **기기 참조**(Garmin LTHR 177, 2026-05-01)를 따로 저장하고, 각각 HRR·LTHR 존을 계산한다(§4-3). 아래 표의 HRmax 193은 r2 시점의 대회 최대값이고, r3 자체 추정은 단일 스파이크를 피하려고 두 번째 큰 값(192)을 쓴다.

### 2-7. 심박-속도 관계와 기온 효과 (r2 재평가)

> **r3**: 기기 온도 대신 외기(Open-Meteo)로 다시 적합했다 — 15℃ 이상 −0.62%/℃, 5℃ 이하 −0.84%/℃, R² 0.42. 개인 `heat_model`은 이를 기본값으로 수축 추정(현재 −0.72 / −0.76). 겨울 잔차는 외기로도 남는다(1~2월 −3.9·−7.4%).

- **기온 모델**: 정상상태 1km 랩 1,244개(기기 온도 있음, 2025-04 이후)에 `속도(GAP) = a + b·HR + c·max(0, T − T0)`를 적합했다.

| T0 | c (1℃당 속도 변화) | R² |
|---|---|---|
| 10℃ | −0.45% | 0.41 |
| **15℃** | **−0.59%** | **0.43** |
| 20℃ | −0.97% | 0.45 |

  기온 없는 모델의 R²는 0.31이다. **채택은 T0=15℃, −0.59%/℃**다.
  - 문헌 대조 [가정: 원문 수치 확인 필요]: Ely 등(2007) 마라톤 기록 분석에서 WBGT가 약 5℃에서 25℃로 오르면 중상위권 러너 기록이 수 % 느려진다. 이 러너의 계수(10℃ 차에 약 6%)는 **기기 온도(손목, 외기보다 높게 나옴)** 기준이라 직접 비교할 수는 없다.
- **월별 잔차**: 보정 전 여름 −4~−8%, 가을 +4~+8%. 보정 후 여름 −0.4~−5.8%로 줄었지만 **1~3월에 −5~−7%가 새로 드러났다**. 겨울에는 손목 온도가 소매 안에서 외기보다 높게 읽히는 문제와, 12~2월 훈련 감소가 섞인 것으로 보인다. 외기 날씨가 없어 분리할 수 없다 [가정].
- **레이스 당일 편향(기온 보정 후)**: 직전 90일 모델에 레이스 평균 HR과 레이스 기온을 넣었을 때, 실제 속도가 모델보다 **평균 +5.5%, SD 5.7%**(n=8, 범위 −2.8~+16.7%) 빨랐다. 보정 전(+7.8%)보다 줄었지만 SD가 커서 **고정 보정계수로 쓰면 개별 예측 오차가 ±7% 수준**이 된다 → 단독 신호로는 부적합하다.
- **LTHR 앵커링**: 같은 곡선에서 LTHR 177의 속도를 "60분 레이스 속도"로 보고 Daniels VDOT를 계산한 H 신호는 레이스 9건에서 D-0 MAE 4.2%(편향 +1.5%), D-28 MAE 4.7%다. 앵커가 없을 때의 **폴백으로는 쓸 만한** 수준이다.

### 4-4. 5K와 신뢰도 (Q9)

- 5K = 결합 VDOT의 Daniels 환산(+개인 k). 90일 5K best effort는 **중앙값에 넣지 않고** 일치도 신호로만 쓴다(구간 기록·기온 미정규화라 하한 성격).
- 신뢰도 = 0.9 × f(앵커 최근성: 8주 1.0 → 52주 0.5) × f(신호 간 차이: 3% 1.0 → 10% 0.6) × f(신호 수: 1개 0.7, 2개 0.9, 3개 이상 1.0) × f(거리 외삽: 1배 1.0 → 4.2배 0.75) × f(마라톤 모델 차: 3% 1.0 → 12% 0.5). 상한 없음. 이유 문자열을 함께 저장.
- 범위: `중앙값 × (1 ± 1.2816·0.035·(1 + 0.5(1 − conf)))`, 느린 쪽 가산(주 15km 미만 마라톤 +3%p, 계획 이행률 <70% +1%p).

### 4-5. 마라톤

r2 §4-6과 같다(Daniels·Tanda 기하평균, 손계수 없음). 추가: 주 15km 미만이면 Tanda 적용 범위 밖으로 보고 Daniels만 + 신뢰도 ×0.8 + 느린 쪽 +3%p [가정]. EF·디커플링·HR 드리프트는 마라톤 검증 표본이 없어 범위·설명에만 쓴다.

### 4-6. 날씨 (Q10)

| 항목 | 규칙 |
|---|---|
| 1순위 | Open-Meteo archive(5일 이상 지난 날) / forecast(`past_days=7`). 좌표 소수 2자리, 시작 시각 + 경과/2 에서 시간별 선형 보간, 변수 기온·습도·이슬점·체감·풍속·일사 → WBGT ≈ 0.567T + 0.393e + 3.94 |

### 4-7. 계획↔실행 수용 구조 (Q11)

- 데이터: `planned_workouts` + `source_system(runpulse|garmin|intervals)`, `external_id`, `structure_json`(`steps`: warmup/work/rest/cooldown, `dur_s|dist_m`, `speed_lo/hi` 또는 `hr_lo/hi`, `repeat{count, steps}`). `session_outcomes` + `compliance_pct`, `segment_match_json`, `source_compliance`, `source_system`, 유일 제약 `planned_id`. 랩 `wkt_step_index`·`compliance_score` 보존.
- 인제스트: 앱 자체 계획은 즉시. Garmin 예정 워크아웃·Intervals 계획 이벤트는 원문을 `source_payloads(entity_type='planned_workout')`로 저장 후 파서(P7-PRED-44, 응답 형태 확인 필요 — 사람 단계). 활동의 `workoutId`/`paired_event_id`가 있으면 날짜 매칭보다 우선.
- `session_outcome`: 이행률 = 100 × (0.4·세트 달성 + 0.3·볼륨 일치 + 0.3·목표 적중(±3%)), 라벨 skipped/overperformed/on_target/underperformed/modified.
- 예측 사용 단계: 1단계(지금) 최근 4주 구조화 세션 ≥4개, 평균 <70%면 느린 쪽 범위 +1%p와 이유 문구만. 2단계(구조화 세션 ≥20개 이후) 롤링 백테스트로 가중 여부 결정.
