# REVIEW-05 — 비전 대비 UI 격차 리뷰 (2026-09-24)

**기준**: "세상에 없던 최고의 러닝 앱" — 개인 러닝 인텔리전스 플랫폼(00 §1: 데이터 소유감 · 투명한 분석 · 맥락 있는 안내).
**방법**: 실데이터 사본(pansongit, 읽기 전용 복사)을 띄워 모바일(390)·데스크톱(1280) 화면을 직접 보고, DB에 무엇이 있는지와 화면이 무엇을 보여주는지를 대조.
REVIEW-04는 "깨진 곳"을 고쳤다. 이 문서는 "고쳐도 여전히 부족한 이유"를 다룬다.

## 1. 결론

깨진 곳은 거의 다 고쳤지만 화면은 **정확한 데이터 목록**일 뿐 **제품 경험**이 아니다. 데이터·계산 계층은 세계 수준(3.9년·1,421회·132개 메트릭·4소스)인데 UI는 그중 5%만 보여주고, 러닝 앱의 기본기(지도·구간·존)도 Strava/Garmin 아래다. 차별점(투명성·통합·근거 있는 코칭)은 있지만 **눈에 보이는 순간(signature moment)이 하나도 없다**.

## 2. 자산 vs 화면 (실데이터 기준)

| DB에 있는 것 | 화면에서 |
|---|---|
| GPS 좌표 204,269점(107개 활동) | **지도 없음** |
| 대회 예측(5K~풀) 431일 이력, VDOT 316일, FEARP 318일 | 어디에도 없음 — 앱의 대표 인사이트가 노출 0 |
| 2023-10~2026-09 CTL/ATL/TSB 838일 | Today의 4주 라인 하나 |
| best efforts 788건, 마일스톤 | 마일스톤 텍스트 목록 |
| 웰니스 1,090일(수면·HRV·BB·SpO2) | 숫자 몇 개 |
| 목표 레이스(춘천마라톤 2026-10-25, D-31) | **앱이 모름** — `goals` 비어 있음, "목표 레이스 없음"·"활성 플랜 없음" 안내만 |
| 랩 102건, 스플릿, 존 | 랩 탭 표(요약에는 없음) |

## 3. 화면별 판정

- **Today**: 문장 하나("피로도가 높습니다")와 TSB/UTRS 칩, 3개 숫자 카드, 최근 활동 3줄. 대표 수치(예측 기록·목표까지 거리·회복 시점)와 시각적 앵커가 없다. 러너가 앱을 여는 이유("내가 지금 어디쯤인가")에 답하지 않는다.
- **활동 상세**: 상단 한 줄 요약 + 메트릭 카드 5개 + 선 두 줄. **지도·km 스플릿·심박존 분포·고도 프로필·"이 러닝이 내 체력에 준 영향"이 없다.** 카드가 전부 같은 크기라 위계가 없다.
- **활동 목록**: 행에 날짜·이름·배지뿐 — 거리·시간·페이스도 없다. 3.9년 아카이브가 "최근 5개"로 표현된다.
- **Library 홈**: 링크 모음 + Provider 동기화 현황(관리자 화면 성격). "내 데이터의 집" 감각이 없다.
- **Coach**: 대화 목록 + 주제 칩. 답변 품질과 별개로, 근거 칩·목표 맥락이 없다.
- **룩앤필**: 남색 배경에 동일한 둥근 카드의 반복. 히어로 수치 스케일·의미 색(상태 링/밴드)·아이콘 체계 없음(이모지). 데스크톱(1280)은 모바일을 그대로 늘린 것(카드 그리드만 4열). 선 차트는 가로로 늘어나며 굵기가 변형된다(`Sparkline`에 non-scaling-stroke 없음).

## 4. 방향 — 세 문장

1. **목표 중심**: 앱은 "다음 레이스"를 안다. 첫 화면은 D-일수·예측 기록 vs 목표·준비도 궤적·오늘 할 일.
2. **보이는 증거**: 모든 활동은 지도·구간·존·영향으로 "읽히는 이야기"이고, 모든 코칭 문장 옆에 눌러서 확인 가능한 근거가 있다.
3. **내 아카이브**: 3.9년치가 히트맵·PB 타임라인·누적 거리로 "내 것"임을 보여준다. 소스 동기화 상태는 Data로 내린다.

로컬 퍼스트 원칙상 **타일 지도(외부 요청) 대신 GPS 폴리라인을 SVG로 직접 그려**(페이스·심박 색상) 외부 의존 없이 지도 경험을 낸다.

## 5. 제안 에픽 (우선순위 순)

| # | 에픽 | 핵심 산출물 | 필요한 데이터 작업 |
|---|---|---|---|
| E1 | 목표 레이스 허브 | 레이스 등록(이름·날짜·목표), Today 히어로(D-N·예측 vs 목표·예측 추이 스파크·테이퍼/준비도), `goals` 연결 | 서비스 `goal_service`(등록·조회), 예측 이력 API |
| E2 | 활동을 이야기로 | 경로 SVG(페이스 색), 고도 프로필, km 스플릿 바, 심박존 분포, "이번 러닝의 영향(CTL Δ·회복 예상)" 히어로 블록, PB 배지 | 스트림→폴리라인 다운샘플 API, 스플릿·존 집계 |
| E3 | 피트니스-폼 시그니처 차트 | CTL/ATL/TSB(폼 밴드)+레이스 마커, 기간 전환, 스크럽 — Today·Library 공용 | (TrendChart 확장) |
| E4 | 내 아카이브 | 3.9년 캘린더 히트맵, 누적 거리, PB 타임라인, 활동 목록 행에 거리·시간·페이스·경로 썸네일, 주 단위 그룹+주간 km 바 | 활동 목록 API 필드 확장, 일별 집계 API |
| E5 | 비주얼 시스템 | 히어로 수치 스케일, 상태 링, SVG 아이콘 세트, 데스크톱 2열 레이아웃(≥1024), 차트 non-scaling-stroke | — |
| E6 | 근거 있는 Coach | 답변 근거 칩(EvidenceQuote), AI/규칙 구분, 목표 레이스 컨텍스트 주입, 입력창 도킹 | Coach 컨텍스트에 goal 추가 |

E1·E2가 체감 격차가 가장 크다(사용자는 지금 D-31 — 곧바로 쓸모가 있다). E5는 E1~E4와 병행해야 일관성이 생긴다.

## 6. 열린 결정
- 목표 레이스를 앱에서 등록하는 흐름(Plan 탭 "새 프로그램" vs Today 온보딩 카드) — 제안: Today 히어로의 빈 상태에서 바로 등록.
- 예측 기록 표기를 단일 값으로 할지 범위(±)로 할지 — 기존 ADR-007(range 표준)에 따라 범위 권장.
- 경로 시각화는 타일 없는 SVG로 확정할지(로컬 퍼스트 우선) — 제안: 예.
