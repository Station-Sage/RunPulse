## U-19 상세 — 노력 등급별 등가 지속시간 환산 (다음 세션 논의 항목, 2026-09-26 보류)

**배경**: 9/12 'Forest run' 10K(47:00, 18.6℃)는 사용자 확인상 "전력 아님, 템포보다 강한 템포런 느낌, A레이스 아님"이다. 현재 설계는 이런 대회를 `paced`로 분류해 전력 앵커에서 빼고 세트와 같은 분산(1.75²)의 **하한 증거**로만 쓴다(값은 "그 기록을 15℃로 환산한 대회 VDOT" 그대로, 즉 45:46 상당). 이 값은 실제 전력 능력보다 낮다(하한).

**제안(에이전트, 미시험)**: 하한 증거를 쓰지 말고 "노력 등급 → 등가 레이스 지속시간"으로 환산해 그 노력이 가리키는 VDOT를 직접 추정한다. 예: 노력이 Daniels T(≈60분 레이스 강도)에 해당하면, 47분 동안 T 강도로 뛴 것이므로 VDOT는 T 페이스 역산(세트 환산과 같은 함수)으로 얻는다. 이 방법으로 9/12는 10K 환산 45:05 근처가 된다(중간 노력 = 53분 레이스 강도면 45:25). 결과적으로 paced 대회가 세트 환산과 같은 체계에 들어가 하한 편향이 줄고, 현재 r4 base가 여름 세트에 끌려 느려지는 문제(10K 46:15 vs 참값 추정 44:30~45:30)를 줄일 수 있다.

**필요한 것**
1. 대회 확인 화면의 노력 값 집합 확장. 현재 `race_results.effort` = allout / submax / trail(및 paced). 후보: `allout`(전력), `hard`(레이스 강도에 가까움, ≈ 해당 거리의 90~95% 노력), `tempo_plus`(템포보다 강함, T~10K 강도 사이), `tempo`(T), `easy_race`(펀런). 각 등급의 등가 강도(%VO2max 또는 등가 지속시간)는 Daniels 강도 구간에 매핑한다. 값 집합 변경은 DB 제약·UI·API·기존 데이터 이행이 걸려 있어 **사용자 확인 필요**.
2. 사용자가 입력하지 않은 대회는 HR 기대범위 판정(REVIEW-09 §10)의 uncertain 상태로 두고 폴백은 지금과 같이 하한 증거.
3. 검증: 사용자가 알고 있는 과거 대회의 노력 등급을 몇 건 입력받아(예: 9/12=tempo_plus, 전력 대회들=allout) 세트와의 정합을 본다. 표본이 작아(paced 1건) 통계 검증은 불가하므로 **전향 평가(P7-PRED-63)와 함께** 판정한다.
4. 위험: 노력 등급의 주관성. 등급이 잘못 입력되면 예측이 오염되므로 등급 환산은 분산을 넓게(등급 불확실성) 두고, 전력(allout)이 아닌 대회로 앵커를 만들지 않는다.

**결정 대기 질문**: 노력 등급 선택지를 4~5단계로 늘릴 것인가, 아니면 allout / paced 이분법을 유지하고 paced는 하한 증거로 둘 것인가. (지금은 후자로 진행.)
