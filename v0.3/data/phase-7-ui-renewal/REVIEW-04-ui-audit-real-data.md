# REVIEW-04 — 구현된 화면 감사 (실데이터 기준)

**작성일**: 2026-09-24 · **범위**: Phase 7a~7b로 구현된 SvelteKit 화면 전부 · **선행**: `00`(비전), `01`(원칙 P1~P8), `REVIEW-vision-alignment`

문서(목업)가 아니라 **실제로 렌더된 화면**을 봤다. 합성 DB(`scripts/synth_smoke`)만으로는 값이 작고 이름이 짧아 안 드러나는
결함이 많아서, 사용자 허락을 받아 `pansongit@gmail.com` 계정 DB의 **복사본**(활동 1,421건·웰니스 1,090일·메트릭 36k행,
`scripts/synth_smoke/out/`, git 무시)으로 앱을 띄워 390×844 모바일 뷰포트로 화면 16개+를 캡처해 검토했다. 원본 DB는 건드리지 않았다.

## 총평

| 원칙 | 판정 | 근거 |
|---|---|---|
| P1 Evidence-First | △ | Today 권고·성장 내러티브·플랜 적응 상태는 근거 칩이 있다. **Coach 답변엔 근거가 없다**(앱의 핵심 AI 표면). 활동 핵심 메트릭은 값만 있고 해석이 없다 |
| P2 Drillable | ○ | 메트릭·칩·차트 탭이 계산 분해로 이어진다. 추세 차트는 축·스크럽이 없어 "데이터 포인트 클릭"(P2)이 안 된다 |
| P3 Provider Transparency | △ | 배지는 어디에나 있으나 **배지가 이름을 잘라먹는다**(`RunPulse · formula_v1`) — 투명성이 가독성을 해침. 소스 비교 표는 대표값 열이 화면 밖 |
| P4 Intent IA | ○ | Today/Library/Coach 3탭 + 의도 라벨. 다만 Today 첫 화면이 의도("오늘 뭐 하지")보다 입력 폼을 앞세움 |
| P5 Quiet Data | △ | 다크 토큰·모노 숫자는 좋다. 카드 안의 카드, 📊 장식 이모지, 네이티브 체크박스·날짜 입력이 "조용한 UI"를 깬다 |
| P6 One Finger Reach | △ | 입력 폼이 첫 화면 45%를 차지(과잉), 활동 상세 하단 compact 입력은 없음 |
| P7 State-Bound Plan | ○ | 플랜 상세 "적응 상태"(ACWR·HRV·피로도) 동작 |

**룩앤필**: 방향(다크·중립·모노 숫자·의미색)은 원칙에 맞다. 그러나 (1) 값이 원시 단위로 나오고(`22440 sec`, `↑26.0799… m`),
(2) 라벨이 잘리며, (3) 타이포 위계가 평평(섹션 제목이 12px 회색)하고, (4) 차트에 축·스케일이 없어 "잘 만든 앱"의 마감에 못 미친다.
**결론: 비전·정보구조는 맞게 구현됐고, 모자란 것은 데이터 표현의 정확성·마감이다** — 아래 S1을 먼저 고친다.

## 이번 세션 조치

오토파일럿 유닛 5개를 큐에 등록해 순서대로 실행·리뷰·병합한다: `VALUE-FORMAT` → `PROVIDER-BADGE-LAYOUT` →
`STREAMS-TRUTH` → `COACH-MARKDOWN` → `TODAY-HERO`. 설계 변경은 `TODAY-HERO` 하나 — `03a-today.md`·`03g-common-patterns.md`
(7-5 표)를 함께 고쳤고 근거는 `DECISIONS.md`에 있다. #1의 저장 데이터 정정은 `P7-DATA-STREAM-ELAPSED`(수동, 재처리 수반).
