## 1. 현재(구현 전) 상태
`frontend/src/lib/menuLinks.ts` + `MenuDrawer.svelte` — 40:S0 "과도기 드로어"(v1↔v2 상호 링크) 구조가 그대로 남아 있었다.

| 영역 | 항목 | 문제 |
|---|---|---|
| 동기화 요약 행 | 탭하면 `?sheet=sync` | 문제 없음 |
| 바로가기 | 오늘, 활동 목록, 웰니스, 훈련 계획, 레이스, AI 코치 | `오늘`·`AI 코치` 는 주 탭(Today/Coach) 루트와 같은 목적지 — 하단 탭(<lg)·좌측 사이드바(lg)가 항상 보이므로 중복 |
| 데이터·설정 | 데이터(동기화·소스), 데이터 내보내기, 설정, 지표 가이드 | 데이터 영역은 **주 탭이 없는 유일한 영역**인데 드로어 하단 그룹에 묻혀 있음. `가져오기`·`소스`·`러너 기준값`·`AI 설정` 은 드로어에서 닿지 않음(데이터 개요 → 서브탭 2단계). `지표 가이드`(Library) 가 데이터 그룹에 섞임 |
| 하단 | 개발용 사용자 전환(V1-8), 로그아웃 | 문제 없음 |

v1 링크는 이미 없다(S5-4). 따라서 "일몰 후 드로어가 맡을 일"은 v1 대체가 아니라 **탭이 맡지 않는 목적지의 입구**를 정하는 것이다.

## 2. 원칙
1. 드로어 = 탭이 없는 영역(데이터)·설정·계정의 입구. 주 탭 루트(`/today`·`/library`·`/coach`, `shell/navTabs.ts` 의 `match`)는 다시 두지 않는다.
2. 그룹 순서는 "드로어로만 닿는 것" 우선: 데이터 → 설정 → 바로가기.
3. 바로가기는 탭에서 두 번 이상 눌러야 닿는 자주 쓰는 화면만(6개 이하).
4. 링크 정의는 `menuLinks.ts` 의 `MENU_GROUPS` 한 곳 — 테스트가 경로 존재·중복·탭 중복을 고정한다.

## 4. 추천안(B) 구성 — 구현함
| 그룹 | 링크(경로) |
|---|---|
| (첫 행) 동기화 요약 | `?sheet=sync` (변경 없음) |
| 데이터 | 데이터 개요(`/data`), 소스 연결(`/data/sources`), 가져오기(`/data/import`), 데이터 내보내기(`/data/export`, `data-testid="menu-export-link"` 유지) |
| 설정 | 데이터 설정(`/data/settings`), 러너 기준값(`/data/settings/profile`), AI 설정(`/data/settings/ai`) |
| 바로가기 | 활동 목록, 훈련 계획(`/coach/plan`), 레이스(`/today/race`), 웰니스, 신발(`/library/shoes`), 지표 가이드(`/library/metrics`) |
| (하단) | 개발용 사용자 전환, 로그아웃 (변경 없음) |

제거: `오늘`·`AI 코치`(탭 중복), `데이터 (동기화·소스)`(→ `데이터 개요` + 첫 행 동기화 요약).
각 그룹은 `role="group"` + `aria-labelledby`(그룹 제목) — 스크린리더가 그룹 이름을 읽는다.
