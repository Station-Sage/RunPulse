## 2. 화면·플로우·상태 설계

### 2.0 생애주기 판정(단일 규칙)

```
요청 /
 ├─ 미인증 ───────────────────────── S0  /  (랜딩) · /demo
 └─ 인증됨
     ├─ 연결 0 & 활동 0 & onboarding≠skipped ─ S1  /welcome
     ├─ 연결 ≥1 & 첫 동기화 진행 중 ────────── S2a /today (empty-syncing)
     ├─ 활동 1..K (임계 미달) ────────────── S2b /today (소량, S2.5)
     ├─ 연결 0 & onboarding=skipped ───────── S2c /today (empty-first, QuickInput 활성)
     └─ 그 외 ────────────────────────────── S3  /today
```
- 판정 입력은 40 §6.1과 동일(SyncState `connected_count`·`first_sync_running`·`latest_data_date`)
  + 활동 수 + 온보딩 상태. **새 입력은 "활동 수"와 "온보딩 상태" 2개뿐**(필요 정보로만 명시).
- `lib/states.ts`의 4분류를 확장하지 않고, 생애주기 판정 `lifecycleOf()`를 같은 파일에 둔다.

### 2.1 S0 공개 랜딩 `/` — 비로그인 방문자

**시나리오**: 러닝 커뮤니티 글의 링크로 들어온 사람. "또 하나의 러닝 앱?"이라는 의심이 기본값.
**첫 3초**: "4개의 탭을 오가며 조립하던 것을 한 화면에서." — 기능 목록이 아니라 그 사람의 현재 고통.

```
┌──────────────────────────────────────────┐
│ RunPulse                     [로그인]      │
│ Garmin·Strava·Intervals·Runalyze를          │  L0 히어로 1문장 + 부제 1줄
│ 오가며 맞추던 숫자, 한 화면에서 근거까지.      │
│ [샘플 러너로 둘러보기]  [내 데이터로 시작 ›]   │  CTA 2개(데모가 1차)
├──────────────────────────────────────────┤
│ ① 하나로 합쳐요   같은 달리기 10.02 vs 10.05km │  L1 증명 카드 3장 — 각 카드가
│ ② 숫자를 열어봐요  CIRS 62 → 계산식·입력값     │  데모의 해당 화면으로 딥링크
│ ③ 상태에 맞춰요   "오늘은 쉬어가요" 근거 3개    │
├──────────────────────────────────────────┤
│ 내 데이터는 내 것: 격리 저장 · 언제든 내보내기  │  P8' 고지(01 원칙)
│ · AI에 보내는 범위 공개 (자세히 ›)            │
│ 트래커가 없어도 괜찮아요 — 오늘부터 기록해도…   │  초보 후크(§9-1)
└──────────────────────────────────────────┘
```
- **L2 없음**(랜딩에 깊이를 두지 않는다 — 깊이는 데모가 담당).
- 상태: 정적이라 로딩 없음. 이미 인증된 사용자가 오면 `/today`로 즉시 이동(랜딩 노출 0).
- 금지: 가짜 수치를 실제 사용자 성과처럼 쓰는 후기·통계, 사회적 증거 문구.

### 2.2 `/demo` — 정직한 데모

- S3 Today·Library 활동 상세·메트릭 드릴을 **같은 컴포넌트**로 렌더(§9-4 재사용 원칙).
- 상단 고정 띠: `샘플 러너 "민준"의 합성 데이터예요 · 실제 사람 아님 [내 데이터로 시작]`.
- 쓰기 동작(체크인·피드백·Coach 전송·계획 생성·동기화)은 실행하지 않고 시트로 전환:
  `이건 내 데이터에서 동작해요 · [시작하기] [계속 둘러보기]`. **Coach는 미리 준비된 대화 1개만 열람**
  (데모에서 LLM 호출 0 — 비용·남용 방지, §5 D-L2 참조).
- 탐색 범위: 하단 3탭 중 Today·Library만. Coach 탭은 열람 전용 스레드 1개. ☰ Data 영역은 숨김.
- 상태: 로딩=S3 스켈레톤 재사용 / 오류=`데모를 불러오지 못했어요 [다시 시도]` + 랜딩 복귀 링크.

### 2.3 S1 가입/연결 — 기존 `/welcome`(40 §2.10) 보완만

40 §2.10의 4단계를 그대로 쓴다. 이 문서가 더하는 것:

1. **진입 전 0단계(1화면, 신규 계정 최초 1회)**: `반가워요. 데이터는 이 계정 전용 공간에 따로 보관돼요.
   언제든 전체를 내보낼 수 있어요.` + [시작]. P8' 고지를 가입 직후 한 번 명시(AI 전송 동의는 D8대로
   첫 Coach 전송 시점 — 여기서 묻지 않는다, 동의 피로 방지).
2. **1/4 기기 연결의 Garmin 행**: v2 연결이 생기기 전까지 `Garmin 연결(이전 화면에서) ↗` + 복귀 안내
   `연결 후 이 탭으로 돌아오면 이어서 진행돼요`. 복귀 시 연결 상태 재조회(포커스 복귀 시 1회).
3. **OAuth 복귀 지점**: `return_to`를 `/welcome?step=2`로(현재 ConnectPanel은 소스 상세로 복귀).
4. **2/4 과거 데이터 범위**: 각 선택지 옆에 예상 시간 1줄(`/data/sync/estimate` 재사용) —
   "최근 90일 · 약 3분". 기본값은 §5 D-L5.
5. **떠남·복귀**: 2단계 진행 중 이탈해도 다음 진입은 Today S2a(진행 화면)로. `/welcome`으로 되돌리지 않는다.

| 상태 | 표시 | 행동 |
|---|---|---|
| 연결 시도 중 | 행 내 스피너, 다른 행 비활성 아님 | — |
| 연결 실패(키 오류) | 행 아래 원인 1문장(`message_ko`) | [다시 입력] |
| OAuth 취소·거부 | `Strava 연결을 취소했어요` (오류 색 아님) | [다시 연결] [다른 기기로] |
| 상태 조회 실패 | `연결 상태를 확인하지 못했어요` | [다시 확인], 3회 실패 시 [건너뛰고 둘러보기] |
| 건너뛰기 | 확인 없이 S2c로 | Today에서 언제든 재진입 |

### 2.4 `/` 분기와 G0 스위치의 공존

- 미인증 → S0. 인증됨 → `ui_default`(v1/v2)를 먼저 보고, v2면 위 §2.0 생애주기 판정.
- 즉 S0 분기는 **G0 앞단**, 생애주기 판정은 **G0 뒷단**. 신규 가입자는 `ui_default`가 비어 있으면
  v1이 아니라 **v2로 시작**(v1 경험이 없는 사람에게 v1을 줄 이유 없음) — §5 D-L6.

### 2.5 S2 콜드스타트 — Today 상태 변형

**S2a 첫 동기화 중 (empty-syncing)** — 빈 화면이 아니라 "채워지는 화면"
```
L0  지난 기록을 가져오는 중이에요
    Garmin ████████░░ 2026-03까지 · 활동 212 · 분석 184
L1  벌써 보이는 것 (도착한 데이터로 즉시 채움, 항목마다 도착하면 나타남)
    · 가장 긴 달리기 24.2km (2025-11-02)   · 최근 4주 주간 거리 32km
    · 가장 빠른 5km 구간 23:41              ← 각 줄 탭 → 해당 활동 상세
L1  곧 열려요 (미래 약속)
    · 체력 추세(CTL)  ▓▓▓▓░ 28/42일         ← 해금 조건과 현재량
    · 회복 상태(UTRS) 수면·HRV 3/7일
[완료되면 알려드릴게요]  [기다리는 동안 목표 대회 정하기 ›] → /coach/plan/new
```
- 완료 → 40 §2.10의 1회성 요약 카드 후 S3(또는 S2b).
- 실패 → 행 단위 상태 기계(40 §3.2) 그대로 + 본문 L0 `가져오다 멈췄어요 · Strava 다시 로그인 필요 [재연결]`.

**S2b 소량 (S2.5)** — 활동 1..K건
- 히어로 자리: 최근 활동 1건 요약(거리·페이스·평균 심박·HR존 막대) + 의미 1문장
  `첫 기록이 들어왔어요. 심박 2존 비중이 높아 편안한 강도였어요 (Z2 71%)`.
- 게이지 3종 자리: 숫자 대신 "곧 열려요" 줄(S2a와 같은 컴포넌트). **0이나 가짜 기본값 표시 금지.**
- QuickInput 활성(체크인은 데이터 양과 무관하게 가치가 있다).
- 첫 주 성취: 7일차에 `첫 주 요약 — 3회 · 14.2km` 카드 1회.

**S2c 연결 0, 온보딩 건너뜀 (empty-first)**
- L0 `기록 없이도 시작할 수 있어요` / L1 [기기 연결하기 → /welcome] · QuickInput(오늘 컨디션) ·
  [목표 대회 정하기]. 현재의 `/settings` 막다른 링크(A7)를 이것으로 대체.

**Library·Coach의 S2 변형**(02 §8.1 표를 구체화만)
- Library 목록: S2a에서 도착한 활동이 위에서부터 쌓이고 하단 `더 가져오는 중 · 128건 남음`.
- 메트릭 상세: 해금 전이면 `이 지표는 42일 데이터가 필요해요 · 지금 28일` + 계산식(투명성 유지).
- Coach: S2에서도 대화 가능. 첫 제안 칩을 `데이터 모이는 동안 할 일` 3개로 교체
  (목표 대회 정하기 · 최근 기록 해석 · 기준값 확인). 근거 부족 시 코치는
  `아직 2주치라 추세는 말하기 일러요 (CTL 미산출)`처럼 한계를 먼저 말한다.

### 2.6 메트릭 표시 규칙(이 영역 추가분)
- 해금 전 메트릭: 회색 점선 테두리 + 진행 비율. 색상 범위(초록/노랑/빨강)는 **해금 후에만**.
- 소량 구간의 단일 활동 값은 "이 활동 기준" 라벨을 붙여 추세값과 구분.
- 데모 수치: 모든 화면에 데모 띠가 보이는 동안 출처 배지는 `샘플`로 고정.

## 3. 경쟁 앱 대비
- Strava/Garmin 첫 화면은 "피드가 비었음" 또는 "기기를 연결하세요" 한 줄. RunPulse는 **가져오는 과정
  자체를 콘텐츠**로 쓰고, 지표가 언제 열리는지와 그 계산식을 첫날부터 공개한다(투명성 원칙).
- Runalyze·Intervals는 랜딩에서 기능 표를 보여주지만 체험이 없다. RunPulse는 **명시적 합성 데모**로
  근거 드릴다운을 가입 전에 만지게 한다.

## 4. 구현 단위 (순서 = REVIEW-03 §9-4의 S3→S2→S0 유지)

각 파일 300줄 이하. 프론트 순수 함수는 노드 단위 테스트, 화면은 Playwright 스모크(실 DB 사본 + 빈 DB).

## 5. 판단이 필요한 항목

표기: **[보안]** **[외부계정]** **[비용]** = 해당 영향 있음 → 사용자 직접 결정 필요.

**D-L1 S0·데모를 어디서 노출하나** [보안][외부계정]
- (a) 같은 도메인에서 CF Access Bypass 정책으로 `/`·`/demo`·정적 자산만 공개 — 앱 코드 변경 작음, 단
  CF 정책 오설정 시 보호 라우트가 열릴 위험. Flask `_identify_user`의 예외 경로 추가 필요.
- (b) 별도 공개 정적 사이트(다른 서브도메인)에 랜딩·데모 빌드 — 앱 인증 경계 무변경, 데모는 정적 JSON.
- (c) 보류 — 공개 가입 계획이 생길 때까지 S0 없음.
- **추천 (b)**, 단 시점은 (c). 이유: 공개 가입이 아직 없는데(D-L3) 랜딩만 열면 "시작하기"가 막다른 길.
  (b)는 인증 경계를 건드리지 않아 데모 데이터 유출 경로가 원천 차단된다.

**D-L2 데모 데이터 원천** [보안][비용]
- (a) `scripts/synth_smoke` 합성 DB를 고정 스냅샷으로 · (b) 실제 사용자 데이터 익명화 · (c) 손으로 만든 정적 JSON.
- **추천 (a)→정적 스냅샷 내보내기**. 실제 데이터는 위치(GPS 경로)·생체 정보 재식별 위험이 있어 (b) 배제.
  데모 Coach는 미리 생성한 대화 1개만 — 라이브 LLM 호출 비용·프롬프트 남용 방지.

**D-L3 가입 개방 정책** [외부계정][비용][보안]
- (a) 현행 유지: CF Access 허용 목록(초대제) · (b) CF Access를 "모든 GitHub/Google 계정"으로 개방 ·
  (c) 05 §11.2의 앱 자체 OAuth(Google/Apple).
- **추천 (a) 유지**, S0의 CTA는 `초대 요청`으로. 이유: (b)는 사용자 수에 따라 CF Zero Trust 좌석 한도·과금
  (무료 한도 수치는 확인 필요), 사용자당 LLM·동기화 서버 비용, Garmin 비공식 인증 경로의 계정 차단 위험을
  한꺼번에 연다. (c)는 system-architect 설계 범위.

**D-L4 Garmin 연결을 v2로 가져올지** [외부계정][보안]
- (a) `/welcome`에서 v1 `/connect/garmin`으로 왕복(현행) · (b) v2 연결 화면 신설.
- **추천 (a) 우선, (b)는 별도 항목**. 이유: Garmin은 공식 OAuth가 아니라 자격증명·토큰 경로라 화면 이동만으로
  끝나지 않는다(자격증명 취급·MFA·차단 대응). 온보딩 완성도를 Garmin 이관에 묶지 않는다.

**D-L5 첫 백필 기본 범위** [비용][외부계정]
- (a) 90일(40 §2.10 권장) · (b) 1년 · (c) 전체.
- **추천 (a)**. 이유: 외부 API 속도 제한·계정 차단 위험과 서버 부하가 범위에 비례. 90일이면 CTL(42일) 해금이
  첫 동기화 직후 가능해 S2a→S3 전환이 빠르다. 나머지는 이후 백그라운드 확장을 선택지로.

**D-L6 신규 가입자 `ui_default` 기본값**
- (a) v1(현 FALLBACK) · (b) 신규는 v2, 기존 사용자는 현행 유지.
- **추천 (b)**. 신규에게 v1→v2 전환 비용을 지울 이유가 없고, 온보딩·빈 상태는 v2에만 설계된다.

**D-L7 S2.5 "소량" 임계값**
- (a) 활동 수 기준(예: <10건) · (b) 메트릭 해금 기준(핵심 3게이지 중 하나라도 미해금이면 소량) · (c) 기간(<28일).
- **추천 (b)**. 이유: 사용자가 체감하는 "부족"은 건수가 아니라 "Today의 판단이 비어 있음"이다. 메트릭별
  최소 데이터 조건을 화면이 받을 수 있어야 하므로 system-architect 확인 필요(A11과 같은 정보).

**D-L8 착수 시점**
- **추천**: L1·L7은 40 S5(G2)에 합류해 지금 진행 가능. L2·L3은 G2 범위로 이어서. L5·L6은 D-L1·D-L3
  결정 후. BACKLOG의 **(판단 필요)** 태그는 L5·L6에만 남기고 나머지는 해제하는 것을 제안.

## 6. system-architect에 넘길 확인 사항(설계 의견 아님)
1. 신규 계정의 사용자 DB 최초 생성 시점과, "DB 없음"을 서버 장애(503)와 구분해 화면이 알 수 있는지(A9).
2. 메트릭별 최소 데이터 조건(해금 조건)과 현재 보유량을 화면이 받을 수 있는지(A11, D-L7).
3. 온보딩 진행 상태와 활동 수를 생애주기 판정 입력으로 받을 수 있는지(§2.0, 기존 사용자 설정 저장소 재사용 가능성 포함).
4. D-L1 (a) 선택 시 공개 경로 예외 목록의 관리 방식(현재 `/feeds/cal/`·`/mcp` 하드코딩).
